# 三学科诊断准确性评测体系设计

> 日期：2026-08-02
>
> 状态：APPROVED BY PRODUCT OWNER
>
> 范围：数学、语文、英语诊断准确性；本地可重复评测流水线；少量云端合同烟测

## 1. 背景

当前版本已经完成云函数部署、真机主流程验收、全套微信开发者工具 E2E、文档与用户导览刷新。产品功能和工程门禁已较完整，下一阶段的主要未知不再是“流程能否运行”，而是诊断结论是否准确、证据是否可靠，以及三学科的行动归因是否正确。

现有自动化测试主要验证结构合同、页面行为和已知业务规则，不能回答以下问题：

- 图片中的题目、学生答案和批改痕迹是否被正确识别；
- 正确、错误、空白和无法辨认是否被正确区分；
- 数学知识节点与细卡点、语文原错项与迁移类型、英语认词与拼写维度是否归因正确；
- 模型或提示词调整后，准确性是改善还是回退。

因此，本阶段建立一套可重复、可人工审计、不会写入线上业务数据的三学科诊断质量评测体系。

## 2. 已确认决策

1. 三科全面评估，不只评数学。
2. 数据由真实历史样本和专门构造的边界样本共同组成。
3. 每科至少 20 份试卷或作业、150 个可独立判断的评测项；三科合计不少于 450 项。
4. AI 负责预标，人工逐项确认后才能形成金标准。
5. 云端数据按需只读导出，脱敏后在本地评测；评测流程不得修改线上业务数据。
6. 采用本地可重复评测流水线，并保留每科 5 份固定样本的生产链路合同烟测。
7. 本阶段唯一核心交付物是首个可信的三学科诊断准确性基线报告。

## 3. 目标与非目标

### 3.1 目标

- 建立统一、版本化的评测样本和金标准结构。
- 建立数学、语文、英语各自独立且可解释的评分器。
- 记录每次运行的代码、模型、提示词和配置版本，使结果可以比较和追溯。
- 提供本地人工复核界面，降低 450 项以上标注的操作成本。
- 生成总体、分学科、分切片和分错误等级的基线报告。
- 在基线稳定后，把核心准确性门槛接入发布检查。

### 3.2 非目标

- 不扩展学习资源。
- 不接入微信订阅消息。
- 不新增面向家长的产品页面。
- 不自动修改线上报告、卡点或掌握状态。
- 不把 AI 预标直接视为金标准。
- 不在首个基线建立前大规模修改模型、提示词或归因逻辑。
- 不把真实学生图片、标注或原始模型输出提交到 Git。

## 4. 评测集设计

### 4.1 数据来源

评测集包含两个固定分层：

| 分层 | 每科最低数量 | 目的 |
| --- | ---: | --- |
| `historical` | 100 项 | 反映真实使用分布、常见题型和真实拍摄条件 |
| `challenge` | 40 项 | 覆盖模糊照片、裁切、批改痕迹、空白题、多答案、跨页题等边界情况 |

每科至少包含 20 份不同作业或试卷以及 150 个评测项；达到两类最低数量后的剩余项可以来自任一分层。每个数据集版本都必须继续满足该最低覆盖，不能用比例漂移改变版本可比性。同一学生、同一题型或同一模板不得大量重复，以免简单重复样本虚高总体准确率。

### 4.2 评测单位

一个评测项是能够独立判断识别结果和诊断结论的最小单位：

- 数学通常是一道完整题目；复合题可按能够独立判分的小问拆分。
- 语文可以是一道题，也可以是一个需要独立复测的错字、错词或句子。
- 英语可以是一道题，或一个需要分别判断认词与拼写状态的词项。

每项使用稳定 `sampleId`，并对原始脱敏图片、裁剪区域和关键元数据计算内容哈希。内容发生变化时必须生成新版本，不能静默复用旧标注。

题目发现指标以完整文档清单为依据。每份正式基线作业或试卷必须包含 `documentId`，每页包含 `pageId`，并由人工确认该页全部可判定评测项的 `sampleId`、区域、多小问关系和跨页关系。页面清单锁定后才能进入正式基线。只有裁剪图而没有完整页面清单的历史材料可以进入单独的探索性报告，但不计入任何正式基线指标，也不能计入每科 150 项最低数量。

### 4.3 样本公共字段

每个样本至少包含：

- `sampleId`、`datasetVersion`、`subject`、`grade`；
- `documentId`、`pageId`、该页完整评测项清单以及复合题父子关系；
- `sourceType`：`historical` 或 `challenge`；
- 脱敏图片引用、页码、题目区域；
- 图片质量与题型标签；
- 当前系统的原始诊断输出引用；
- AI 预标结果引用；
- 人工确认的金标准引用；
- 标注状态、确认人代号、确认时间、修改历史和争议说明；
- 图片与元数据内容哈希。

真实数据位于环境变量 `DIAG_EVAL_DATA_ROOT` 指向的本机受控目录。该目录必须是绝对路径，且不得位于本仓库、Google Drive、iCloud 或其他自动同步目录内。仓库只保存 JSON Schema、完全虚构示例、评分代码和不含个人信息的汇总报告。

## 5. 三学科金标准

### 5.1 数学

每项至少确认：

- 标准化题目文本；
- 学生答案和正确答案；
- `correct / incorrect / blank / unreadable` 四分类结论；
- 错误类型；
- 标准数学知识节点；
- 细卡点；
- 必要时的证据区域与争议说明。

### 5.2 语文

每项至少确认：

- 标准化原题文本；
- 原错字、错词或错句；
- 正确形式；
- 四分类结论；
- 错误类型；
- 原项复测目标；
- 允许的迁移类型以及原项与迁移项的绑定关系。

### 5.3 英语

每项至少确认：

- 标准化单词或短语；
- 学生答案和正确答案；
- 四分类结论；
- 认词维度结果；
- 拼写维度结果；
- 期望的错词状态更新。

## 6. 标注与防偏差流程

1. AI 预标只读取原始图片、裁剪区域和必要题目背景，不读取被测系统的诊断输出。
2. 人工复核页面默认隐藏被测系统输出，只展示图片和 AI 预标。
3. 人工可以接受、修改或标记争议；所有修改保留审计记录。
4. 金标准只有在人工点击确认后才进入正式评分分母。
5. 金标准锁定后，页面才显示系统结果与金标准差异。
6. 题目拆分不一致、跨页关联、多重批改痕迹或无法自动匹配的样本进入待仲裁队列，不得静默跳过。
7. 已锁定金标准如需修改，必须提升数据集版本并记录原因。
8. 学科确认人必须通过一组已裁定校准样本：四分类一致率不低于 95%，学科归因一致率不低于 90%；未通过时不能锁定正式标注。
9. 每科至少 10% 的样本按学科、年级、来源和图片质量分层抽取，由第二位确认人从原图独立标注，不读取 AI 预标、第一位标注或被测系统输出。
10. 所有 S0/S1 候选、两位确认人结论不一致以及双方标记争议的样本均由第三角色仲裁；角色可以由同一项目团队成员在不同批次承担，但同一样本的仲裁人不能是其第一确认人。
11. 四分类双标一致率低于 95%或学科归因一致率低于 90%时，暂停锁定该学科数据集，先更新标注指南并重新抽样复核。

确认人不以职称作为唯一准入条件，但必须能依据标准答案、现行学科目录和标注指南解释决定。报告记录匿名角色代号，不记录真实姓名。

## 7. 指标体系

### 7.1 通用指标

| 层级 | 指标 |
| --- | --- |
| 题目发现 | 金标准题目召回率、漏题率、虚构题目率 |
| 内容识别 | 题干、学生答案、正确答案、批改痕迹的标准化匹配率 |
| 结论判断 | `correct / incorrect / blank / unreadable` 四分类准确率与混淆矩阵 |
| 置信处理 | 不清晰样本的正确拒答率、错误高置信结论率 |
| 行动归因 | 知识节点、细卡点、错误类型、原错项或错词维度准确率 |
| 输出完整性 | 必填字段、证据引用和样本关联完整率 |

### 7.2 学科专项指标

- 数学：知识节点 Top-1、细卡点 Top-1、错误原因准确率。
- 语文：原错项定位、错误类型、原项复测绑定、迁移类型合法率。
- 英语：词项识别、认词/拼写双维判断、错词状态更新准确率。

### 7.3 评分语义

- 文本比较先执行版本化的学科规范化规则，包括 Unicode、全半角、空白和标点处理；数学数值、分数和等价表达只能按金标准中显式登记的等价答案比较，不能由评分模型临时猜测语义等价。
- 每个评测项必须有一个主结论和一个主归因。允许多标签时，额外报告标签集合的 precision、recall 和 F1；层级归因分别报告叶节点精确命中与祖先节点命中，不能用祖先命中冒充 Top-1 叶节点正确。
- `unreadable` 是正式金标准类别。系统明确拒答且金标准为 `unreadable` 才算正确拒答；系统对可读样本拒答记为漏判，对不可读样本强行给出对错结论记为 S1。
- 复合题按金标准登记的小问分别计分，父题只用于分组，不能与小问重复进入分母。
- 自动匹配采用一对一规则：优先使用稳定 `sampleId`；没有回传 ID 时，同页唯一候选的区域 IoU 必须不低于 0.5；区域不足时，规范化文本相似度必须不低于 0.90，且与次优候选至少相差 0.05。多对一、一对多、缺少必要定位信息或未达到阈值的结果必须进入人工仲裁。阈值属于评分合同，修改时必须提升评分器版本。
- 未匹配的金标准项计为漏题；未匹配的系统输出计为虚构题目。若虚构输出进一步声称学生答错、生成不存在的错误或给出行动归因，则同时记为 S1；无诊断结论的重复检测只进入虚构题目指标。运行失败页上的全部金标准项进入题目发现分母并计为漏题，同时单独计入运行失败率。
- 字段和归因准确率只以成功一对一匹配的项为分母，并必须与题目召回率、运行完成率并列展示。不得只报告条件准确率。
- 错误等级按 S0、S1、S2、S3 的最高严重度归档，同一项可以保留多个错误标签，但严重错误率按评测项去重。S1 严重错误率定义为“发生 S1 的金标准项数 + 产生 S1 结论的虚构输出数”除以正式金标准项总数；虚构输出不会增加分母。

### 7.4 错误等级

| 等级 | 定义 |
| --- | --- |
| S0 | 数据串档、隐私泄漏、样本对应错误 |
| S1 | 把错题判对、把对题判错、把空白或不可辨认内容强行下结论、凭空生成错误 |
| S2 | 题目判断基本正确，但知识节点、细卡点、错误类型或行动目标归因错误 |
| S3 | 文本标准化、格式或其他低影响字段错误 |

### 7.5 目标质量门槛

首轮只建立基线，不因低于目标而阻塞评测交付。完成针对性修复并建立稳定基线后，启用以下门槛：

- S0 必须为 0。
- 清晰图片题目召回率不低于 98%。
- 四分类结论准确率不低于 95%。
- S1 严重错误率不高于 2%。
- 数学知识节点 Top-1 不低于 90%，细卡点 Top-1 不低于 85%。
- 语文原错项定位不低于 95%，错误类型不低于 90%。
- 英语词项识别不低于 98%，认词/拼写双维判断不低于 95%。
- 不可辨认样本的正确拒答率不低于 90%。
- 评测运行完成率不低于 99%，且所有未完成项均保留在失败清单和题目发现分母中。

总体达标不能掩盖主要切片回退。报告必须按学科、年级、题型、图片质量和数据来源切片；样本数不足的切片只显示观察值和置信区间，不单独宣告达标。

## 8. 评测流水线

```text
只读导出并脱敏
  → 导入本地数据集
  → Schema、哈希、重复与隐私校验
  → 当前诊断流程以评测模式运行
  → 保存不可变运行输出
  → AI 预标
  → 人工确认并锁定金标准
  → 自动匹配与三科评分
  → 新旧版本比较
  → 生成基线报告
```

### 8.1 运行元数据

每次运行生成不可变 `runId`，至少记录：

- Git commit；
- 数据集版本；
- 模型与供应方；
- 提示词或合同版本；
- 关键运行配置；
- 开始与结束时间；
- 成功、失败、隔离和重试样本数量；
- 调用用量与估算成本（如可获得）。

不同运行的输出不得相互覆盖。

### 8.2 评分与版本比较

评分器先以锁定的文档/页面完整清单完成一对一题目匹配，再计算字段和归因指标。无法可靠自动匹配的项进入待仲裁队列。报告至少包含：

- 当前版本和上一基线的总体差异；
- 三科独立结果；
- 主要切片结果；
- S0–S3 错误数量和代表性脱敏案例编号；
- 改善项、回退项和持续错误；
- 比例指标的置信区间；
- 失败、隔离和未完成复核样本清单。

首个基线稳定必须同时满足：数据集全部锁定、质控抽样通过、评分器对同一固定输出连续两次产生完全相同结果、运行完成率不低于 99%，以及三科合同烟测通过。

后续版本出现任一情况即判定回退：新增 S0；相对基线新增 2 个或以上 S1 项；任一受门禁核心指标绝对下降超过 2 个百分点；或配对结果的 McNemar 检验在 `p < 0.05` 时显示显著变差。McNemar 检验只用于固定金标准项的“诊断整体正确”二元结果：该项被发现、四分类正确，且需要行动归因时主归因也正确；其他指标使用绝对百分点和严重错误规则。只新增 1 个 S1 时必须人工审查，未获得明确豁免不得提升基线。核心指标达到目标门槛且未触发回退规则后，运行结果才可以被提升为新的正式基线。

### 8.3 生产链路烟测

每科固定选择 5 份脱敏样本，通过生产等价链路验证输入输出合同。烟测只验证链路与本地评测适配层的一致性，不进入正式准确率分母。烟测必须使用隔离身份或明确的评测模式，并禁止写入真实学生档案。

## 9. 工程结构与命令

建议结构：

```text
evaluation/diagnostic-accuracy/
├── schemas/
├── fixtures/
├── scorers/
├── adapters/
├── review-app/
└── reports/

$DIAG_EVAL_DATA_ROOT/
├── datasets/
├── annotations/
├── runs/
├── exports-redacted/
└── staging-unredacted/
```

建议命令：

```bash
npm run eval:diagnosis:import
npm run eval:diagnosis:prelabel
npm run eval:diagnosis:review
npm run eval:diagnosis:run
npm run eval:diagnosis:compare
npm run eval:diagnosis:smoke
```

各命令必须支持明确的数据集版本和运行编号参数；涉及真实数据的命令不得默认扫描工作区或上传任何文件。

## 10. 错误处理与安全要求

- 图片缺失、Schema 不合法、哈希变化、模型超时、输出结构错误或人工未确认时，运行必须显式标记不完整。
- 失败样本可以重试，但不得从分母或失败清单中静默消失。
- 未脱敏导出只能进入 `$DIAG_EVAL_DATA_ROOT/staging-unredacted/`。导入流程同时检查文件名、结构化字段和图片内容：先用本机离线 OCR/模式规则标记姓名、学号、学校、班级、联系方式等区域，再由人工逐页确认遮罩；可能出现人脸时还需人工确认人脸遮罩。未脱敏图片不得发送给外部模型、预标服务或日志系统。
- 脱敏生成新图片，不能覆盖原图；人工确认脱敏结果后才能进入正式数据集。无法确认已完整脱敏的样本不得参与评测。
- `DIAG_EVAL_DATA_ROOT` 启动时必须通过路径守卫，拒绝仓库内部和已知同步目录。仓库仍加入 `.local/evaluation/` 等常见误放路径的忽略与防泄漏规则，以阻止误复制的数据被暂存。
- 评测数据只允许项目负责人和明确授权的标注人访问；本机必须启用磁盘加密。可移动备份必须单独加密，禁止未加密备份和自动云同步。
- 未脱敏暂存数据在脱敏确认后 7 天内删除。脱敏评测数据在被更新基线取代 180 天后删除，除非项目负责人书面延长；删除动作写入不含个人信息的审计日志。
- 导出的结构化元数据使用随机评测代号替换学生、家长、学校和数据库文档身份；映射表与评测数据分开加密保存，并在抽样核对结束后删除。
- 只读导出与评测运行使用不同能力边界；任何线上写入请求均应被评测适配层拒绝。
- 模型调用必须设置并发上限、重试上限和可选成本上限，避免一次评测失控。

## 11. 测试策略

- Schema、内容哈希、去重、版本和隐私扫描单元测试。
- 文档/页面完整清单、复合题关系以及一对一匹配规则测试。
- 三科评分器的完全虚构金样本测试。
- 文本规范化、等价答案、多标签/层级归因、拒答、失败运行与未匹配项分母测试。
- 四分类混淆矩阵、Top-1、严重错误率、置信区间与配对回退计算测试。
- AI 预标无法读取被测系统输出的隔离测试。
- 未标注、无法匹配、失败或隔离样本不得静默退出统计的测试。
- 同一运行元数据与不可变输出约束测试。
- 新旧版本比较、回退检测和基线提升规则测试。
- 小型虚构数据集的本地端到端测试。
- Git 防泄漏测试。
- 每科固定 5 份样本的生产链路合同烟测。

真实数据评测不进入普通 CI；Schema、评分器、虚构端到端和防泄漏测试进入默认验证命令。

## 12. 分阶段交付

### 阶段 1：评测骨架

使用完全虚构的小型三科样本完成 Schema、导入校验、运行记录、评分器、人工复核页面和报告生成。

### 阶段 2：首个真实基线

导入并人工确认每科至少 150 项的历史与边界样本，产出首个三学科基线报告。此阶段只陈述现状，不以目标门槛否决基线交付。

### 阶段 3：准确性修复

按 S0、S1、S2、S3 顺序聚类问题，优先修复影响对错结论和行动建议的系统性错误。每项修复都运行完整数据集并与首个基线比较。

### 阶段 4：质量门禁

在指标稳定后启用正式门槛，把虚构回归测试纳入默认验证，把受控真实数据评测纳入发布清单。

## 13. 验收标准

首阶段整体设计完成的最终验收条件是：

1. 三科均达到至少 20 份试卷或作业、150 个已人工确认评测项。
2. 每科历史集不少于 100 项、边界集不少于 40 项，来源数量和主要切片可追溯。
3. 计入正式 450 项基线的每份材料都有锁定的文档/页面完整清单，题目发现指标可以重复计算；裁剪图探索集与正式指标完全隔离。
4. AI 预标与被测系统输出隔离，人工修改有审计记录；每科至少 10% 独立双标且一致率达到要求。
5. 评测运行不写入线上业务数据，真实数据不在仓库或同步目录内，不会被 Git 跟踪，并按脱敏、访问和保留规则管理。
6. 三科评分器、规范化、匹配、错误分级、版本比较和不完整运行处理通过自动化测试。
7. 生成首个包含总体、分科、分切片、严重错误和置信区间的基线报告。
8. 每科 5 份生产链路烟测通过，且不计入准确率分母。
9. 学习资源、订阅消息和家长端新功能没有被带入本阶段范围。

## 14. 后续决策方式

基线报告完成后，不预设模型、提示词或规则中哪一层最需要改。先按错误聚类和严重等级判断根因，再分别决定是否调整图片预处理、OCR/多模态提示词、输出合同、学科归因规则或置信度降级策略。任何优化都必须用同一数据集进行新旧对比，避免凭少量案例主观判断改善。
