# 学习档案首页与全局体验改版设计

日期：2026-06-12

## 背景

当前小程序首页仍是“学习诊断 / 选择学生开始诊断”的旧入口模式。这个模式适合多学生管理，但不适合当前“仅服务钟青羽的单人 MVP”。它存在两个问题：

1. 信息密度低：首页只展示学生姓名、年级、诊断次数和更新时间。
2. 点击链路长：家长需要先进入学生，再进入学科，才能看到真正有价值的诊断摘要、学习卡点和学习记录。

新的产品方向已经从“选择学科开始诊断”转向“围绕一个孩子沉淀学习档案”。因此首页应成为学习档案入口，而不是学生列表入口。

## 设计目标

1. 首页直接呈现钟青羽的学习档案摘要，减少进入核心信息的点击次数。
2. 用报告式语言表达当前综合学习情况，避免只展示冷冰冰的数据。
3. 明确样本覆盖范围，让家长知道当前结论主要基于哪些学科和材料。
4. 将学习观察和学习记录分工清楚：观察回答“当前发现什么”，记录回答“这些结论来自哪里”。
5. 保留高频操作，但不让操作按钮喧宾夺主。
6. 统一视觉语言：柔和、友好、有证据感，避免过重的“诊断压力”。

## 页面命名

首页名称从“学习诊断”调整为“学习档案”。

原因：

- “学习诊断”强调一次性动作。
- “学习档案”强调持续记录和阶段性总结，更符合 MVP 的证据链产品形态。

## 首页信息架构

首页顺序固定为：

1. 插图 + 综合诊断摘要
2. 样本覆盖提示
3. 轻量指标
4. 学习观察
5. 学习记录
6. 下一步建议
7. 学科入口

### 1. 插图 + 综合诊断摘要

使用现有两个小女孩学习插图作为首屏视觉。插图应放在综合摘要卡片顶部，增加亲和力。

摘要采用报告式表达：

> 基于近期上传的数学试卷，目前已整理出 2 条待验证学习观察，主要集中在计算基础和审题理解。当前结论主要来自数学样本，语文和英语还需要后续补充试卷或作业记录。

摘要规则：

- 先说明数据来源。
- 再说明当前结论。
- 最后说明样本缺口和下一步建议。

### 2. 样本覆盖提示

首页必须展示样本覆盖范围，例如：

> 样本覆盖：已分析数学试卷；语文、英语暂无有效诊断记录。

这条提示用于避免家长误以为系统已经对孩子的全部学习情况做出完整判断。

### 3. 轻量指标

早期不展示“已改善 0”这种容易产生负面感或空洞感的指标。

建议指标：

- 学习观察：2
- 有效报告：1
- 最近更新：今天

当后续存在有效验证反馈时，再引入“已改善”指标。

### 4. 学习观察

将“待验证卡点、分学科摘要、重点卡点、诊断报告入口”整合为一个清单。

示例：

```text
数学 · 2 条待验证观察
计算基础、审题理解 · 来源：最近诊断报告
状态：待验证
```

点击后进入数学学科详情页。

首页不展开具体错题和完整证据，只展示聚合摘要。

### 5. 学习记录

学习记录必须放在首页，因为它是产品可信度的证据链。

首页只展示最近 2 到 3 条：

- 上传试卷照片
- 诊断报告
- 验证反馈

完整记录通过“查看全部”进入学习记录时间线。

学习记录不是简单的上传历史，它应覆盖：

- 上传图片
- 诊断报告
- 生成的验证试卷
- 验证试卷批改后反馈

### 6. 下一步建议

下一步建议基于当前观察生成。

示例：

```text
优先完成数学验证试卷
用于确认计算基础和审题理解是否稳定出现。
```

主操作：

- 生成验证试卷

次操作：

- 上传新试卷

### 7. 学科入口

学科入口保留，但放到首页后部。

建议状态：

- 数学：已有观察
- 语文：待采样
- 英语：待采样

学科入口的职责是进入学科详情页，不再作为主页核心。

## 其他页面职责调整

### index 首页

从“学生列表”改为“学习档案首页”。

单人 MVP 下，默认展示钟青羽的学习档案。如果未来支持多学生，可将“管理孩子 / 切换孩子”作为右上角次级入口。

### subject-select

从主流程页面降级为学科入口页，后续可以被首页中的学科入口替代。

短期可以保留页面和路由，避免大范围改动。

### subject-home

重新定义为“单学科详情页”。

它负责展示某一学科的完整信息：

- 单学科综合摘要
- 当前学习观察
- 最近变化
- 该学科学习记录
- 生成验证试卷
- 上传该学科新试卷

### upload-history

从“上传历史”升级为“学习记录”。

它应支持全学科时间线，也要支持从学科详情页进入时按学科过滤。

时间线事件类型包括：

- 上传图片
- 诊断报告
- 生成验证试卷
- 上传完成后的验证反馈

### report

报告页需要统一为报告式阅读体验。

结构建议：

1. 本次结论摘要
2. 样本来源
3. 学习观察和证据
4. 错题详情
5. 下一步建议

### 验证卷流程

`generate-verification`、`paper-preview` 和验证卷上传应被视为一个连续流程。

理想路径：

```text
选择学习观察
→ 生成验证试卷
→ 预览 / 下载 PDF
→ 线下完成
→ 上传批改结果
→ 生成验证反馈
```

## 数据要求

首页需要聚合以下数据：

- `students`：学生姓名、年级
- `subjectProfiles`：各学科总报告数、当前摘要、当前学习观察、更新时间
- `reports`：最近诊断报告和验证报告
- `papers`：最近生成的验证试卷

第一版可以使用规则生成综合摘要，不需要调用 AI 生成跨学科总结。

综合摘要规则示例：

- 有数学观察，语文英语无记录：
  - “数学学习线索已形成，其他学科仍待补充样本。”
- 三科均无记录：
  - “当前还没有形成有效学习观察，建议先上传一份数学或语文试卷。”
- 有验证改善：
  - “近期验证显示部分学习观察已有改善，建议继续跟踪巩固。”

## 视觉语言

1. 主色保持蓝色体系，但降低大面积深蓝占比。
2. 使用浅蓝、浅黄、浅绿作为辅助色，表达“观察、记录、改善”。
3. 卡片圆角控制在 14 到 18 rpx，避免过度圆润。
4. 首页插图使用两个小女孩学习图，形成温和首屏。
5. 避免大块空白和低密度列表。
6. 按钮不宜过多，首页主操作最多两个。

## 成功标准

1. 用户打开小程序首页后，不需要点击即可看到钟青羽当前学习摘要。
2. 用户能在首页理解当前结论来自哪些样本。
3. 用户能看到最近上传图片和诊断报告的证据链。
4. 用户能从首页直接进入下一步验证或上传。
5. 用户仍然可以进入数学、语文、英语详情页。

## 第一阶段改版范围

第一阶段只改信息架构最关键的页面：

1. `index`：改为学习档案首页。
2. `subject-select`：保留路由，但弱化为学科入口或后续备用页。
3. `upload-history`：首页露出最近记录，完整页仍沿用现有时间线。

暂不一次性重做全部页面，避免范围过大。

## 暂缓事项

以下内容不进入第一阶段：

- 多学生切换的完整体验
- AI 自动生成跨学科长摘要
- 全新的底部导航
- 复杂的学习成长趋势图
- 语文和英语在线验证流程
