# 实用 Emoji 兼容性测试页设计

## 目标

把家庭学习工作台首页现有的临时图标面板迁移到独立测试页，建立一套适合教育产品的实用 Emoji 候选库。用户可在 Android 微信真机逐类检查，并通过稳定的分类编号或图标编号精确反馈兼容性结果。

测试结果只代表对应的手机型号、Android 版本、微信版本和小程序基础库版本，不直接推断为所有 Android 设备通用结论。

## 页面入口

- 删除首页当前默认展开的 7 项图标测试面板。
- 在家庭学习工作台标题区下方增加一条紧凑入口，标题为“图标兼容性测试”，展示候选图标总数和进入箭头。
- 入口不使用待测试 Emoji，避免入口本身因兼容性问题失效。
- 新页面路由为 `pages/icon-compatibility/icon-compatibility`。

## 测试页结构

1. 顶部显示测试环境摘要，包括手机型号、系统版本、微信版本和基础库版本。优先使用 `wx.getDeviceInfo()`、`wx.getAppBaseInfo()`；旧基础库回退到 `wx.getSystemInfoSync()` 的 `model`、`system`、`version`、`SDKVersion` 字段，单项缺失显示“未知”。
2. 使用横向滚动的分类标签。切换后标签栏自动滚动到当前分类；页面状态和 WXML 中只保留当前分类项目，避免同时创建约 200 个图标节点。
3. 分类标题显示分类编号、名称、当前分类数量和测试风险说明。
4. 图标采用四列紧凑网格，每项显示 Emoji、稳定编号和中文语义。
5. 页面底部提供“上一类”和“下一类”操作，便于按顺序完成真机检查；到达边界时保留按钮尺寸并显示禁用状态，避免布局跳动。
6. 点击图标卡复制其编号；点击分类编号复制分类编号。反馈可使用 `C06` 或 `C06-12` 形式。
7. 首批已经验证的 7 个图标单独归入 `C01 已验证基础`，并显示“首批已验证”状态。

## 编号规则

- 分类编号使用 `C01`、`C02` 等两位编号。
- 图标编号使用 `<分类编号>-<至少两位序号>`，例如 `C03-08`。
- 编号是面向兼容性测试的公开标识，不是业务内部编码。
- `C01` 是本次 7 个已验证图标的永久冻结快照，不随未来生产白名单扩展而变化。
- 已发布编号永久稳定。分类内新增项目只向后追加；新增分类只使用新的分类编号；废弃项目保留编号并标记 `deprecated`，不得删除、复用或填补空号。
- 每类超过 99 项时序号自然扩展为三位，不改变原有两位编号。
- 仓库保存不可变的 `ID -> Unicode 标量序列` 快照测试；任何既有映射变化都必须使测试失败。

## 数据与交互

- 测试页加载时读取本地静态候选库，不发起云调用。
- 页面初始化时使用微信系统信息 API 生成测试环境摘要；读取失败时显示“环境信息不可用”，但不影响图标测试。
- 当前分类索引保存在页面状态中。切换分类时只替换当前分类数据。
- 复制失败时使用 toast 明确提示，页面继续可用。
- 本阶段不在小程序内记录正常或异常状态，用户通过稳定编号反馈，避免引入账号、云存储和结果同步逻辑。

## 真机判定流程

1. 使用微信开发者工具“预览”生成二维码，在目标 Android 微信中打开。
2. 记录页面顶部测试环境和测试日期，按 C01–C14 顺序检查。
3. `pass`：呈现单个、完整、未裁切且语义正确的预期图形。普通候选的厂商画风差异不判失败；包含 VS16 的 Emoji 呈现候选必须显示为 Emoji 图形，退化为黑白文本记为 `fail`。C14 中明确标为“文本”的候选允许黑白文本样式。
4. `fail`：显示方框、空白、替代字符、错误语义、严重裁切，或 ZWJ/旗帜/键帽序列被拆成多个可见图形。
5. `uncertain`：能够显示但无法确定语义、组合是否完整或尺寸是否可用于界面。该状态不得进入生产白名单，需截图复核。
6. 反馈格式包含环境摘要以及 `分类或项目编号: pass/fail/uncertain`；整类全部通过可写 `C06: pass`，异常项必须逐项列出并可附截图。

## 性能与包体约束

- 候选库使用文本数据，不增加图片资源。
- 仅渲染当前分类，控制首屏节点和 setData 数据量。
