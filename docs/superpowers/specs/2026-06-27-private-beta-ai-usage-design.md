# 体验版内测与 AI 用量账本设计

> 日期：2026-06-27  
> 状态：已确认设计，待实施计划  
> 范围：微信小程序体验版真实家庭内测、隐私授权、数据删除、AI 用量账本、估算成本展示  
> 不在本阶段范围：正式上架、公开搜索访问、充值、扣费、微信支付、套餐定价

## 1. 背景

当前小程序已经具备拍照诊断、学习报告、验证试卷、学习卡点中心、学习任务包和英语练习等核心链路。下一步目标是把小程序发给少量朋友做真实家庭内测。

本轮内测选择：

- 发布方式：微信小程序体验版。
- 使用对象：朋友可创建自家孩子档案，并上传真实试卷或作业照片。
- 成本控制：暂不限制 AI 用量，优先保证体验完整性。
- 用户可见性：向用户展示完整账单雏形。
- 费用口径：显示 token、功能次数和平台估算成本，但不产生应付款项。

因此第一阶段要解决两个问题：

1. 真实孩子资料和试卷照片进入系统后，需要清晰的家长授权、内测说明和删除机制。
2. AI 调用开始产生真实运营成本后，需要记录到可追溯账本，并以“内测成本估算”的方式展示给用户和维护者。

## 2. 目标

### 2.1 产品目标

- 支持少量朋友使用体验版完成真实学习诊断闭环。
- 家长首次使用前明确知道系统会收集和处理哪些资料。
- 家长可以看到自己的 AI 用量和平台估算成本。
- 维护者可以按用户、孩子、功能、模型和时间查看 AI 成本结构。
- 为后续免费额度、套餐定价、充值扣费提供真实数据基础。

### 2.2 工程目标

- 用追加式 AI 用量事件记录替代分散日志，避免成本统计不可追溯。
- 用独立集合承载内测授权和用量事件，不侵入现有报告、试卷和学习任务包主结构。
- 在 CloudBase AI 调用边界统一写入 usage event，使后续新增模型或功能时只扩展事件类型。
- 第一阶段只展示估算成本，不实现余额、冻结、扣费和支付。

### 2.3 非目标

- 不做正式版审核和公开发布。
- 不接入微信支付或虚拟支付。
- 不设计套餐售卖页。
- 不做成本自动封顶或强制停用。
- 不把估算成本展示为用户欠费或应付账单。
- 不把内测用量数据用于自动化营销或画像推荐。

## 3. 发布内测设计

### 3.1 发布形态

第一阶段使用微信开发者工具上传体验版，邀请朋友作为体验成员。体验版只用于小范围测试，不作为正式商业服务。

发布前沿用现有门禁：

- `npm run release:check`
- `git diff --check`
- 微信开发者工具 CLI preview
- 云函数部署清单检查
- 真实数据烟测

新增一份内测发布记录，记录：

- 发布 commit
- 体验版上传时间
- 体验成员名单或微信备注
- 已部署云函数
- 本次开放功能
- 已知风险
- 回滚点
- 是否启用 AI 用量账本
- 是否启用用户账单页

### 3.2 入口控制

第一版可以继续使用体验成员控制，不强制做独立邀请码系统。若体验成员范围扩大，再增加 `betaAccessList` 或邀请码。

建议入口策略：

- 体验成员进入后可创建孩子档案。
- 非体验版路径不增加公开入口文案。
- 首页或首次进入流程展示“内测说明”。

### 3.3 内测验收路径

每次体验版发布后至少验证：

1. 创建孩子档案。
2. 上传一组试卷照片并完成 AI 分析。
3. 打开诊断报告。
4. 进入学习卡点中心。
5. 生成验证试卷并下载 PDF。
6. 点击学习任务包。
7. 查看 AI 用量账单页。
8. 删除或申请删除测试孩子档案。

## 4. 隐私授权与数据删除设计

### 4.1 首次授权

首次进入真实上传能力前，展示内测授权页或弹窗。用户必须明确确认后，才能创建孩子档案或上传试卷。

授权说明应包含：

- 收集内容：孩子姓名或昵称、年级、学科、试卷/作业照片、AI 识别结果、学习报告、验证卷、作答照片、学习卡点、学习任务包和 AI 用量记录。
- 使用目的：生成学习诊断、验证卷、学习卡点追踪、学习建议、内测问题排查和 AI 成本统计。
- 风险提示：AI 诊断可能出错，仅供家庭学习参考，不替代老师、学校或专业教育评估。
- 保存说明：内测期间保存用于连续学习记录、问题排查和产品改进。
- 删除方式：家长可以在小程序中发起删除请求，或联系维护者删除。
- 限制提醒：尽量不要上传含身份证号、住址、学校敏感信息或其他无关个人信息的照片。

### 4.2 数据访问隔离

继续沿用现有 `studentMembers` 和 `studentAccess` 权限模型：

- 家庭只能访问自己创建或受邀加入的孩子档案。
- 前端不直接读取其他家庭数据。
- 维护者只在用户授权、问题排查或内测运营需要时查看数据。

### 4.3 删除机制

第一阶段采用软删除优先：

- 孩子档案标记为 `isArchived` 或 `deletedAt`。
- 相关报告、试卷、学习记录、任务包和用量记录进入归档状态。
- 原始照片可标记为待清理，后续由维护脚本或云函数定期清理云存储。
- 删除请求记录操作人、时间、范围和处理状态。

建议新增集合：`dataDeletionRequests`

字段建议：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `_openid` | String | 发起删除的家长 |
| `studentId` | String | 目标孩子档案 |
| `scope` | String | `student_all`、`photos_only`、`usage_only` 等 |
| `reason` | String | 用户填写或系统默认 |
| `status` | String | `requested`、`processing`、`completed`、`rejected` |
| `createdAt` | Date | 发起时间 |
| `processedAt` | Date | 处理完成时间 |
| `processedBy` | String | 维护者或系统 |
| `note` | String | 处理说明 |

第一阶段可以先做到“发起请求 + 维护者处理 + 状态可见”，不必一次性实现全自动物理删除。

## 5. AI 用量账本设计

### 5.1 集合

新增集合：`aiUsageEvents`

该集合是追加式事件账本。每次 AI 调用或明显消耗 AI 成本的动作都写入一条事件。事件可以更新状态和用量结果，但不应被覆盖成另一种业务含义。

### 5.2 事件类型

第一阶段事件类型：

| 类型 | 场景 |
| --- | --- |
| `photo_analysis` | 拍照诊断、验证作答照片分析、英语纸面听写 OCR/判定 |
| `paper_generation` | 默认诊断卷和验证卷题目生成 |
| `learning_resource_pack` | 学习卡点“学一下”任务包生成 |
| `dictation_grading` | 英语认词或听写 AI 判定 |
| `report_pdf` | 若报告 PDF 生成涉及 AI，再记录；纯渲染不记录 AI 成本 |

### 5.3 字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `_openid` | String | 发起调用的微信 openid |
| `studentId` | String | 关联孩子 |
| `subject` | String | `math`、`chinese`、`english` |
| `eventType` | String | 事件类型 |
| `sourceId` | String | reportId、paperId、sessionId、resourcePackId 等 |
| `sourceType` | String | `report`、`paper`、`english_session`、`resource_pack` |
| `cloudFunction` | String | 触发调用的云函数 |
| `model` | String | 模型名，如 `hy3-preview`、`deepseek-v4-flash` |
| `provider` | String | `cloudbase_ai` |
| `inputTokens` | Number | 输入 token；无法取得时为估算 |
| `outputTokens` | Number | 输出 token；无法取得时为估算 |
| `totalTokens` | Number | 合计 token |
| `imageCount` | Number | 图片数量 |
| `pageCount` | Number | 页数或批次数 |
| `estimatedCostCny` | Number | 平台估算成本，单位元 |
| `pricingVersion` | String | 价格表版本 |
| `costSource` | String | `provider_usage`、`estimated_by_chars`、`estimated_by_image_count` |
| `status` | String | `pending`、`succeeded`、`failed` |
| `isEstimate` | Boolean | 是否含估算 |
| `isTest` | Boolean | 是否为 mock 或测试事件 |
| `errorMessage` | String | 失败原因摘要 |
| `createdAt` | Date | 创建时间 |
| `completedAt` | Date | 完成时间 |

### 5.4 写入时机

推荐模式：

1. 云函数开始调用 AI 前写入 `pending` 事件。
2. AI 返回后更新为 `succeeded`，写入 token、成本和完成时间。
3. AI 调用失败时更新为 `failed`，保留输入规模、模型和错误摘要。

若某个函数已有复杂重试机制，应避免重复记账：

- 每次真实 AI 请求可独立记一条事件。
- 如果同一业务任务重试并产生了多次 AI 成本，应保留多条事件。
- 如果只是读取缓存，不产生 AI 请求，不新增成本事件；可选记录 `cache_hit` 指标到普通日志，不进入成本账本。

### 5.5 token 与成本估算

优先级：

1. 使用云服务返回的真实 usage 字段。
2. 没有 usage 时，按输入字符、输出字符、图片数量和页数估算。
3. 估算规则必须带 `pricingVersion` 和 `costSource`，不能混作真实账单。

建议新增本地/云端价格配置：`aiPricingRules`

字段建议：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `model` | String | 模型名 |
| `unit` | String | `token`、`image`、`request` |
| `inputPricePer1k` | Number | 每千输入 token 成本 |
| `outputPricePer1k` | Number | 每千输出 token 成本 |
| `imagePriceEach` | Number | 单张图片估算成本 |
| `version` | String | 价格版本 |
| `effectiveAt` | Date | 生效时间 |
| `sourceUrl` | String | 官方或维护者记录的价格来源 |
| `note` | String | 估算说明 |

第一阶段价格表可以由维护者手工维护，不做后台配置页面。

## 6. 用户账单页设计

### 6.1 页面定位

账单页第一阶段命名建议为“AI 用量与成本估算”，避免叫“充值账单”或“消费账单”。

必须展示醒目说明：

> 当前为内测成本估算，不代表应付款项。

### 6.2 页面内容

页面分三层：

1. 汇总区：
   - 本月总 token
   - 本月平台估算成本
   - 本月 AI 调用次数
   - 涉及孩子数量

2. 功能拆分：
   - 拍照诊断
   - 试卷生成
   - 学习任务包
   - 英语练习/批改

3. 明细列表：
   - 时间
   - 孩子
   - 功能
   - 模型
   - token 或图片页数
   - 估算成本
   - 状态

### 6.3 用户语气

账单页文案要避免商业收费压力：

- 使用“平台估算成本”，不使用“应付金额”。
- 使用“内测观察”，不使用“欠费”。
- 使用“本次 AI 处理约消耗”，不使用“扣除”。

## 7. 维护者视图

第一阶段不必做复杂后台，可以先通过脚本或云数据库查询完成维护者统计。

建议提供脚本或 CLI 报表：

- 按用户统计总成本。
- 按孩子统计总成本。
- 按模型统计成本。
- 按功能统计成本。
- 列出失败但产生成本的事件。
- 列出没有 usage、只能估算的事件。

未来如果体验用户增加，再做维护者管理页。

## 8. 未来充值演进

充值系统进入第二阶段，独立设计和实现。

建议方向：

- 用户充值人民币，形成余额或学习币。
- `aiUsageEvents` 继续记录真实 AI 成本。
- `walletTransactions` 记录充值、赠送、扣费、退款和调整。
- 任务开始前做余额预检查。
- 对长任务可先冻结预估费用，成功后按规则结算，失败后释放冻结。
- 价格表使用版本化 `aiPricingRules`，保留历史价格。
- 用户看到的是产品定价或学习币消耗，维护者看到的是平台真实成本。

正式收费前必须单独确认：

- 小程序主体和服务类目。
- 小程序备案状态。
- 微信支付商户号。
- 微信小程序对虚拟商品、知识服务、教育服务和充值余额的规则。
- 退款、发票、客服、用户协议和隐私政策。

## 9. 合规注意事项

本设计不是法律意见，正式发布或收费前需要再做一次合规复核。

当前阶段必须按真实未成年人信息处理来设计，原因是用户会上传真实孩子试卷和学习报告。关键约束：

- 不满十四周岁儿童个人信息处理需要取得父母或其他监护人同意。
- 儿童个人信息应有专门保护规则和清晰告知。
- 收集、存储、使用、删除路径要可说明、可执行。
- 小程序处理用户个人信息时，需要配置和适配微信侧隐私保护指引。

参考：

- [儿童个人信息网络保护规定](https://www.cac.gov.cn/2019-08/23/c_1124913903.htm)
- [中华人民共和国个人信息保护法](https://www.cac.gov.cn/2021-08/20/c_1631050028355286.htm)
- [腾讯云：小程序隐私保护指引适配说明](https://cloud.tencent.com/document/product/1301/97930)
- [教育移动互联网应用程序备案管理平台](https://app.eduyun.cn/)

## 10. 测试与验收

### 10.1 自动化测试

实施阶段应补充：

- 授权状态 helper 测试：未授权不能进入真实上传。
- AI 用量事件写入测试：成功、失败、缓存命中、重试。
- 成本估算测试：真实 usage 优先、无 usage 降级估算、价格版本保存。
- 账单 presenter 测试：按月汇总、按功能分组、明细排序、失败事件展示。
- 权限测试：用户只能看自己可访问孩子的用量事件。
- 删除请求测试：创建请求、状态流转、归档标记。

### 10.2 真机验收

体验版发布前至少用一个真实测试账号完成：

1. 首次进入看到内测授权。
2. 拒绝授权后不能上传真实资料。
3. 同意授权后可创建孩子档案。
4. 上传照片并完成报告。
5. 生成验证卷。
6. 打开学习任务包。
7. 账单页能看到对应 AI 事件。
8. 账单页明确显示“内测成本估算，不代表应付款项”。
9. 发起删除请求后，维护者能看到并处理。

## 11. 风险与缓解

| 风险 | 缓解 |
| --- | --- |
| 用户误以为需要付款 | 页面不用“欠费/扣费/应付”等词，明确内测估算不代表应付款项 |
| 成本估算不准 | 显示估算标记，保留 `costSource` 和 `pricingVersion` |
| 重试导致成本漏记 | 在真实 AI 请求边界写事件，业务任务重试保留多条事件 |
| 用户上传过多敏感信息 | 首次授权和上传页提示只上传必要试卷内容 |
| 删除误伤排查能力 | 第一阶段软删除优先，物理删除由维护流程二次确认 |
| 后续收费返工 | 第一阶段分离 `aiUsageEvents` 与未来 `walletTransactions` |

## 12. 实施顺序建议

后续实施计划可按以下顺序拆分：

1. 内测授权与删除请求。
2. AI 用量事件模型和云函数写入 helper。
3. 接入主要 AI 调用链路。
4. 用户 AI 用量与成本估算页。
5. 维护者统计脚本。
6. 文档、发布清单和真机验收更新。

## 13. 已确认决策

- 使用体验版内测，不正式上架。
- 允许朋友创建真实孩子档案并上传真实试卷。
- 内测阶段不限制 AI 用量。
- 用户可看到完整用量账单雏形。
- 展示平台估算成本，但不收费、不扣费。
- 第一阶段只预留充值演进，不实现支付。
