# 数学工作台紧凑化、卡点证据矩阵与基础 Emoji 白名单设计

日期：2026-07-16  
状态：已确认

## 1. 背景与目标

当前数学学科工作台的“知识地图”和“待处理队列”字号、行高和留白偏大，降低了首屏信息密度。数学诊断报告虽然已有高、中、低置信度文字，但没有充分展示系统已经保存的数值证据。

本次升级解决三个问题：

1. 压缩数学工作台的地图入口和处理队列，让更多任务进入首屏。
2. 在数学诊断报告中增加高密度“卡点证据矩阵”，用真实数字解释每个卡点。
3. 恢复一组已在目标 Android 设备上验证可显示的基础 emoji，同时继续禁止兼容风险较高的复杂 emoji。

本设计只增强展示和统计数据，不改变诊断、验证卷出题、权限或导航逻辑。

## 2. 已确认方向

用户选择 C 方案：高密度分析。

核心原则：

- 数学工作台更紧凑，但不删除现有地图、处理队列、状态和操作入口。
- 数学诊断报告同时展示评分、出现频次、错题数量、验证次数和时间跨度。
- `weight` 显示为“综合置信分”，不能称为“准确率”。
- 恢复基础 emoji 白名单：`🗺️ 📚 📄 📸 📊 🎯 ✅`。
- emoji 只辅助识别，所有入口和状态必须保留文字。

## 3. 数学工作台设计

### 3.1 知识地图入口

数学工作台的知识地图入口恢复 `🗺️`，结构保持：

```text
🗺️  知识地图
     3 个待修复卡点                         ›
```

视觉约束：

- 图标约 `28-32rpx`，不再使用当前偏大的 `40rpx`。
- 标题约 `26rpx`，描述约 `20rpx`。
- 容器上下内边距约 `16rpx`，圆角不超过 `10rpx`。
- 入口仍完整显示“知识地图”，emoji 缺失时不影响理解和点击。

### 3.2 待处理队列

队列保留现有状态、卡点名称和证据摘要，改为高密度行：

```text
计算基础
证据 3 · 错题 9 · 首见 6/12 · 最近 6/14          86分
```

视觉约束：

- 区域标题约 `26rpx`。
- 卡点名称约 `23-24rpx`。
- 证据摘要约 `19-20rpx`。
- 单行上下内边距约 `14-16rpx`。
- 原有大号状态方块缩小为状态点或小型文字标记。
- 右侧显示综合置信分；状态文字继续保留，不能只显示颜色或数字。

语文工作台可复用紧凑字号，但不强制展示数学置信分。英语工作台保持现有双功能布局。

## 4. 数学卡点证据矩阵

### 4.1 每个卡点展示

数学正式诊断报告在卡点分组中增加下列指标：

| 指标 | 展示示例 | 数据来源 |
|---|---|---|
| 综合置信分 | `86 / 100` | `currentBottlenecks[].weight` |
| 出现频次 | `出现 3 次` | `evidenceCount` |
| 历史累计错题 | `累计错题 14` | 新字段 `cumulativeErrorCount` |
| 近期错题 | `近期错题 9` | `recentErrorCount` |
| 验证通过 | `通过 1` | `verificationPassCount` |
| 验证未通过 | `未通过 2` | `verificationFailCount` |
| 首次发现 | `首见 6/12` | `firstSeenAt` |
| 最近出现 | `最近 6/14` | `lastSeenAt` |
| 持续时间 | `持续 32 天` | `firstSeenAt` 到 `lastSeenAt` 的自然日差 |
| 趋势 | `持续 / 复发 / 改善中` | `trend` 与 `status` |

没有值的指标不显示 `0` 占位，验证次数除外；验证次数只有一方存在时可显示成对结果，例如“通过 0 / 未通过 1”。

### 4.2 评分表达

现有 `weight` 范围为 0–100，计算规则包括：

- 首次出现：`50 + min(30, errorCount × 5)`。
- 再次出现：增加 20。
- 改善后复发：增加 30。
- 验证未通过：增加 15。
- 验证通过：降低 30 或 40。

界面名称统一为“综合置信分”。说明文案：

> 综合置信分反映该卡点证据是否充分、是否需要优先处理，不是模型准确率或孩子答题正确率。

保留高、中、低档位作为辅助解释：

- 75–100：高置信。
- 45–74：中置信。
- 0–44：低置信。

报告不显示伪精度小数，评分只使用整数。

### 4.3 视觉结构

每个卡点使用：

1. 卡点名称、状态和综合置信分。
2. 一条 0–100 的短进度条。
3. 证据指标小标签，优先顺序为出现频次、累计错题、近期错题、验证结果、持续时间。
4. 根因与下一步行动保持原有文字层级。

矩阵必须在 360px 宽度下自然换行，不能横向滚动。

## 5. 累计错题数据设计

### 5.1 新字段

在 `subjectProfiles.currentBottlenecks[]` 增加：

```js
cumulativeErrorCount: Number
```

含义：所有有效正式诊断中，该卡点相关错题数的可追溯累计值。

### 5.2 新诊断更新

有效正式诊断合并卡点时：

```text
cumulativeErrorCount =
  previous.cumulativeErrorCount + currentReportBottleneck.errorCount
```

无效、证据不足、重复或被替代的报告不参与累计。验证报告不增加诊断错题累计。

实时累加必须复用现有 `profileAppliedAt` 幂等保护：同一报告只能写入学习档案一次。分析重试、恢复任务或重复完成回调不能再次增加 `cumulativeErrorCount`。

### 5.3 历史回算

提供一次性回算逻辑：

- 只读取 `type=diagnosis`、`status=completed`、`isEffective=true` 的正式报告。
- 排除带有 `replacedByReportId` 的旧源报告、重复样本和质量不足报告。
- 如果报告是历史重分析替代报告，以 `reanalysis.sourceReportId` / `originalReportId` 建立来源关系，同一来源只保留最终有效替代报告。
- 按学生、学科和稳定卡点标识聚合 `errorCount`。
- 优先使用 `bottleneckId`，其次使用稳定 `lpCode`。
- 无法可靠匹配的历史记录不计入，也不以 `evidenceCount` 替代。
- 回算必须可重复执行且结果幂等。
- 回算写入前记录版本号和完成时间；相同版本重复执行时覆盖聚合结果，不做增量叠加。

### 5.4 旧数据降级

当 `cumulativeErrorCount` 不存在时：

- 界面不显示“累计错题”。
- 仍展示出现频次、近期错题和验证次数。
- 不使用 `recentErrorCount × evidenceCount` 推算累计值。

## 6. 基础 Emoji 白名单

### 6.1 允许集合

第一轮仅允许：

| Emoji | 语义 |
|---|---|
| `🗺️` | 知识地图 |
| `📚` | 学习档案、学习资料 |
| `📄` | 试卷、报告 |
| `📸` | 拍照上传 |
| `📊` | 统计、证据矩阵 |
| `🎯` | 今日目标、优先行动 |
| `✅` | 完成、验证通过 |

### 6.2 禁止范围

继续禁止：

- 人物、家庭和肤色组合。
- 国旗。
- ZWJ 组合序列。
- 较新的 Unicode emoji。
- 未经目标 Android 真机验证的 emoji。
- 只依靠 emoji 表达的按钮或状态。

### 6.3 实现规则

- 建立集中式 emoji 白名单模块，不在页面散落硬编码。
- 每个 emoji 必须绑定明确语义键。
- 页面始终同时显示文字标题或无障碍标签。
- 若真机验证失败，可按语义键关闭该 emoji，不影响页面结构。
- 不引入图片资源、iconfont 或第三方图标包。

### 6.4 自动化检查

调整现有符号扫描：

- 白名单中的精确 emoji 序列允许出现。
- 白名单外的 emoji 和不稳定符号继续失败。
- 测试确保白名单入口仍有文字。
- 测试覆盖 Android 目标设备人工冒烟清单。

## 7. 交互与错误处理

- 地图入口、队列行和报告卡点沿用现有导航目标。
- 数值字段缺失时只隐藏对应指标，不显示 `NaN`、空标签或推测值。
- 评分超出范围时钳制为 0–100。
- 日期无效时不显示首见、最近或持续天数。
- 历史回算失败不能阻断诊断报告加载；保留已有字段并记录后台错误。

## 8. 测试与验收

### 8.1 自动化

- 数学工作台字号和行高契约测试。
- emoji 白名单与白名单外拦截测试。
- `buildConfidence` 数值、档位和缺失字段测试。
- `cumulativeErrorCount` 新诊断累加测试。
- 历史回算的有效报告过滤、去重、匹配和幂等测试。
- 报告 presenter 指标显示与缺失降级测试。
- 360px 和 390px DevTools 截图检查。

### 8.2 真机

在目标 Android 和 iOS 微信上检查：

- 七个白名单 emoji 均能显示。
- emoji 与文字基线对齐，不出现方框或异常放大。
- 数学工作台首屏信息密度明显提高。
- 证据矩阵无横向溢出。
- 1.2 倍系统字体下数字、标签和状态不重叠。

若某个 emoji 在 Android 失败，将其从白名单移除并改用文字或 CSS 图形，不扩大白名单。

## 9. 不在本次范围

- 将综合置信分升级为经过标注数据校准的统计学概率。
- 改变现有 weight 算法和验证卷题量阈值。
- 为所有页面恢复旧版 emoji。
- 引入图片图标、SVG、iconfont 或第三方图标库。
- 改造语文和英语的诊断评分模型。
