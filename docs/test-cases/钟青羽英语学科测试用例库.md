# 钟青羽英语学科测试用例库

更新时间：2026-06-20

## 一、当前英语学科功能状态

英语学科当前不复用数学“整卷诊断 → 学习卡点 → 验证试卷”的主链路，而是围绕钟青羽个人 PEP 词库建立单词掌握闭环。

已完成的核心功能：

| 模块 | 当前状态 | 说明 |
| --- | --- | --- |
| 个人 PEP 词库 | 已完成 | 内置钟青羽 PEP 三年级到六年级上册个人词库，首页可自动导入 |
| 英语工作台 | 已完成 | 展示今日建议、今日待练、已熟悉、拼写薄弱、真正掌握、最近需要多见几次的词 |
| 单词熟悉度 | 已完成 | 每轮默认 20 词，中文/英文提示混合；孩子口头回答，AI 自动判定 |
| 纸面听写 | 已完成 | 每轮默认 20 词，AI 播放提示，孩子写在纸上，完成后拍照上传 |
| 听写纸批改 | 已完成 | 以本次 20 个候选词约束 OCR，再做确定性拼写复核 |
| 双维掌握状态 | 已完成 | `familiarity` 和 `spelling` 独立推进，`overallMastery` 派生整体掌握 |
| 错词复现与复测 | 已完成 | 错词提高抽中优先级，正确后进入 1 天、3 天、7 天复测 |
| 学习记录接入 | 已完成 | 学习记录可展示英语单词熟悉度、纸面听写和听写纸照片证据 |
| 语音“下一个” | 已完成 | 纸面听写支持“好了/下一个”辅助推进，按钮仍为主通道 |
| 入口收敛 | 已完成 | 首页只保留一个主 CTA；工具区不重复当前主任务；词库维护不再常驻首页 |
| 时态/句型 | 暂不做 | 当前阶段聚焦单词，不做时态、句型、阅读、作文 |

## 三、自动化用例清单

机器可读用例库：`tests/fixtures/english-devtools-test-cases.json`

这份 JSON 是英语 E2E 的单一事实来源。每个用例必须声明：

- `route`：微信开发者工具打开的真实小程序页面。
- `expectedTexts` / `forbiddenTexts`：首屏可见文案和禁止出现的旧入口。
- `steps`：需要执行的模拟器动作，例如点击按钮、调用页面方法、上传听写纸。
- `dataAssertions`：该用例保护的数据状态，例如词库数量、20 词队列、错词复现、照片证据。
- `artifacts`：本地沉淀产物，目前至少包含截图和 `report.json`。

| 用例 ID | 功能点 | 页面 | 模拟器动作 | 数据校验 |
| --- | --- | --- | --- | --- |
| ENG-WB-001 | 英语工作台 | `subject-home` | 点击“开始认词”，确认跳转到认词练习页 | `englishVocabularyStats.totalWords=505`；认词/听写/错词本/学习记录入口齐全 |
| ENG-IMPORT-001 | 自动导入 | `subject-home` | 打开空词库学生的英语工作台 | `seedPersonalVocabulary` 调用 1 次；导入后显示 505 词 |
| ENG-FAM-001 | 认词练习 | `english-practice` | 调用 `onRecognitionResult` 提交一次识别结果 | 生成 20 词；错词重新入队，队列变 21；提交 `durationMs` |
| ENG-DICT-001 | 纸面听写 | `english-dictation` | 调用语音“下一个”，再点击“拍照上传” | 进度推进到第 2 词；上传 1 张照片；OCR 批改完成；返回 2 条逐词结果 |
| ENG-RECORD-001 | 学习记录 | `upload-history` | 打开英语筛选学习记录 | 时间线包含认词、纸面听写、听写纸照片证据 |
| ENG-WRONG-001 | 错词本 | `english-wrong-words` | 点击“去认词练习”，确认跳转到认词练习页 | 薄弱词 18、待复测 16、已稳定 140；错词含 science 和 museum |
| ENG-EMPTY-001 | 空态 | `english-practice` | 打开无词库学生的认词练习页 | 0 词 session 显示可恢复空态，不出现 1/20 进度 |

## 四、执行方式

执行英语页面自动化：

```bash
npm run test:e2e:english
```

输出目录：

```text
tmp/e2e/english/
```

输出文件：

- `report.json`
- `ENG-*-initial.png`：每个用例初始页面截图。
- `ENG-*-after-*.png`：有点击、判定、上传等交互的用例会额外保存交互后截图。

`report.json` 会记录：

- 每个用例的 `id / feature / route / status / durationMs`。
- 该用例声明的 `steps` 和 `dataAssertions`。
- `artifacts.screenshots`：本次实际生成的截图路径。
- `consoleCount / exceptionCount`：运行期间的小程序控制台信息数量。
