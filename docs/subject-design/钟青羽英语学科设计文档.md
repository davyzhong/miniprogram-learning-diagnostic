# 钟青羽英语学科设计文档

> 目的：给后续开发者、产品协作者或其他 AI 快速理解钟青羽英语学科的设计目标、功能边界、数据结构和落地顺序。
> 适用范围：微信小程序 `miniprogram-learning-diagnostic` 的英语学科链路。
> 当前版本：v3，英语词汇掌握系统。
> 更新原则：当前阶段只做“个人词库、认词练习、纸面听写、错词本、学习记录”，暂不扩展到完整英语学习系统。

---

## 0. 设计结论

英语学科当前不再按“拍照诊断试卷”或“大英语学习系统”来设计，而是聚焦一个更清晰、更高频、更容易验证的闭环：

```text
个人词库
↓
认词练习
↓
纸面听写
↓
错词本
↓
学习记录
↓
复测与掌握状态更新
```

这套闭环解决的是钟青羽当前最现实的问题：

- 这个词是否认识；
- 看到中文能不能想起英文；
- 看到英文能不能知道中文；
- 最后能不能在纸上完整写对。

当前阶段明确不做：

- 发音评分；
- 听力专项训练；
- 时态和句型专项；
- 阅读理解；
- 作文表达；
- 英语整卷拍照诊断；
- 类似数学的英语“学习卡点”体系。

这些内容后续可以扩展，但不进入当前版本，以免把 MVP 重新做大。

---

## 1. 整套背景

### 1.1 为什么英语不能照搬数学链路

数学链路的证据来自纸笔过程：列式、演算、单位、订正、验算都能在卷面中被观察。因此数学适合“拍照试卷 -> 诊断学习卡点 -> 生成验证试卷 -> 拍照复测”的闭环。

英语当前最明显的问题不是一道试题背后的复杂认知链路，而是更基础、更高频的词汇掌握：

- 单词写错；
- 词义不熟；
- 看到中文想不起英文；
- 看到英文不确定中文意思；
- 听写时漏字母、错字母、顺序错。

所以英语第一阶段应该独立设计，不复用数学的整卷诊断报告模型。

### 1.2 为什么只做词汇掌握

对小学生英语来说，词汇是最基础的数据对象。无论后续做听力、阅读、句型、作文，都会回到“这个词是否认识、是否能写、是否稳定掌握”。

因此当前阶段先把词汇掌握做扎实：

- 有一个属于钟青羽自己的词库；
- 每个词有来源、年级、单元和掌握状态；
- 每次练习都能沉淀到词级记录；
- 错词会自动提高复现优先级；
- 家长可以看到今天练了什么、错了什么、下次该复测什么。

### 1.3 当前真实基础

项目已经具备一批英语基础数据和能力：

| 项目 | 当前情况 |
| --- | --- |
| PEP 个人词库 | 已从三年级到六年级上册资料生成 505 条种子词 |
| 云函数 | 已有 `englishVocabulary` 作为英语词库和练习主入口 |
| 页面 | 已有英语工作台、`english-practice`、`english-dictation` 等基础页面 |
| 状态模型 | 已有 `familiarity` 和 `spelling` 双维字段雏形 |
| 学习记录 | 已开始接入 `englishPracticeSessions` |

但从产品设计角度看，当前还存在三个问题：

1. 认词练习的交互不够清楚：孩子不知道该看文字、听提示，还是按哪里录音。
2. 纸面听写入口不够醒目：这应该是一级核心功能，不应藏在次级流程里。
3. 词库来源不应只有已上传的 PEP 表：还需要补充小学阶段常用词，以及真实错词、手动添加词。

## 2. 功能边界

### 2.1 当前必须做的 5 个功能

| 功能 | 定位 | 当前阶段要求 |
| --- | --- | --- |
| 个人词库 | 英语学习的数据底座 | 汇总教材词、小学常用词、真实错词、手动添加词 |
| 认词练习 | 判断“是否认识这个词” | 文字提示为主，显式录音按钮，AI 判定回答 |
| 纸面听写 | 判断“是否写得出这个词” | 出 20 个词，纸上写，拍照上传识别 |
| 错词本 | 管理薄弱词 | 汇总不熟词、拼写错词、待复测词 |
| 学习记录 | 保存证据链 | 按天记录认词、听写、错词变化和上传照片 |

### 2.2 当前明确不做的功能

| 暂不做 | 原因 |
| --- | --- |
| 发音评分 | 复杂度高，且当前目标不是口语发音纠正 |
| AI 默认读题 | 认词练习看文字即可，默认朗读会增加噪声和等待 |
| 听音专项 | 与认词、听写容易混淆，暂不拆新能力 |
| 时态句型 | 需要另一套语法数据模型，不能污染词汇状态 |
| 阅读作文 | 不是当前最短闭环 |
| 英语整卷诊断 | 当前问题不是整卷认知诊断，而是词级掌握 |

## 3. 核心闭环

### 3.1 总流程

```text
导入/补充个人词库
↓
系统按薄弱程度和复测时间抽词
↓
孩子做认词练习或纸面听写
↓
AI/规则判定 correct、incorrect、unclear
↓
更新词级状态
↓
错误词进入错词本
↓
按 1 天、3 天、7 天安排复测
↓
学习记录沉淀当天证据
```

### 3.2 两种练习测不同能力

| 功能 | 孩子做什么 | 主要验证 | 更新维度 |
| --- | --- | --- | --- |
| 认词练习 | 看中文说英文，或看英文说中文 | 是否认识、是否能快速调取词义 | `recognition` / `familiarity` |
| 纸面听写 | 根据提示在纸上写英文单词 | 是否能完整拼写 | `spelling` |

这两个功能不能合并。一个词“认识”和“会写”是两件事。

### 3.3 掌握状态口径

一个词只有同时满足：

- 认词维度稳定通过；
- 拼写维度稳定通过；

才算真正掌握。

如果只认识但写不出，展示为“会认不会写”。如果拼写测过但词义不熟，展示为“词义不熟”。如果两边都薄弱，展示为“重点错词”。

## 4. 个人词库设计

### 4.1 词库来源

个人词库不是通用词库，而是钟青羽当前阶段需要掌握的词库。来源分四类：

| 来源 | 说明 | 优先级 |
| --- | --- | --- |
| PEP 教材词 | 已导入三年级到六年级上册 505 条 | 最高 |
| 小学常用词 | 补充教材表未覆盖但小学阶段常见的高频词 | 高 |
| 真实错词 | 从听写、作业、试卷中发现的错词 | 最高 |
| 手动添加 | 家长临时加入的考试或老师要求词 | 中 |

### 4.2 为什么要补小学常用词

只用已上传的 PEP 单词表会有三个问题：

1. 有些真实考试或老师听写词不一定出现在当前表格中。
2. 教材表可能漏掉常见变体、短语或基础词。
3. 系统需要覆盖“孩子真实会遇到的词”，而不是只覆盖“文件里出现过的词”。

因此个人词库应支持“基础教材词 + 常用补充词 + 真实错词”的组合。

### 4.3 词条字段

建议每个词条包含：

```js
{
  studentId: 'student_xxx',
  word: 'Wednesday',
  normalizedWord: 'wednesday',
  meanings: ['星期三'],
  cnSynonyms: ['周三'],
  phonetic: '',
  partOfSpeech: '',

  sourceTypes: ['pep', 'common', 'mistake', 'manual'],
  sources: [
    {
      type: 'pep',
      grade: 5,
      volume: '上册',
      unit: 'Unit 2',
      file: 'PEP五年级上册 英语单词句型表.pdf'
    }
  ],

  recognition: {
    status: 'untested',
    correctCount: 0,
    wrongCount: 0,
    unclearCount: 0,
    lastTestedAt: '',
    nextReviewAt: ''
  },

  spelling: {
    status: 'untested',
    correctCount: 0,
    wrongCount: 0,
    unclearCount: 0,
    lastTestedAt: '',
    nextReviewAt: ''
  },

  overallMastery: 'untested',
  createdAt: Date,
  updatedAt: Date
}
```

现有 `familiarity` 字段可以继续兼容，新的产品文案建议统一叫“认词”或“熟悉度”，避免给家长显示过多技术词。

### 4.4 去重规则

导入时按 `normalizedWord` 去重。

同一个词可以保留多个来源，例如：

```text
word: "football"
sourceTypes: ["pep", "common", "mistake"]
sources: [PEP 五上 Unit 2, 小学常用词, 2026-06-20 听写错词]
```

这样既避免重复练同一个词，又能保留“为什么这个词重要”的上下文。

## 5. 认词练习设计

### 5.1 功能定位

认词练习用于判断孩子是否认识这个词。

它不是听写，也不是发音评分。它只回答两个问题：

- 看到中文，能不能说出英文；
- 看到英文，能不能说出中文。

### 5.2 交互原则

当前阶段认词练习以“看文字”为主，不默认让 AI 读题。

推荐页面结构：

```text
题号 3 / 20

提示：
星期三

请说出对应英文

[开始录音回答]

辅助：
[播放英文发音] [跳过] [我不认识]
```

如果是英文到中文：

```text
题号 4 / 20

提示：
Wednesday

请说出中文意思

[开始录音回答]

辅助：
[播放英文发音] [跳过] [我不认识]
```

关键点：

- 必须有明确的“开始录音回答”按钮；
- 录音状态必须可见；
- 不要让孩子猜是不是已经在听；
- 不默认播放 AI 语音，避免等待和误解；
- “播放英文发音”只是辅助按钮，不是主流程。

### 5.3 判定规则

认词练习三态判定：

| 判定 | 含义 | 处理 |
| --- | --- | --- |
| `correct` | 明确答对 | 推进认词维度 |
| `incorrect` | 明确答错或说不知道 | 进入错词本 |
| `unclear` | 语音识别失败或噪声过大 | 不计对错，稍后重测 |

中文到英文时，允许大小写差异和轻微识别归一。

英文到中文时，允许同义词，例如“星期三”和“周三”都算正确。

### 5.4 每次练习

默认每次 20 个词。

抽词优先级：

1. 认词错过的词；
2. 今天到期复测的词；
3. 纸面听写错过但认词未测的词；
4. 新词；
5. 已掌握词的少量回顾。

## 6. 纸面听写设计

### 6.1 功能定位

纸面听写用于判断孩子是否能完整写出英文单词。

这是英语当前阶段最关键的验证功能，因为真实考试和老师听写最终都落在纸面拼写上。

### 6.2 交互流程

```text
生成 20 个词
↓
页面逐个展示中文提示或英文词义提示
↓
孩子在纸上按顺序写英文
↓
点击“下一个”
↓
全部完成后拍照上传
↓
系统识别纸面结果
↓
生成听写结果
↓
错词进入错词本
```

### 6.3 页面结构

```text
纸面听写

准备一张纸，按题号一行一个词写英文。

题号 5 / 20
中文提示：星期三

[下一个]
[重读提示] [上一题]

完成后：
[拍照上传听写纸]
```

说明：

- 主操作是“下一个”按钮；
- 可选支持孩子说“好了”或“下一个”，但不能依赖语音控制；
- 每题不展示英文答案；
- 完成前可以回看题号，但不展示目标词；
- 完成后一次性拍照上传。

### 6.4 纸面识别原则

纸面听写不做开放式英语作文 OCR，而是“候选词约束识别”。

系统知道本次 20 个目标词，因此判定时应按以下方式：

```text
本次 20 个候选词
↓
识别照片中的书写文本
↓
按题号或位置匹配
↓
与目标词计算拼写差异
↓
输出 correct / incorrect / unclear
```

判定示例：

| 目标词 | 识别结果 | 判定 |
| --- | --- | --- |
| Wednesday | Wednesday | correct |
| Wednesday | Wensday | incorrect |
| Wednesday | 空白 | incorrect |
| Wednesday | 看不清 | unclear |

`unclear` 不直接算错，但会进入“需重测”。

## 7. 错词本设计

### 7.1 功能定位

错词本不是一个静态列表，而是英语词汇掌握的工作台。它告诉家长和孩子：

- 哪些词总错；
- 哪些词是会认不会写；
- 哪些词是不熟；
- 哪些词今天该复测；
- 哪些词已经稳定。

### 7.2 错词来源

| 来源 | 说明 |
| --- | --- |
| 认词练习答错 | 不认识、中文英文对应不上 |
| 纸面听写写错 | 拼写错误、漏字母、顺序错 |
| OCR/语音 unclear 多次 | 进入待确认，不直接算错 |
| 家长手动标记 | 从作业或老师反馈中手动加入 |

### 7.3 错词分组

建议错词本首页按以下分组：

| 分组 | 含义 | 操作 |
| --- | --- | --- |
| 高频错词 | 多次错误，优先处理 | 立即练习 |
| 会认不会写 | 认词通过，听写错误 | 去纸面听写 |
| 不熟词 | 认词错误或未掌握 | 去认词练习 |
| 待复测 | 到达 1/3/7 天复测点 | 开始复测 |
| 已稳定 | 最近连续通过 | 低频回顾 |

### 7.4 错词卡片

单个错词卡片建议展示：

```text
Wednesday
星期三

状态：会认不会写
来源：五年级上册 Unit 2
最近错误：纸面听写写成 Wensday
下次复测：明天

[认词] [听写]
```

## 8. 学习记录设计

### 8.1 功能定位

学习记录是孩子英语学习的证据链，不只是上传历史。

它需要记录：

- 哪天做了认词；
- 哪天做了纸面听写；
- 哪些词答错；
- 哪些词复测通过；
- 上传了哪张听写纸；
- 掌握状态发生了什么变化。

### 8.2 时间线结构

建议按天组织：

```text
2026年6月20日

认词练习
20 词，正确 16，错误 3，不清楚 1
新增不熟词：Wednesday, science, museum

纸面听写
20 词，写对 14，写错 5，不清楚 1
新增拼写错词：Wednesday, tomorrow...
查看听写纸照片
```

### 8.3 与首页关系

英语学科首页不应该重复展示完整学习记录，只展示摘要和入口：

- 今天待复测 8 个；
- 高频错词 5 个；
- 最近一次纸面听写正确率 70%；
- 最近一次认词正确率 85%；
- 进入完整学习记录。

完整明细放到学习记录页。

## 9. 英语工作台设计

### 9.1 页面定位

英语工作台不是“学科诊断页”，而是“词汇掌握首页”。

首屏目标：

1. 让家长马上知道今天该做什么；
2. 让孩子马上看到两个核心入口；
3. 不把低频维护功能放到最高优先级。

### 9.2 推荐首屏结构

```text
英语词汇掌握
钟青羽 · 6年级

今天建议
先做 20 词纸面听写，重点复测 8 个拼写薄弱词。

[认词练习]
看中文/英文，说出对应内容

[纸面听写]
纸上写英文，完成后拍照识别

数据摘要
个人词库 505+
待复测 12
错词 18
已稳定 96

错词提醒
Wednesday / science / museum ...

辅助入口
[错词本] [个人词库] [学习记录]
```

### 9.3 入口优先级

| 优先级 | 入口 | 说明 |
| --- | --- | --- |
| P0 | 认词练习 | 每天可做，高频 |
| P0 | 纸面听写 | 当前最关键验证 |
| P1 | 错词本 | 复盘和定向处理 |
| P1 | 学习记录 | 查看证据链 |
| P2 | 个人词库 | 低频维护，不应占据首屏主按钮 |

个人词库是底座，不是每天高频操作，不应在首页以“导入词库”占据最高优先级。系统初始化时应自动尝试导入基础词库；只有导入失败或词库为空时，才提示家长处理。

## 10. 数据模型建议

### 10.1 `studentEnglishWords`

个人词库主集合，记录每个词的来源和掌握状态。

关键字段：

```js
{
  studentId,
  word,
  normalizedWord,
  meanings,
  cnSynonyms,
  sourceTypes,
  sources,
  recognition,
  spelling,
  overallMastery,
  status,
  createdAt,
  updatedAt
}
```

### 10.2 `englishPracticeSessions`

每次认词或听写一条 session。

```js
{
  studentId,
  functionType: 'recognition' | 'dictation',
  wordLimit: 20,
  wordItems: [],
  attempts: [],
  photoFileIds: [],
  status: 'created' | 'in_progress' | 'analyzing' | 'completed' | 'failed',
  startedAt,
  completedAt
}
```

### 10.3 错词本是否需要独立集合

第一阶段不建议新增 `englishWrongWords` 集合。

错词本可以从 `studentEnglishWords` 派生：

- `recognition.wrongCount > 0`
- `spelling.wrongCount > 0`
- `recognition.status === 'needs_practice'`
- `spelling.status === 'needs_practice'`
- `nextReviewAt <= today`

等错词本交互复杂后，再考虑独立集合。

## 11. 状态规则

### 11.1 维度状态

认词和听写各自运行一套状态：

| 状态 | 含义 |
| --- | --- |
| `untested` | 尚未有效测试 |
| `needs_practice` | 明确答错或写错 |
| `reviewing` | 已答对，进入复测 |
| `mastered` | 连续复测通过 |

### 11.2 判定三态

| 判定 | 处理 |
| --- | --- |
| `correct` | 推进状态，安排下一次复测 |
| `incorrect` | 进入薄弱，增加错词权重 |
| `unclear` | 不计对错，稍后重测 |

### 11.3 复测节奏

第一版采用：

```text
第一次正确 -> 1 天后复测
第二次正确 -> 3 天后复测
第三次正确 -> 7 天后复测
第四次正确 -> mastered
```

如果中途答错：

```text
回到 needs_practice
correctCount = 0
wrongCount + 1
```

## 12. 实施计划

### Phase 1：英语工作台重构

目标：让入口清楚、功能不重复、词库不喧宾夺主。

要做：

1. 英语首页改名为“英语词汇掌握”。
2. 首屏展示今天建议和两个主入口：认词练习、纸面听写。
3. 移除“拍照诊断、默认试卷、学习卡点”等数学式入口。
4. 个人词库入口降级为辅助入口。
5. 词库为空时自动触发初始化导入，失败才展示修复提示。

验收：

- 首页一屏内能看到认词和纸面听写两个主入口；
- 不再出现两个返回按钮或双顶部 banner；
- 不再把“导入个人词库”作为常驻最高优先级入口；
- 词库已有数据时不显示“词库为空”。

### Phase 2：认词练习重构

目标：解决“没有录音按钮、交互迷惑”的问题。

要做：

1. 页面以文字提示为主，不默认播放 AI 语音。
2. 增加醒目的“开始录音回答”按钮。
3. 明确显示当前题目方向：中文 -> 英文，或英文 -> 中文。
4. 录音中、识别中、判定后都有清晰状态。
5. 答错词进入错词本派生视图。

验收：

- 用户一眼知道该说什么；
- 录音入口清楚；
- 无需等待默认 TTS；
- 完成后能看到正确、错误、不清楚统计。

### Phase 3：纸面听写入口与流程

目标：把听写变成英语一级核心功能。

要做：

1. 英语工作台增加“纸面听写”主入口。
2. 生成 20 词听写 session。
3. 每题显示中文提示和题号，不显示英文答案。
4. 通过“下一个”控制节奏。
5. 完成后拍照上传听写纸。
6. 识别后更新 `spelling`。

验收：

- 能从首页直接进入纸面听写；
- 可以完整走完 20 词；
- 可以上传听写纸；
- 听写结果进入学习记录；
- 拼写错词能在错词本看到。

### Phase 4：错词本

目标：把薄弱词集中起来，形成复盘入口。

要做：

1. 新增或改造错词本页面。
2. 按“高频错词、会认不会写、不熟词、待复测、已稳定”分组。
3. 单词卡片显示最近错误、来源、下次复测。
4. 每个词支持进入认词或听写。

验收：

- 能看到真实错词而不是空列表；
- 能区分“会认不会写”和“不熟词”；
- 能从错词本继续练习。

### Phase 5：学习记录整合

目标：让英语学习证据完整可追溯。

要做：

1. 学习记录接入认词 session。
2. 学习记录接入纸面听写 session。
3. 显示听写照片和识别结果。
4. 按天汇总英语练习结果。

验收：

- 首页进入学习记录能看到英语事件；
- 英语工作台进入学习记录可默认筛选英语，但可切回全部；
- 每条听写记录能追溯照片和错词结果。

## 14. 给后续 AI 的约束

后续 AI 接手英语链路时，应遵守：

1. 当前英语只做词汇掌握，不扩展时态、句型、阅读、作文。
2. 个人词库是底座，但不是高频入口，不能长期占据首页主视觉。
3. 认词练习以文字提示为主，必须有明确录音按钮。
4. 纸面听写是一级功能，不能藏在“默认试卷”或“拍照诊断”里。
5. 错词本必须从真实练习结果派生，不要手写假数据。
6. 学习记录要保留证据链，特别是听写纸照片。
7. `unclear` 不能当作错误，也不能当作正确。
8. 新增小学常用词时要标记来源，不要覆盖 PEP 词源。
9. 不要把英语数据写入数学 `reports` 的学习卡点模型。
10. 所有实现都要围绕“会认 + 会写 + 可复测”这个闭环。
