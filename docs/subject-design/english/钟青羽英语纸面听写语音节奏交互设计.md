# 钟青羽英语纸面听写语音节奏交互设计

> 文档性质：英语学科纸面听写交互升级设计。
> 创建日期：2026-06-20
> 适用范围：微信小程序 `miniprogram-learning-diagnostic` 的 `english-dictation` 页面。
> 关联文档：[钟青羽英语学科设计文档](./钟青羽英语学科设计文档.md)、[钟青羽英语双功能闭环设计规格](./钟青羽英语双功能闭环设计规格.md)、[钟青羽英语双功能闭环技术实现文档](./钟青羽英语双功能闭环技术实现文档.md)。

## 1. 背景

当前英语纸面听写已经具备以下能力：

- 从个人 PEP 词库中抽取默认 20 个拼写维度待练词；
- 生成 `word-dictation-paper` 会话；
- 逐词展示提示；
- 辅助播放当前提示；
- 手动点击“下一个”；
- 完成后拍照上传听写纸；
- 使用本次候选词做约束 OCR，批改结果只更新 `spelling` 维度。

但当前交互更像“孩子自己看页面翻题”，不像真实家庭场景中的“家长报听写”。实际使用中，孩子应该在纸上写，系统负责按节奏报题；孩子写完后通过“OK / 好了 / 下一个”推进下一词。

因此，本次升级的目标是把纸面听写从“手动逐题页”升级为“自动报题 + 纸笔作答 + 语音推进”的会话流程。

---

## 2. 目标与非目标

### 2.1 目标

1. 进入纸面听写后，先展示本轮 20 个词的完整列表，便于家长确认。
2. 点击“开始听写”或说“开始”后，系统自动播放第一个词的提示。
3. 每题播放提示后，系统进入 5-10 秒书写等待时间，默认 7 秒。
4. 孩子说“OK”“好了”“好啦”“下一个”“next”等口令后，系统自动进入下一题并播放提示。
5. 页面保留按钮兜底：开始、重读、下一个、暂停、继续、拍照上传。
6. 听写态不持续暴露英文答案，避免破坏纸面听写效果。
7. 不改变现有抽词、OCR 批改、`spelling` 维度状态更新逻辑。

### 2.2 非目标

1. 不做真正的全程连续监听。微信小程序语音识别在权限、环境噪音和插件稳定性上不适合依赖无感长监听。
2. 不在本轮升级中做英文拼读教学、音标讲解或错词讲解。
3. 不改变 `englishPracticeSessions` 的核心业务语义。
4. 不把英语纸面听写接入数学式 `reports → bottlenecks → papers` 链路。

## 3. 核心设计：三态流程

纸面听写页面升级为三段式：

```text
准备态 ready
  ↓ 点击“开始听写”或说“开始”
听写态 running
  ↓ 20 个词全部播放完成
完成态 finished
  ↓ 拍照上传听写纸
批改结果态 reviewed
```

### 3.1 准备态

准备态面向家长和孩子一起确认本轮任务。

页面应展示：

- 本轮 20 个词列表；
- 每个词的英文、中文意思、单元、拼写状态；
- 听写说明：“准备一张纸，按题号一行一个词写英文”；
- 主按钮：“开始听写”；
- 辅助提示：“也可以说‘开始’”。

准备态允许显示英文答案，因为此时还没有开始正式听写，目标是让家长确认本轮词是否合理。

### 3.2 听写态

听写态面向孩子独立书写。

页面应展示：

- 当前题号：`第 3 / 20 题`；
- 当前提示类型：中文提示 / 英文发音；
- 中文提示题可显示中文意思；
- 英文提示题不显示英文单词，只显示“请听英文发音并写出单词”；
- 倒计时或状态文案：`正在播放`、`请书写`、`说“好了”进入下一题`；
- 操作按钮：重读、下一个、暂停。

开始听写后不在主区域持续显示完整英文列表，避免孩子抄答案。完整列表可以收起到“本轮词单”折叠区；默认折叠，家长需要时再展开。

### 3.3 完成态

当最后一题完成后，页面进入完成态。

页面应展示：

- “本轮 20 个词已报完”；
- “请拍照上传听写纸”；
- 上传按钮；
- 上传进度；
- AI 批改结果摘要。

完成态继续复用现有上传和 OCR 批改逻辑。

## 4. 会话状态机

页面增加 `dictationPhase` 和 `playbackState` 两层状态。

### 4.1 `dictationPhase`

| 状态 | 含义 | 可执行动作 |
| --- | --- | --- |
| `ready` | 已生成 20 词，等待开始 | 开始听写、重新生成 |
| `running` | 正在听写 | 重读、下一个、暂停 |
| `paused` | 听写暂停 | 继续、重读 |
| `finished` | 20 词已报完 | 拍照上传 |
| `reviewed` | 已上传并完成批改 | 查看结果 |

### 4.2 `playbackState`

| 状态 | 含义 | 进入条件 |
| --- | --- | --- |
| `idle` | 未播放 | 准备态或暂停态 |
| `speaking` | 正在 TTS 播放提示 | 开始听写、重读、进入下一题 |
| `writing` | 播放完成后等待孩子书写 | TTS 成功或播放降级后 |
| `waitingCommand` | 等待孩子口令推进 | 书写等待时间结束 |

### 4.3 状态流

```text
ready
  ├─ startDictation()
  ↓
running + speaking
  ├─ TTS 成功或失败降级
  ↓
running + writing
  ├─ 7 秒等待结束
  ↓
running + waitingCommand
  ├─ 口令 OK / 好了 / 下一个 / next
  ↓
advanceToNextWord()
  ├─ 未到最后一题 → running + speaking
  └─ 已到最后一题 → finished
```

## 5. 语音口令设计

### 5.1 支持口令

| 意图 | 口令 |
| --- | --- |
| 开始 | `开始`、`开始听写`、`start` |
| 下一题 | `OK`、`okay`、`好了`、`好啦`、`下一个`、`下一题`、`next` |
| 重读 | `重读`、`再读一遍`、`repeat` |
| 暂停 | `暂停`、`停一下`、`pause` |
| 继续 | `继续`、`继续听写`、`resume` |

### 5.2 识别策略

1. 准备态只识别“开始”类口令。
2. 听写态优先识别“下一题”类口令。
3. 未听清时不自动推进，只提示“没有听清，可以点下一个”。
4. 语音推进是主体验，但按钮必须始终可用。

### 5.3 监听策略

不做后台长监听。页面在以下时机启动一次命令监听：

- 准备态点击“语音开始”按钮；
- 每题进入 `waitingCommand` 后，显示“说‘好了’进入下一题”按钮；
- 用户点击语音按钮后开始短时识别。

后续如果微信插件稳定性验证良好，可以再探索 `waitingCommand` 自动弹出短时监听，但 MVP 不依赖它。

## 6. 自动播放规则

### 6.1 播放内容

当前 `wordItems` 已有 `promptType`：

- `promptType = chinese`：播放中文意思，孩子写英文；
- `promptType = english`：播放英文单词发音，孩子写英文。

### 6.2 页面显示

| 提示类型 | 播放内容 | 页面显示 |
| --- | --- | --- |
| 中文提示 | 中文意思 | 显示中文意思 |
| 英文提示 | 英文发音 | 不显示英文单词，只显示“请听英文发音并写出单词” |

### 6.3 播放失败降级

如果 WechatSI TTS 不可用：

- 中文提示题仍可显示中文意思；
- 英文提示题显示“语音播放失败，请家长读本题英文”；
- 页面允许家长展开本轮词单查看当前英文词；
- 不阻塞听写流程。

## 8. 数据与兼容性

本次升级优先作为前端交互升级，不要求改变云端数据模型。

可以新增的页面内数据：

```js
{
  dictationPhase: 'ready',
  playbackState: 'idle',
  writingWaitSeconds: 7,
  writingCountdown: 0,
  commandHint: '点击开始，或说“开始”',
  wordListExpanded: true,
  autoStartedAt: 0,
  currentPromptStartedAt: 0
}
```

可选写入 `englishPracticeSessions` 的字段：

```js
{
  interactionMode: 'voice-paced-paper',
  promptWaitSeconds: 7,
  startedAt: '2026-06-20T...',
  finishedPromptAt: '2026-06-20T...'
}
```

为了减少首轮风险，第一版可以不新增云端字段，只继续用现有 `durationMs` 记录整场耗时。若后续需要分析“每题反应时间”，再把逐题播放和推进事件写入 `attempts` 或新字段。

## 9. 测试要求

### 9.1 单元 / 页面流测试

必须覆盖：

1. 进入页面后展示 20 个词列表，`dictationPhase = ready`。
2. 点击“开始听写”后进入 `running`，并自动调用播放当前提示。
3. `handleVoiceNextCommand('OK')` 能推进下一题。
4. `handleVoiceNextCommand('好了')` 能推进下一题。
5. `handleVoiceNextCommand('下一个')` 能推进下一题。
6. 进入最后一题后再推进，页面进入 `finished`。
7. 听写态英文提示题不在主提示区域显示英文答案。
8. 上传听写纸仍调用现有上传、提交和 OCR 分析链路。

### 9.2 E2E 测试

英语 DevTools E2E 用例 `ENG-DICT-001` 应升级为：

- 预期文案包含：`本轮词单`、`开始听写`、`第 1 / 20 题`、`说“好了”进入下一题`、`拍照上传`；
- 步骤包含：
  - 调用 `onStartTap`；
  - 调用 `handleVoiceCommand('OK')` 或 `handleVoiceNextCommand('OK')`；
  - 断言 `currentIndex` 推进；
  - 上传照片；
  - 断言 `analysisStatus = completed`。

## 11. 验收标准

1. 进入纸面听写后，可以看到本轮 20 个词列表。
2. 点击“开始听写”后，系统自动播放第一题提示。
3. 说“OK”“好了”“下一个”可以推进到下一题。
4. 推进后系统自动播放下一题提示。
5. 听写过程中英文答案不持续暴露在主提示区域。
6. 20 题结束后进入拍照上传。
7. 上传和 AI 批改结果展示不退化。
8. 原有英语认词、错词本、学习记录不受影响。
