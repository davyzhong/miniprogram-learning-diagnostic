# 钟青羽学习卡点学习材料任务包竞品调研与设计文档

> 目的：解决“学习卡点背后只有外部链接，孩子点了也不能直接学习”的问题，把学习材料升级为小程序内可执行、可记录、可复测的学习任务包。
> 适用范围：微信小程序 `miniprogram-learning-diagnostic` 的数学学习卡点链路，后续可扩展到英语单词错词包和语文错项包。
> 形成日期：2026-06-17。
> 当前阶段：产品设计与落地拆解依据，不直接替代现有验证卷和报告链路。

---

## 1. 背景

当前数学链路已经能完成：

```text
试卷拍照
  ↓
AI 诊断错题
  ↓
归纳学习卡点
  ↓
生成验证卷
  ↓
拍照回传
  ↓
更新掌握状态
```

但“卡点修复”这一段仍然偏弱。系统会推荐一些资源链接，但这些链接对家庭实际使用有几个问题：

1. 孩子点开以后不一定知道看哪一段。
2. 外部平台会把孩子带到信息流、评论区或推荐流。
3. 家长需要自己筛选、打开、解释和判断是否学会。
4. 系统无法记录孩子是否看过、是否理解、是否练过。
5. 学习材料与后续验证卷之间没有强绑定。

所以这次设计的核心不是“再推荐更多链接”，而是把资源转化成一个小程序内的任务：

```text
学习卡点
  ↓
学习任务包
  ↓
微讲解
  ↓
例题拆解
  ↓
易错对比
  ↓
3-5 道即时练习
  ↓
加入复测或生成纸面练习
```

## 2. 竞品调研结论

### 2.1 Khan Academy：技能掌握与练习闭环

Khan Academy 的核心不是只给视频链接，而是把学习单元拆成技能、练习和掌握进度。孩子看完讲解后，可以直接做对应练习，系统根据练习结果推进掌握状态。

参考：[Khan Academy Course and Unit Mastery](https://support.khanacademy.org/hc/en-us/articles/115002552631-What-are-Course-and-Unit-Mastery)

对本项目的启示：

- 学习材料要绑定具体技能或知识点。
- 讲解后必须接练习，不应只停留在“去看链接”。
- 状态应该从“看过”升级为“练过、通过、待复测”。

### 2.2 IXL：诊断结果直接映射到推荐技能

IXL 的 Real-Time Diagnostic 会输出学生当前能力水平，并推荐下一步技能练习。它的重点是“诊断后马上进入可操作任务”，不是让家长自己搜索资料。

参考：[IXL Real-Time Diagnostic](https://www.ixl.com/diagnostic)

对本项目的启示：

- 学习卡点页应该有明确下一步：“学一下”“练一下”“验证一下”。
- 资源要按卡点自动匹配，不让家长从很多链接里重新做判断。
- 首页或卡点中心应展示优先级，而不是资源库列表。

### 2.3 ALEKS：知识检查驱动补救学习

ALEKS 通过 Knowledge Checks 确认学生掌握情况，然后把未掌握内容安排回学习路径。它的价值在于把“判断是否掌握”放在系统闭环里。

参考：[ALEKS Knowledge Checks Overview](https://www.aleks.com/resources/ALEKS_Knowledge_Checks_Overview_for_Students.pdf)

对本项目的启示：

- 学习材料不能独立存在，要能进入复测排程。
- 只完成学习任务不代表掌握，必须有验证证据。
- “不确定”不能算通过，应回到待验证。

### 2.4 DreamBox / MATHia / Zearn：把讲解、操作和练习嵌入同一体验

DreamBox、Carnegie Learning MATHia 和 Zearn 的共同点是：孩子不是先看到一个诊断报告，再跳出去找学习材料，而是在同一学习体验里完成讲解、操作、反馈和练习。

参考：

- [DreamBox Math Work](https://dreamboxlearning.zendesk.com/hc/en-us/articles/27281843188243-How-Does-DreamBox-Math-Work)
- [Carnegie Learning MATHia AI](https://www.carnegielearning.com/blog/mathia-ai)
- [Zearn Math Works](https://about.zearn.org/how-zearn-math-works)

对本项目的启示：

- 对孩子来说，最好的入口不是“资源链接”，而是“一件今天要完成的小任务”。
- 每个任务要有明确结束条件。
- 操作反馈要轻，不要让孩子和家长在多个页面之间来回跳。

### 2.5 ASSISTments：按技能生成练习集合

ASSISTments 的 Skillbuilders 强调围绕某个技能持续练习，直到达到要求。它更接近“老师布置一个专项练习任务”。

参考：[ASSISTments Skillbuilders](https://www.assistments.org/individual-resource/skillbuilders)

对本项目的启示：

- 学习任务包可以先小，不必一上来做完整课程。
- 每个任务包只服务一个卡点或一组强相关卡点。
- 系统要保留练习记录，后续可复盘。

### 2.6 国内产品：拍照讲题强，卡点修复链路相对弱

作业帮、小猿等产品在拍照搜题、题目讲解、AI 讲题方面入口很强，适合解决“这道题怎么做”。洋葱学园更偏体系化动画微课，适合重新学概念。

参考：

- [作业帮 App Store](https://apps.apple.com/cy/app/id803781859)
- [小猿 AI App Store](https://apps.apple.com/us/app/id1325419855)
- [洋葱学园 App Store](https://apps.apple.com/cn/app/id990959871)

对本项目的启示：

- 拍照讲题容易停在“这道题会了”，不等于根因修复。
- 微课平台内容强，但与钟青羽的真实错题证据没有自动绑定。
- 我们的差异点应是“个人错题证据 → 学习卡点 → 任务包 → 复测”，而不是做一个通用内容平台。

## 3. 设计判断

### 3.1 不建议继续只做链接

只做链接会让产品停在资源推荐层：

```text
发现卡点
  ↓
给几个链接
  ↓
家长自己判断、孩子自己看
  ↓
系统无法知道是否学会
```

这不符合本项目“证据链”和“闭环验证”的方向。

### 3.2 建议做“学习卡点任务包”

每个卡点背后生成一个可打开、可完成、可记录的小任务包：

```text
卡点解释
  ↓
1 分钟微讲解
  ↓
例题拆解
  ↓
常见错误对比
  ↓
3-5 道即时练习
  ↓
加入验证排程
```

第一版不需要做视频播放器，也不需要接入外部课程。先用结构化文本、步骤、例题和少量练习完成 MVP。

### 3.3 外部链接降级为“家长参考资料”

外部链接仍然有价值，但不应该是孩子的主入口。建议定位为：

- 家长备课；
- AI 生成任务包时的参考来源；
- 当孩子需要换一种讲法时的补充材料；
- 不直接给孩子自由浏览。

## 4. 任务包内容结构

一个学习卡点任务包建议包含以下模块：

| 模块 | 面向对象 | 作用 |
| --- | --- | --- |
| 卡点一句话 | 家长和孩子 | 说明今天要补什么 |
| 为什么会错 | 家长和孩子 | 把错因说软，不贴负面标签 |
| 先看这个 | 孩子 | 1 分钟内的概念微讲解 |
| 例题拆解 | 孩子 | 展示一步一步怎么想 |
| 常见错误对比 | 孩子 | 看见错误路径和正确路径的差别 |
| 马上练 3 题 | 孩子 | 检查刚学完是否能做 |
| 纸面练习 | 家长 | 需要演算时生成打印页 |
| 下一次复测 | 系统 | 加入验证任务包或间隔复测 |

示例：小数乘法小数点定位

```text
卡点一句话：
小数乘法里，数字乘对了，但小数点位置不稳定。

为什么会错：
孩子可能把它当成整数乘法来算，算完以后没有用“小数位数”和“估算范围”检查答案。

先看这个：
先把 2.4 × 1.5 当成 24 × 15 = 360。
两个因数一共有 2 位小数，所以结果要变成 3.60，也就是 3.6。
再用估算检查：2.4 接近 2，1.5 接近 1.5，结果应该在 3 左右，不可能是 36 或 0.36。

例题：
0.24 × 1.5
第一步：24 × 15 = 360
第二步：0.24 有 2 位小数，1.5 有 1 位小数，一共 3 位
第三步：360 变成 0.360，也就是 0.36
第四步：估算 0.24 × 1.5 大约是 0.36，合理

常见错误：
把答案写成 3.6，说明小数位数少数了一位。

马上练：
1. 2.4 × 1.5 =
2. 0.24 × 1.5 =
3. 24 × 0.15 =
```

## 5. 小程序页面建议

### 5.1 学习卡点中心

卡点卡片增加三个动作：

| 动作 | 文案 | 说明 |
| --- | --- | --- |
| 主动作 | 学一下 | 打开学习任务包 |
| 次动作 | 做练习 | 进入 3-5 题即时练习 |
| 次动作 | 加入验证 | 放入下一次验证任务包 |

### 5.2 学习卡点详情页

详情页从“证据链 + 生成验证卷”升级为：

```text
卡点概览
  ↓
最近证据
  ↓
学习任务包
  ↓
练习与验证
  ↓
完整证据链
```

证据链仍然重要，但不应该把“学什么”挤到最后。

### 5.3 新增学习任务包页

建议新增页面：

```text
pages/learning-resource/learning-resource
```

页面结构：

1. 顶部：卡点名称、所属知识点、建议用时。
2. 概念：短文本微讲解。
3. 例题：分步骤展示。
4. 易错对比：错误答案与正确答案并排。
5. 练习：3-5 道小题。
6. 底部动作：完成学习、生成纸面练习、加入复测。

### 5.4 学习记录

学习任务包完成后，学习记录中新增事件：

```text
完成学习任务包：小数乘法中积的小数位数判断错误
练习 3/5 正确
已加入 3 天后复测
```

## 6. 数据模型建议

### 6.1 `learningResourcePacks`

```js
{
  _id,
  _openid,
  studentId,
  subject: 'math',
  sourceType: 'bottleneck',
  sourceReportId,
  lpCode,
  bottleneckId,
  knowledgeNodeIds: [],
  title,
  status: 'draft' | 'ready' | 'completed' | 'archived',
  estimatedMinutes: 8,
  version: 1,
  blocks: [
    { type: 'summary', title, body },
    { type: 'concept', title, body },
    { type: 'worked_example', question, steps: [] },
    { type: 'common_mistake', mistake, correction, explanation },
    { type: 'practice', questions: [] }
  ],
  externalResources: [
    { resourceId, title, platform, url, role }
  ],
  createdAt,
  updatedAt
}
```

### 6.2 `learningResourceAttempts`

```js
{
  _id,
  _openid,
  studentId,
  resourcePackId,
  subject: 'math',
  lpCode,
  bottleneckId,
  answers: [],
  correctCount,
  totalCount,
  result: 'passed' | 'needs_review' | 'incomplete',
  nextReviewAt,
  createdAt
}
```

第一版也可以先不新增 `learningResourceAttempts` 集合，把练习结果轻量写入 `learningResourcePacks.progress`。但如果要做长期追踪，独立集合更清晰。

## 7. MVP 范围

第一版只做数学。

必须做：

1. 从学习卡点详情页进入任务包。
2. 自动生成一个结构化任务包。
3. 小程序内展示微讲解、例题、易错对比和练习题。
4. 支持“完成学习”写入学习记录。
5. 支持“加入验证”或跳转生成验证卷。

暂不做：

- 不做视频播放；
- 不接入外部课程 API；
- 不做复杂练习批改；
- 不让孩子自由浏览外部资源；
- 不要求每个知识点都有完美资源。

---

## 8. 验收标准

1. 家长从任意数学学习卡点能打开“学一下”。
2. 孩子不离开小程序就能看到学习材料。
3. 任务包内容和当前卡点名称、知识节点一致。
4. 练习题数量不超过 5 道，适合 5-10 分钟完成。
5. 完成后学习记录出现对应事件。
6. 任务包可以把卡点加入下一次验证。
7. 外部链接只作为“家长参考”，不是主入口。

---

## 9. 结论

本项目不应该演化成通用资源导航工具。真正有价值的方向是：

```text
真实错题证据
  ↓
定位学习卡点
  ↓
生成小程序内学习任务包
  ↓
孩子完成短学习和短练习
  ↓
纸面验证或间隔复测
  ↓
更新学习档案
```

这比“推荐几个链接”更接近项目最初的目标：把学习问题像软件缺陷一样定位、修复、验证和持续追踪。
