## 1. 实现目标

英语 v2 的目标不是复用数学的“拍照整卷诊断”链路，而是围绕钟青羽个人 PEP 词库建立一个独立的单词掌握闭环。

核心闭环：

```text
个人 PEP 词库
↓
单词熟悉度：听/看提示后口头回答
↓
纸面听写：听提示后在纸上写英文单词
↓
AI / OCR 判定 correct / incorrect / unclear
↓
分别更新 familiarity 与 spelling 两个维度
↓
错词强化与 1天 / 3天 / 7天复测
↓
两维都稳定后，派生为真正掌握
```

技术实现上要做到：

- 英语单词数据不污染数学 `reports`、`papers`、`subjectProfiles.currentBottlenecks` 的诊断模型。
- 旧版单维 `masteryStatus` 数据可以继续读取，不丢失历史练习记录。
- 新版业务逻辑以双维 `familiarity` 和 `spelling` 为准。
- 口头熟悉度与纸面听写是两个独立功能，单次会话只做一种任务。
- 学习记录可以展示英语练习证据链，包括熟悉度会话、听写会话、听写照片和判定结果。


## 3. 目标架构

### 3.1 英语链路独立于数学链路

数学链路继续使用：

```text
photos → reports → bottlenecks → papers → verification report
```

英语单词链路使用：

```text
studentEnglishWords → englishPracticeSessions → learning timeline
```

第一版不把英语听写结果写成 `reports`，原因：

- `reports` 当前语义是“试卷/照片诊断报告”，包含错题、学习卡点、报告质量、验证证据等数学强相关字段。
- 英语听写的核心对象是“单词”，不是“学习卡点”。
- 写入 `englishPracticeSessions` 可以更轻、更高频，也更适合后续统计掌握度。

### 3.2 前端页面职责

| 页面 | v2 职责 |
| --- | --- |
| `subject-home` | 英语工作台，展示词库摘要、双任务入口、薄弱词和最近记录 |
| `english-practice` | 单词熟悉度，逐题语音交互，更新 `familiarity` |
| `english-dictation` | 纸面听写，逐词播放提示，完成后拍照上传，更新 `spelling` |
| `upload-history` | 学习记录，展示英语会话、听写照片和判定摘要 |

`english-dictation` 建议新增页面，不建议继续把所有逻辑塞入 `english-practice`。两个功能的操作方式不同：一个是“说”，一个是“写 + 拍照”，拆开后更清楚，也更容易测试。

### 3.3 云函数职责

`englishVocabulary` 继续作为英语主云函数，不新增独立云函数，原因：

- 词库、选词、练习会话、判定和状态更新都围绕同一组集合。
- 权限逻辑可以复用当前 `authorize(studentId, write)`。
- 第一版业务复杂度可控，不需要拆函数。

## 4. 数据结构

### 4.1 `studentEnglishWords`

每条单词文档代表钟青羽个人词库里的一个词。

目标字段：

```js
{
  _id: 'word_xxx',
  _openid: 'owner_openid',
  studentId: 'student_xxx',
  status: 'active',

  word: 'wednesday',
  meanings: ['星期三'],
  cnSynonyms: ['周三'],
  partOfSpeech: '',
  phonetic: '',
  grade: 5,
  volume: '上册',
  unit: 'Unit 2',
  sources: [],

  familiarity: {
    status: 'untested',
    correctCount: 0,
    wrongCount: 0,
    lastTestedAt: '',
    nextReviewAt: '',
    lastDirection: ''
  },

  spelling: {
    status: 'untested',
    correctCount: 0,
    wrongCount: 0,
    lastTestedAt: '',
    nextReviewAt: ''
  },

  overallMastery: 'untested',

  // 兼容字段，迁移期保留。
  masteryStatus: 'untested',
  correctCount: 0,
  wrongCount: 0,
  lastReviewedAt: '',
  nextReviewAt: '',

  createdAt: Date,
  updatedAt: Date
}
```

### 4.2 双维状态对象

`familiarity` 与 `spelling` 使用同一套结构：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `status` | String | `untested`、`needs_practice`、`reviewing`、`mastered` |
| `correctCount` | Number | reviewing 轨道上的连续正确次数 |
| `wrongCount` | Number | 该维度明确错误次数 |
| `lastTestedAt` | String | 最近一次有效测试日期，格式 `YYYY-MM-DD` |
| `nextReviewAt` | String | 下次复测日期，格式 `YYYY-MM-DD` |
| `lastDirection` | String | 仅 `familiarity` 使用，记录 `cn2en` 或 `en2cn` |

### 4.3 `overallMastery`

`overallMastery` 是派生字段，不应由页面随意写入。

派生规则：

| familiarity | spelling | overallMastery |
| --- | --- | --- |
| `mastered` | `mastered` | `mastered` |
| 两维均 `untested` | 两维均 `untested` | `untested` |
| 其他任意组合 | 其他任意组合 | `partial` |

### 4.4 旧字段兼容

迁移期保留旧字段：

- `masteryStatus`
- `correctCount`
- `wrongCount`
- `lastReviewedAt`
- `nextReviewAt`

兼容读取规则：

1. 如果文档已有 `familiarity` 和 `spelling`，直接使用双维字段。
2. 如果没有双维字段，但有 `masteryStatus`，初始化：
   - `familiarity.status = masteryStatus`
   - `spelling.status = 'untested'`
   - `familiarity.correctCount = correctCount`
   - `familiarity.wrongCount = wrongCount`
   - `familiarity.nextReviewAt = nextReviewAt`
3. 不删除旧字段，避免线上旧页面或历史测试断裂。
4. 新逻辑更新双维字段后，同步回写一个兼容版 `masteryStatus`，值取 `overallMastery` 或当前维度摘要，供旧 UI 降级展示。

## 5. 状态机

两个维度各自独立运行同一套状态机。

### 5.1 状态定义

| 状态 | 含义 |
| --- | --- |
| `untested` | 该维度没有有效记录 |
| `needs_practice` | 该维度明确出错，需要强化 |
| `reviewing` | 该维度已答对，进入间隔复测 |
| `mastered` | 该维度完成连续复测，暂时视为掌握 |

### 5.2 转移规则

```text
untested
  correct   → reviewing, correctCount=1, nextReviewAt=今+1天
  incorrect → needs_practice, wrongCount+1, nextReviewAt=今+1天
  unclear   → untested，不改状态

needs_practice
  correct   → reviewing, correctCount=1, nextReviewAt=今+1天
  incorrect → needs_practice, wrongCount+1, nextReviewAt=今+1天
  unclear   → needs_practice，不改状态

reviewing
  correct 且 correctCount=1 → reviewing, correctCount=2, nextReviewAt=今+3天
  correct 且 correctCount=2 → reviewing, correctCount=3, nextReviewAt=今+7天
  correct 且 correctCount>=3 → mastered, nextReviewAt=''
  incorrect → needs_practice, correctCount=0, wrongCount+1, nextReviewAt=今+1天
  unclear   → reviewing，不改状态

mastered
  correct   → mastered，不必改变
  incorrect → needs_practice, correctCount=0, wrongCount+1, nextReviewAt=今+1天
  unclear   → mastered，不改状态
```

### 5.3 判定三态

| 判定 | 含义 | 是否更新状态 |
| --- | --- | --- |
| `correct` | 明确答对或写对 | 更新 |
| `incorrect` | 明确答错或写错 | 更新 |
| `unclear` | 语音/OCR 不清楚、空白、无法确认 | 不更新 |

`unclear` 不能记为错，否则会把语音识别失败或拍照不清误伤成孩子能力问题。

## 6. 抽词算法

### 6.1 输入

```js
{
  words,
  dimension: 'familiarity' | 'spelling',
  today: '2026-06-16',
  limit: 20
}
```

### 6.2 优先级

本次测试维度记为 X，另一维度记为 Y。

| 优先级 | X 状态 | Y 状态 | 说明 |
| --- | --- | --- | --- |
| P0 | `needs_practice` | `needs_practice` | 双维薄弱，最高优先 |
| P1 | `needs_practice` | 任意 | 当前维薄弱 |
| P2 | `reviewing` 且 `nextReviewAt <= today` | 任意 | 到期复测 |
| P3 | `untested` | `reviewing` 或 `mastered` | 另一维有进展，当前维补盲区 |
| P4 | `untested` | `untested` 或 `needs_practice` | 新词 |
| P5 | `reviewing` 未到期 | 任意 | 推进中 |
| P6 | `mastered` | 任意 | 默认不选 |

同优先级排序：

1. 当前维 `wrongCount` 高的优先；
2. `nextReviewAt` 更早的优先；
3. 单词字母序稳定排序。

### 6.3 session 生成

每次默认生成 20 个词。

熟悉度 session：

- `functionType = 'familiarity'`
- `type = 'word-familiarity'`
- `direction = 'mixed'`
- `promptType` 在中文提示和英文提示之间轮换
- `direction` 在 `cn2en` 和 `en2cn` 之间轮换

纸面听写 session：

- `functionType = 'spelling'`
- `type = 'paper-dictation'`
- `direction = 'mixed'`
- `promptType` 可在中文提示和英文发音之间轮换
- 只要求孩子写英文单词

## 8. AI 与 OCR 判定

### 8.1 口头熟悉度判定

`cn2en`：

- 提示：中文释义。
- 孩子回答：英文单词。
- 判定：归一化英文后与目标词比较。

`en2cn`：

- 提示：英文发音。
- 孩子回答：中文含义。
- 判定：识别文本命中 `meanings` 或 `cnSynonyms`。

英文归一化：

```text
小写化 → 去除空格与标点 → 只保留 a-z
```

中文归一化：

```text
去空格 → 去常见标点 → 与 meanings / cnSynonyms 做包含或等值匹配
```

### 8.2 纸面听写 OCR

纸面听写不是开放 OCR，而是候选词约束匹配。

AI prompt 必须包含：

- 本次 session 的 20 个 `wordItems`；
- 每个候选词的 `wordId`、`order`、`word`、`meanings`；
- 明确要求输出逐词 JSON；
- 明确不能编造不在纸面或候选词里的内容；
- 明确空白、模糊、无法对应时输出 `unclear`。

输出 JSON：

```json
{
  "items": [
    {
      "order": 0,
      "wordId": "word_xxx",
      "targetWord": "wednesday",
      "recognizedText": "wensday",
      "verdict": "incorrect",
      "reason": "少写 e",
      "confidence": 0.86
    }
  ]
}
```

服务端收到 AI 结果后还要二次清洗：

- `verdict` 只允许 `correct / incorrect / unclear`。
- `wordId` 必须属于本次 session。
- 缺失项补为 `unclear`。
- 多余项丢弃。
- 同一个 `wordId` 多次出现时取置信度最高的一条。

## 9. 前端流程

### 9.1 英语工作台

英语工作台首屏结构：

```text
英语工作台
├─ 今日建议
│  ├─ 建议先做：单词熟悉度 / 纸面听写
│  └─ 说明：基于薄弱词、待复测词和未测维度
├─ 主操作
│  ├─ 单词熟悉度
│  └─ 纸面听写
├─ 词库统计
│  ├─ 总词数
│  ├─ 已熟悉
│  ├─ 拼写薄弱
│  ├─ 今日复测
│  └─ 真正掌握
├─ 高频问题
│  ├─ 不熟词
│  └─ 拼写错词
└─ 学习记录入口
```

不显示：

- 拍照诊断；
- 默认试卷；
- 学习卡点；
- 数学式验证试卷。

### 9.2 单词熟悉度页

页面：`english-practice`。

流程：

1. onLoad 调用 `generateRecognitionSession`。
2. 展示当前第 N / 20 个词。
3. 播放中文或英文提示。
4. 孩子按住或点击录音。
5. WechatSI 返回识别文本。
6. 调用 `submitRecognitionAttempt`。
7. 展示 AI 判定与正确答案。
8. `incorrect` 或 `unclear` 可加入本轮末尾重测。
9. 完成后返回英语工作台或进入学习记录。

### 9.3 纸面听写页

页面：`english-dictation`。

流程：

1. onLoad 调用 `generatePaperDictationSession`。
2. 页面提示准备纸笔，并说明“一行一个词，按顺序写”。
3. 系统逐题播放中文释义或英文发音。
4. 孩子写完后点“下一个”；语音“好了/下一个”可作为后续增强，不作为 MVP 必需。
5. 20 个词完成后，进入拍照上传。
6. 上传照片到云存储。
7. 调用 `submitDictationPhoto`。
8. 展示听写结果摘要：正确、错误、无法确认。
9. 错词与 unclear 进入后续复测。

### 9.4 学习记录

学习记录需要接入 `englishPracticeSessions`。

事件类型：

| 类型 | 展示标题 | 来源 |
| --- | --- | --- |
| `english-familiarity-session` | 英语单词熟悉度 | `englishPracticeSessions.functionType=familiarity` |
| `english-dictation-session` | 英语纸面听写 | `englishPracticeSessions.functionType=spelling` |
| `english-dictation-photo` | 听写纸照片 | `englishPracticeSessions.photoFileIds` |
| `english-weak-word-update` | 错词复测变化 | session summary 派生 |

第一版可以只展示 session 级主记录，不必拆出每个单词为时间线事件。

## 10. 兼容与迁移

### 10.1 迁移原则

- 不删除历史字段。
- 不迁移真实数据到不可逆结构。
- 读取时兼容旧数据，写入时逐步补双维字段。
- 任何缺字段单词都应可继续参与选词。

### 10.2 懒迁移策略

不做一次性数据库迁移脚本，优先采用懒迁移：

1. `getVocabularySummary` 读取词库时调用 `normalizeWordProgress(word)`。
2. 发现缺少 `familiarity/spelling` 时，按旧字段生成内存态双维对象。
3. 在下一次该词被练习并更新时，将双维字段写回数据库。

### 10.3 种子导入更新

`normalizeImportCandidates` 新增默认双维字段：

```js
familiarity: {
  status: 'untested',
  correctCount: 0,
  wrongCount: 0,
  lastTestedAt: '',
  nextReviewAt: '',
  lastDirection: ''
},
spelling: {
  status: 'untested',
  correctCount: 0,
  wrongCount: 0,
  lastTestedAt: '',
  nextReviewAt: ''
},
overallMastery: 'untested'
```

## 12. 测试计划

### 12.1 单元测试

- 双维初始化：旧字段生成双维对象。

- 口头中文判定：释义、同义词、空识别。

## 13. 验收标准

### 13.1 功能验收

- 英语工作台可以清楚区分“单词熟悉度”和“纸面听写”。
- 每次熟悉度默认 20 词。
- 每次纸面听写默认 20 词。
- 熟悉度只更新 `familiarity`。
- 纸面听写只更新 `spelling`。
- `unclear` 不计对错。
- 两维都 mastered 后，`overallMastery` 才是 mastered。
- 学习记录能看到英语练习证据。

### 13.2 数据验收

- 505 个历史词可以继续使用。
- 旧 `masteryStatus` 数据不会丢失。
- 新 session 不写入数学 `reports`。
- 非成员不能读取或写入英语词库与练习记录。

### 13.3 质量验收

- 自动化测试通过。
- 真机语音链路可完成。
- 真实纸面听写照片能完成候选词约束 OCR。
- OCR 不确定时进入 `unclear`，不误判为孩子写错。

## 14. 后续可扩展方向

当前 v2 只做单词。后续可以在不破坏当前结构的前提下扩展：

- 更细的错误类型：漏字母、字母顺序、大小写、音近混淆。
- 错词本：按错误次数、复测到期、单元聚合。
- 打印版听写纸：自动生成带序号的 A4 听写纸。
- 家长复核：OCR 判定不确定时允许家长手动修正。
- 语音质量评分：发音是否接近目标词。
- 句型和时态：另建 `studentEnglishPatterns` 的练习链路，不混入当前单词闭环。

## 15. 给后续 AI / 工程师的实现提醒

1. 不要把英语纸面听写做成数学 `upload → report → bottleneck` 链路。
2. 不要把“熟悉度答对”直接当作“单词已掌握”。
3. 不要把 `unclear` 算作错误。
4. 不要在一个 session 里混合“说”和“写”。
5. 不要开放式 OCR 猜孩子写了什么，必须带本次候选词约束。
6. 不要删除旧 `masteryStatus` 字段。
7. 不要让英语工作台继续出现数学式“学习卡点”和“默认试卷”入口。
8. 优先让真实学习闭环跑通，再考虑复杂的发音评分和语法扩展。
