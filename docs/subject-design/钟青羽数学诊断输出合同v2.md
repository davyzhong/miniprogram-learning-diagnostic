# 钟青羽数学诊断输出合同 v2

> 版本：v2.1（2026-07-17）——与实时管线实现对齐：nodeIds 经 `canonicalizeNodeId` 归一化（新增 `unmatchedNodeIds` 字段）、掌握状态从五态迁移为六态（§3 已重写，权威实现见 `docs/superpowers/specs/2026-07-17-math-node-mastery-loop-design.md`）。

本文档定义数学诊断升级后的输出形态。它不是立刻替换现有报告，而是在现有 `reports.bottlenecks`、`subjectProfiles.currentBottlenecks` 和验证试卷链路上增加“知识节点 + 细颗粒度卡点 + 资源重学 + 掌握状态”的证据层。

## 1. 输出原则

- AI 初次诊断只给候选结论，不直接把粗略错误定性为最终卡点。
- 每个候选卡点必须能映射到至少一个知识节点。
- 先推荐重学资源和微验证，再决定是否进入整套验证卷。
- 资源只展示给家长筛选，孩子端不直接进入平台信息流。
- 资源排序采用“高质量锚点 + 国内补充”：Khan Academy、YouTube 若讲法高置信，可作为优先参考；同一知识点尽量补充 B站、小红书等国内资源，方便孩子实际观看和中文复述。
- 旧字段保留兼容，新字段逐步驱动报告页和学科首页。

## 2. 报告字段扩展

现有 `reports` 文档可继续保留：

```js
{
  subject: 'math',
  bottlenecks: [
    {
      lpCode: 'LP-001',
      displayName: '计算准确性',
      evidenceText: '小数乘法小数点定位错误'
    }
  ]
}
```

升级后在每个 `bottleneck` 项下增加：

```js
{
  lpCode: 'LP-001',
  displayName: '小数乘法小数点定位不稳',
  nodeIds: ['MATH-NUM-DEC-MUL-POINT'],
  candidateBottlenecks: [
    {
      bottleneckId: 'BN-DEC-MUL-POINT-COUNT',
      title: '小数乘法中小数位数累计规则不稳',
      evidenceStrength: 'medium',
      evidenceItems: [
        {
          sourceType: 'photoAnalysis',
          questionRef: '第 3 题',
          observation: '8.5×3.16 竖式过程正确，但答案小数点定位错误'
        }
      ],
      microValidationRequired: true,
      suggestedMicroValidation: [
        '8.5×3.16',
        '0.85×3.16',
        '8.5×0.316'
      ],
      repairFirst: true,
      recommendedResourceIds: [
        'RES-BILI-DEC-MUL-001',
        'RES-KHAN-DEC-MUL-001'
      ]
    }
  ],
  evidenceStrength: 'medium',
  nextActionType: 'resourceReview',
  nextActionText: '先用小数乘法资源重学小数点定位，再做 3 道微验证题。',
  unmatchedNodeIds: []
}
```

**nodeIds 归一化规则（2026-07-17 起生效）**：AI 返回的每个 nodeId 经 `canonicalizeNodeId` 处理——标准目录命中、变体别名、ID 前缀互含、标题子串匹配四层归并；均不命中的原始值从 `nodeIds` 移除并记录到 `unmatchedNodeIds`（最多 6 条，仅在有丢弃时出现），供后续节点扩充回溯。因此入库报告的 `nodeIds` 保证 100% 命中标准知识节点目录。

## 3. 知识节点掌握状态

`studentNodeMastery` 集合（已实现，每文档 = 一个 studentId + subject + nodeId）：

```js
{
  studentId: 'student-zhong-qingyu',
  subject: 'math',
  nodeId: 'MATH-NUM-DEC-MUL-POINT',
  status: 'partial_mastery',
  confidence: 0.72,
  activeBottleneckIds: [
    'BN-DEC-MUL-POINT-COUNT',
    'BN-DEC-MUL-POINT-ESTIMATE'
  ],
  evidenceRefs: [
    {
      type: 'errorEvidence',
      sourceId: 'report-20260616-001',
      summary: '小数乘法小数点定位错误',
      at: '2026-06-16T20:30:00+08:00'
    }
  ],
  lastEvidenceAt: '2026-06-16T20:30:00+08:00',
  lastPracticedAt: '2026-06-18T19:00:00+08:00',
  nextReviewAt: '2026-06-19T19:00:00+08:00',
  updatedAt: '2026-06-18T19:00:00+08:00'
}
```

状态枚举（六态，v2.1 起替代旧五态；`unobserved` 为默认态不落库）：

| 状态 | 含义 | 下一步 |
| --- | --- | --- |
| `unobserved` | 未观察，无任何证据 | 等待错题或微验证 |
| `suspected_gap` | 疑似漏洞：错题指向，未确认 | 微验证或资源重学 |
| `relearning` | 正在重学：验证失败确认卡点 | 资源学习 + 当场练习 |
| `partial_mastery` | 部分掌握：当场练习通过 | 24/72h 间隔复测 |
| `mastered` | 已掌握：间隔复测通过 | 日常观察，复发回退 |
| `recurring` | 复发：掌握后同类错误再现 | 重新干预 |

状态流转由四事件驱动（errorEvidence / verificationFailed / verificationPassed / resourcePracticePassed），完整转移表与守卫规则见 `docs/superpowers/specs/2026-07-17-math-node-mastery-loop-design.md`。

## 4. 微验证输出

微验证不是一张完整试卷，而是 3-6 道围绕同一知识节点的小题。它用于区分“偶发粗心”和“真实卡点”。

```js
{
  validationId: 'MV-20260616-001',
  nodeId: 'MATH-NUM-DEC-MUL-POINT',
  bottleneckId: 'BN-DEC-MUL-POINT-COUNT',
  questions: [
    {
      prompt: '8.5×3.16',
      expectedObservation: '是否能正确累计 3 位小数'
    },
    {
      prompt: '0.85×3.16',
      expectedObservation: '是否能迁移到 4 位小数'
    },
    {
      prompt: '先不计算，判断 8.5×3.16 的结果大约是多少',
      expectedObservation: '是否有数量级估算'
    }
  ],
  passRule: '至少 2 道计算正确，且能口头解释小数点定位原因'
}
```

## 5. 资源推荐输出

资源推荐只返回资源 ID 和家长提示，不复制平台内容：

```js
{
  nodeId: 'MATH-NUM-FRACTION-DIV-RECIPROCAL',
  bottleneckIds: [
    'BN-FRACTION-DIV-RECIPROCAL-MISSING'
  ],
  resourcePlan: [
    {
      resourceId: 'RES-BILI-FRACTION-DIV-001',
      recommendationLevel: 'A',
      parentPrompt: '看完后请孩子解释“6 里面有几个 7/8”。'
    },
    {
      resourceId: 'RES-KHAN-FRACTION-DIV-001',
      recommendationLevel: 'B',
      parentPrompt: '作为高质量锚点资源，家长先看它校准概念，再配合同知识点的国内资源给孩子复述。'
    }
  ]
}
```

资源推荐排序：

1. 若同一知识点存在 Khan Academy、YouTube 高置信讲法，先进入家长参考候选。
2. 同时查找 B站、小红书等国内补充资源，作为孩子实际观看或中文复述材料。
3. 报告页不要只给境外资源，也不要只给国内搜索入口；最好给出“锚点资源 + 国内补充”的组合。

## 6. 报告页展示建议

报告页从“粗卡点列表”升级为“证据链卡片”：

- 第一层：本次最可能影响成绩的 3 个知识节点。
- 第二层：每个节点下展示候选细卡点、证据强度和典型错题。
- 第三层：显示“先重学”或“可验证”的下一步。
- 第四层：家长可打开资源评价和干预记录，不让孩子直接刷平台推荐流。

## 7. 学科首页展示建议

数学首页长期由知识地图驱动：

- 顶部显示掌握状态分布：已掌握、部分掌握、正在重学、疑似漏洞、未观察、复发（六态）。
- 中部显示优先攻略节点，而不是只显示 LP 编号。
- 底部显示最近一次干预会话和下次复测日期。

## 8. 兼容策略

- `LP-001` 到 `LP-010` 不删除，作为旧报告和旧验证卷的兼容层。
- 新报告优先使用 `candidateBottlenecks[].bottleneckId` 和 `nodeIds`。
- 如果旧报告没有 `nodeIds`，可按 LP 编号和题目类型做弱映射，但标记 `evidenceStrength: 'low'`。
- 如果资源库没有对应资源，报告页应显示“待家长筛选资源”，不要自动给孩子开放平台搜索。
