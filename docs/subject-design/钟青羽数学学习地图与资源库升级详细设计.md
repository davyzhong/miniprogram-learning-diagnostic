# 钟青羽数学学习地图与资源库升级详细设计

> 目的：说明如何在现有数学诊断小程序基础上，升级出“知识地图 + 细颗粒度卡点 + 全网资源库 + 掌握状态追踪”的家庭自用学习闭环。
> 适用范围：微信小程序 `miniprogram-learning-diagnostic` 的数学链路，以及配套的本地知识库、资源库和后续数据模型设计。
> 当前阶段：设计说明，不直接修改代码实现。
> 上游计划：`26-数学学习地图与资源库升级计划.md`。

---

## 1. 目标与边界

### 1.1 目标

本升级的核心目标是给自家孩子建立一套可持续使用的数学学习操作系统：

```text
错题证据
  ↓
定位知识节点
  ↓
确认细颗粒度学习卡点
  ↓
选择合适资源重学
  ↓
孩子复述和少量练习
  ↓
间隔复测
  ↓
更新掌握状态
```

系统要帮助家长回答四个问题：

1. 这道错题背后的真正卡点是什么？
2. 这个卡点属于小学数学知识地图中的哪个节点？
3. 孩子应该先用什么资源重新学习？
4. 这个知识点后来是否真的掌握了？

### 1.2 非目标

本阶段不追求：

- 不优先商业化；
- 不优先对外分发资源；
- 不把竞品差异化作为核心目标；
- 不让孩子直接刷小红书、B站、YouTube 等平台信息流；
- 不把官方教材资源作为默认首选；
- 不推翻现有拍照诊断、报告和验证卷闭环。

### 1.3 与现有数学链路的关系

现有数学链路已经具备：

- 拍照上传试卷；
- AI 识别错题；
- 归类到学习卡点；
- 生成诊断报告；
- 生成验证试卷；
- 上传验证卷；
- 更新卡点状态。

本设计是在现有链路上增加三层：

1. **知识地图层**：所有卡点都要落到数学知识节点。
2. **资源重学层**：确认漏洞后，先让孩子重新学习，而不是直接出整套验证卷。
3. **掌握状态层**：长期追踪节点是否已掌握、部分掌握或复发。

## 2. 知识地图结构

### 2.1 四大领域

小学数学知识地图按四大领域组织：

1. 数与代数；
2. 图形与几何；
3. 统计与概率；
4. 综合与实践。

这四大领域来自小学数学课程内容框架，但本系统不机械复制教材目录。教材目录回答“学校怎么教”，知识地图回答“孩子的掌握状态如何演化”。

### 2.2 知识节点字段

建议新增 `knowledgeNodes` 结构。

```js
{
  nodeId: 'MATH-NUM-DEC-MUL-POINT',
  subject: 'math',
  title: '小数乘法中的小数点定位',
  domain: '数与代数',
  gradeRange: [5, 6],
  priority: 'high',
  prerequisites: [
    'MATH-NUM-INT-MUL-MULTIDIGIT',
    'MATH-NUM-DEC-PLACE-VALUE'
  ],
  successors: [
    'MATH-NUM-DEC-DIV',
    'MATH-MOD-PERCENT-DISCOUNT'
  ],
  typicalProblems: [
    '8.5 × 3.16',
    '0.24 × 1.5',
    '判断积的小数位数'
  ],
  commonBottlenecks: [
    'BN-DEC-MUL-POINT-COUNT',
    'BN-DEC-MUL-POINT-ESTIMATE'
  ],
  masteryCriteria: {
    immediatePractice: '3 道同类题全对，并能说出小数位数规则',
    transferPractice: '能在应用题和竖式题中稳定定位小数点',
    spacedReview: '24/72 小时间隔复测均通过'
  },
  textbookRefs: [],
  resourceIds: []
}
```

### 2.3 首批优先节点

首批优先覆盖六年级和小升初高频薄弱区：

- 整数、小数、分数四则运算；
- 分数、小数、百分数互化；
- 百分数应用中的单位 1；
- 比和比例；
- 单位换算和量纲统一；
- 平面图形周长面积；
- 圆、圆柱、圆锥；
- 统计图表读取；
- 方程建模；
- 应用题中的数量关系；
- 验算和答案合理性检查。

### 2.4 依赖关系原则

依赖关系只记录会影响诊断和修复的关键前置，不追求画出所有教材顺序。

例如：

```text
小数位值
  → 小数乘法
  → 小数乘法小数点定位
  → 百分数折扣应用
```

如果孩子在百分数折扣应用中出错，系统要能回溯到“小数乘法小数点定位”或“单位 1 判断”这样的前置节点，而不是只停在“百分数应用题错误”。

## 3. 细颗粒度卡点体系

### 3.1 从粗卡点升级为三级结构

现有 `LP-001` 到 `LP-010` 适合 MVP 展示，但不够诊断。新体系建议保留兼容层，并新增三级卡点：

```text
粗卡点：计算基础
  ↓
知识方向：小数乘法
  ↓
最小卡点：小数点定位规则不稳
```

### 3.2 卡点字段

建议新增 `bottleneckTaxonomyV2` 结构。

```js
{
  bottleneckId: 'BN-DEC-MUL-POINT-COUNT',
  legacyLpCode: 'LP-001',
  subject: 'math',
  title: '小数乘法中积的小数位数判断错误',
  nodeId: 'MATH-NUM-DEC-MUL-POINT',
  categoryPath: ['计算基础', '小数乘法', '小数点定位'],
  symptomPatterns: [
    '数字乘积正确，但小数点位置错误',
    '答案数量级明显不合理',
    '竖式中未统计两个因数的小数位数'
  ],
  rootCauseSignals: [
    '能完成整数乘法',
    '不能解释积为什么有几位小数',
    '不会用估算检查答案数量级'
  ],
  microValidationRules: [
    '给 3 道数字乘积相同但小数位数不同的题',
    '要求先估算数量级，再写精确答案',
    '要求孩子口头解释小数点移动依据'
  ],
  repairStrategy: [
    '先复习小数位值',
    '再用整数乘法结果回填小数点',
    '最后用估算判断结果是否合理'
  ],
  masteryEvidence: [
    '能说出两个因数共有几位小数',
    '能用估算发现 2.186 与 26.86 的数量级差异',
    '变式题连续正确'
  ]
}
```

### 3.3 最小可修复原则

一个卡点只有满足以下条件，才进入正式卡点库：

- 能通过卷面或口头解释观察；
- 能设计 2-3 道微验证题；
- 能对应一个主知识节点；
- 能安排一次 10-20 分钟重学；
- 能通过复测判断是否改善。

### 3.4 候选卡点与确认卡点

AI 初次诊断只能生成候选卡点，不能直接盖章确认。

```text
错题
  ↓
候选卡点 1/2/3
  ↓
微验证
  ↓
确认主卡点
```

报告中要明确区分：

- `suspected`：疑似卡点；
- `confirmed`：已通过微验证确认；
- `rejected`：验证后排除；
- `watching`：证据不足，继续观察。

## 4. 资源库设计

### 4.1 资源来源

资源库面向家庭自用，来源可以更开放。资源排序不简单等同于“国内优先”或“国外优先”，而是分成两层：

- **高质量锚点来源**：Khan Academy、YouTube 等资源，如果讲法清楚、结构严谨、置信度高，可以作为知识点理解的优先参考。
- **国内补充来源**：同一知识点尽量补充 B站、小红书、公众号等国内资源，方便国内网络环境下使用、中文复述和孩子定向观看。

可采集来源包括：

- B站；
- 小红书；
- YouTube；
- Khan Academy；
- 公众号文章；
- 老师讲义；
- 教学动图；
- 互动网页；
- 国家中小学智慧教育平台；
- 人教社等公开教材资源；
- AI 自制讲解、类比和例题。

### 4.1.1 高质量锚点 + 国内补充规则

资源库按以下规则建设：

1. 如果 Khan Academy、YouTube 上存在高质量讲法，优先保留为该知识点的“锚点资源”。
2. 同一个知识点必须尽量补充 B站、小红书等国内资源，解决访问、语言、孩子接受度和家长陪学便利性。
3. 国内资源不是为了替代高质量锚点，而是为了让孩子能在熟悉语境里再学一遍。
4. 当境外资源和国内资源都存在时，推荐流程可以是：家长先看锚点资源校准概念，再让孩子看国内资源，最后用孩子复述和变式题验证。
5. 如果国内资源讲得更贴近孩子，也可以作为默认观看资源；Khan/YouTube 继续作为家长备课和准确性校验。

### 4.2 资源保存原则

系统不搬运资源正文，不下载视频，不复制平台内容。只保存：

- 链接；
- 标题；
- 平台；
- 摘要；
- 适用知识点；
- 适用卡点；
- 家长评价；
- 孩子反馈；
- 是否推荐复用。

### 4.3 资源字段

建议新增 `learningResources` 结构。

```js
{
  resourceId: 'RES-BILI-DEC-MUL-001',
  subject: 'math',
  nodeId: 'MATH-NUM-DEC-MUL-POINT',
  bottleneckIds: ['BN-DEC-MUL-POINT-COUNT'],
  platform: 'B站',
  title: '小数乘法小数点到底怎么点',
  url: 'https://...',
  type: 'video',
  teachingStyle: ['图示讲解', '步骤拆解', '易错对比'],
  duration: '6:30',
  targetGradeRange: [5, 6],
  summary: '用整数乘法结果回填小数点，并用估算检查数量级。',
  strengths: [
    '讲法短',
    '有数量级估算',
    '能解释为什么不是机械数位数'
  ],
  risks: [
    '评论区和推荐流不适合孩子直接浏览'
  ],
  parentRating: 5,
  childFeedback: {
    watchedAt: null,
    understood: null,
    selfExplanation: ''
  },
  recommendationLevel: 'A',
  reviewStatus: 'parent_approved',
  notes: '适合作为默认重学资源。'
}
```

### 4.4 资源搜索模板

每个知识节点可生成多组搜索关键词。

示例：

| 节点 | 搜索关键词 |
| --- | --- |
| 小数乘法小数点定位 | `小数乘法 小数点 为什么错`、`小数乘法 小数点 动画 小学` |
| 百分数单位 1 | `百分数 单位1 怎么判断 小学`、`百分数应用题 基准量 判断` |
| 分数除法 | `分数除法 为什么乘倒数`、`除以分数 小学 动画` |
| 圆柱体积 | `圆柱体积 动画 小学生`、`圆柱体积 底面积乘高 为什么` |
| 比和比例 | `比和比例 部分整体 区分`、`比例应用题 参照系 小学` |

### 4.5 孩子端访问边界

孩子不直接打开平台刷信息流。推荐使用方式：

1. 家长或 AI 先筛选资源；
2. 资源进入知识点教材库；
3. 家长打开指定资源；
4. 孩子只看指定内容；
5. 看完后立刻复述和练习；
6. 家长记录反馈。

## 5. 资源评价规则

### 5.1 六维评分

每条资源按 6 个维度评价：

| 维度 | 评价问题 |
| --- | --- |
| 准确性 | 有没有数学错误、概念偷换或公式误导 |
| 针对性 | 是否正好解释当前卡点 |
| 讲法友好度 | 是否有图示、动画、反例、生活例子、步骤拆解 |
| 认知负荷 | 是否短、清楚、节奏适合孩子 |
| 迁移能力 | 看完后是否能做变式题 |
| 孩子反馈 | 孩子是否愿意看、能否复述、是否减少同类错题 |

### 5.2 推荐等级

| 等级 | 含义 | 进入流程 |
| --- | --- | --- |
| A | 强推荐 | 默认推荐给当前节点 |
| B | 可备用 | A 类资源不合适时使用 |
| C | 家长参考 | 只给家长理解，不直接给孩子 |
| D | 不推荐 | 排除，并记录原因 |

推荐等级评的是“当前家庭学习流程适用性”，不是平台质量。Khan Academy、YouTube 可以是高质量锚点，但如果语言或访问成本高，仍可能标为 B/C；B站、小红书更适合孩子直接观看，但仍要经过准确性筛选。

### 5.3 评价记录模板

```text
资源标题：
平台：
链接：
适用节点：
适用卡点：
推荐等级：
为什么推荐：
可能风险：
孩子看完能否复述：
看完后的 3 道变式题结果：
是否保留为默认资源：
```

## 6. 学习流程

### 6.1 新流程

```text
错题上传
  ↓
AI 识别题目、答案和过程
  ↓
映射知识节点
  ↓
生成候选细卡点
  ↓
微验证确认主卡点
  ↓
推荐资源重学
  ↓
孩子自我解释
  ↓
3 道变式练习
  ↓
24/72 小时间隔复测
  ↓
更新知识地图状态
```

### 6.2 与旧流程的差异

旧流程偏向：

```text
发现卡点 → 生成验证试卷 → 上传验证卷 → 判断改善
```

新流程改为：

```text
发现疑似卡点 → 微验证 → 先重学 → 少量练习 → 间隔复测
```

验证卷仍然保留，但不再是漏洞发现后的第一动作。对于明确的概念漏洞，优先给孩子一次换讲法重新学习的机会。

### 6.3 15-20 分钟家庭流程

每天最多处理一个卡点：

| 环节 | 时间 | 目标 |
| --- | --- | --- |
| 看错题和讲思路 | 3 分钟 | 让孩子暴露真实思路 |
| 微验证 | 3 分钟 | 确认是不是这个卡点 |
| 看资源或听讲解 | 5-8 分钟 | 换一种讲法重学 |
| 孩子复述 | 3 分钟 | 进入建构式学习 |
| 变式练习 | 5 分钟 | 观察能否迁移 |
| 记录 | 1 分钟 | 更新资源评价和节点状态 |

## 7. 数据模型与现有系统衔接

### 7.1 新增集合或本地数据表

建议新增或先用 JSON/Markdown 本地维护以下数据：

| 名称 | 用途 |
| --- | --- |
| `knowledgeNodes` | 小学数学知识地图 |
| `bottleneckTaxonomyV2` | 细颗粒度卡点库 |
| `learningResources` | 知识点教材库 |
| `studentNodeMastery` | 学生在知识节点上的掌握状态 |
| `interventionSessions` | 一次重学、练习、复测的完整记录 |

### 7.2 `studentNodeMastery`

```js
{
  studentId: 'student_xxx',
  subject: 'math',
  nodeId: 'MATH-NUM-DEC-MUL-POINT',
  status: 'partial',
  confidence: 0.72,
  evidenceRefs: [
    {
      type: 'report',
      id: 'report_xxx',
      note: '8.5 × 3.16 小数点位置错误'
    },
    {
      type: 'interventionSession',
      id: 'session_xxx',
      note: '看完资源后 3 道变式题对 2 道'
    }
  ],
  lastPracticedAt: '2026-06-16T20:00:00+08:00',
  nextReviewAt: '2026-06-19T20:00:00+08:00'
}
```

### 7.3 `interventionSessions`

```js
{
  sessionId: 'SESSION-20260616-001',
  studentId: 'student_xxx',
  subject: 'math',
  nodeId: 'MATH-NUM-DEC-MUL-POINT',
  bottleneckId: 'BN-DEC-MUL-POINT-COUNT',
  sourceErrorRefs: ['report_xxx:error_01'],
  microValidation: {
    result: 'confirmed',
    notes: '整数乘法正确，小数点位数解释不清'
  },
  resourcesUsed: ['RES-BILI-DEC-MUL-001'],
  childSelfExplanation: '两个因数一共有三位小数，所以积也要从右往左数三位。',
  practiceResults: [
    { question: '0.8 × 3.2', correct: true },
    { question: '1.25 × 0.4', correct: true },
    { question: '8.5 × 3.16', correct: true }
  ],
  outcome: 'partial',
  nextReviewAt: '2026-06-19T20:00:00+08:00'
}
```

### 7.4 兼容现有 `reports.bottlenecks`

现有报告字段保留：

- `lpCode`;
- `lpName`;
- `rootCause`;
- `suggestion`;
- `severity`;
- `errorCount`。

逐步新增：

- `nodeIds`：对应知识节点；
- `candidateBottlenecks`：候选细卡点；
- `confirmedBottleneckId`：微验证后确认的卡点；
- `evidenceStrength`：证据强度；
- `recommendedResourceIds`：推荐资源；
- `nextLearningAction`：下一步是微验证、重学、练习还是复测。

示例：

```js
{
  lpCode: 'LP-001',
  lpName: '计算基础',
  nodeIds: ['MATH-NUM-DEC-MUL-POINT'],
  candidateBottlenecks: [
    {
      bottleneckId: 'BN-DEC-MUL-POINT-COUNT',
      confidence: 0.82,
      evidence: '8.5 × 3.16 数字序列正确但小数点错位'
    }
  ],
  confirmedBottleneckId: '',
  evidenceStrength: 'medium',
  nextLearningAction: 'micro_validation'
}
```

### 7.5 `subjectProfiles.currentBottlenecks`

现有 `subjectProfiles.currentBottlenecks` 继续用于首页和学科主页展示待处理卡点。

长期升级方向：

```text
currentBottlenecks
  ↓
由 studentNodeMastery + interventionSessions 派生
```

也就是说，未来“下一步建议”不再只来自某个卡点出现次数，而来自：

- 节点重要性；
- 前置依赖程度；
- 近期错误频率；
- 是否即将复测；
- 是否已有好资源；
- 修复成本和收益。

## 8. 执行路线与验收

### Phase 1：落盘文档

交付物：

- `26-数学学习地图与资源库升级计划.md`
- `docs/subject-design/钟青羽数学学习地图与资源库升级详细设计.md`

验收：

- 两份文档存在；
- 明确自用优先；
- 明确全网资源评价优先；
- 不强调竞品差异化。

### Phase 2：建立 80-120 个细卡点

交付物：

- `bottleneckTaxonomyV2` 初版；
- 每个卡点有知识节点、症状、微验证、修复策略。

验收：

- 任意历史错题不再只能落到“计算错误”；
- 至少覆盖现有报告中的高频问题。

### Phase 3：建立 150-220 个知识节点

交付物：

- `knowledgeNodes` 初版；
- 覆盖小学数学主干；
- 标注前置依赖和掌握标准。

验收：

- 每个正式卡点能映射到至少一个节点；
- 六年级和小升初高频区覆盖完整。

### Phase 4：为前 50 个高频节点建立资源库

交付物：

- `learningResources` 初版；
- 每个高频节点至少 2 条审核资源。

验收：

- 每条资源有平台、链接、适用卡点、评价等级；
- A 类资源能直接进入家庭学习流程。

### Phase 5：改诊断输出和报告展示

交付物：

- AI 输出增加知识节点和候选细卡点；
- 报告页展示“症状、根因、节点、资源、下一步”。

验收：

- 家长能从一条错题看到对应知识节点；
- 报告能区分疑似卡点和确认卡点。

### Phase 6：试运行两周

交付物：

- 每天 1 个卡点的干预记录；
- 每周掌握状态复盘；
- 资源有效性评分。

验收：

- 至少 10 个干预会话；
- 至少 5 个节点从疑似漏洞或部分掌握推进到已掌握；
- 至少识别 3 条 A 类高复用资源。

## 9. 后续实现建议

建议下一步先不要直接改 UI，而是按以下顺序推进：

1. 用 Markdown 或 JSON 建立 `knowledgeNodes` 和 `bottleneckTaxonomyV2` 初版；
2. 选取现有钟青羽数学报告中的 20 道高价值错题做回放标注；
3. 验证细卡点和知识节点是否足够区分真实问题；
4. 再建立前 20 个节点的资源库；
5. 最后改 AI prompt 和报告结构。

这样可以避免一上来做页面和数据库，结果发现知识地图颗粒度不对。数学学习系统的核心不是界面，而是诊断颗粒度、资源质量和掌握状态是否可信。
