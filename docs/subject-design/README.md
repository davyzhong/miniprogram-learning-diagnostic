阅读建议：

1. 先读数学基础文档，理解整个 MVP 的“证据链 + 学习卡点 + 验证闭环”。
2. 再读数学升级详细设计，理解为什么数学要从粗 LP 卡点升级为“知识节点 + 细卡点 + 资源重学 + 掌握状态”。
3. 再读学习卡点学习材料任务包文档，理解为什么不能只给外部链接，而要把资源转化为“学一下 + 练一下 + 复测”的小程序内任务。
4. 再读数学卡点层级升级文档，理解粗类、卡点家族、细卡点和知识节点各自承担什么系统职责。
5. 真正改数学 Prompt、报告页或数据层时，按数学诊断输出合同 v2 落字段，旧 LP 字段保留兼容。
6. 如果要把历史图片重新跑一遍，按数学历史报告全量重分析执行说明先 dry-run，再 start/finalize。
7. 再读语文设计文档，理解为什么语文要以“具体错项清单”为主，而不是只归入粗学习卡点。
8. 再读英语正式文档，理解为什么英语不复用数学整卷诊断，而是围绕个人词库做“熟悉度 + 纸面听写”。
9. 需要理解英语 v2 规则时，再读英语双功能闭环规格，重点看双维状态机、单次会话单功能、P3 补盲区联动抽词和候选词约束 OCR。
10. 需要真正改英语代码时，再读英语技术实现文档，按数据模型、云函数 API、页面职责、迁移策略和测试计划落地。
11. 英语板块的产品与技术背景另见根目录 `24-英语学习APP竞品调研与板块设计启示.md`、`25-英语板块口语听力技术可行性与决策分析.md`。
12. 需要查看系统实现时，再读 `../ARCHITECTURE.md`、`../DATA_DICTIONARY.md` 和 `../CLOUD_FUNCTIONS.md`。
