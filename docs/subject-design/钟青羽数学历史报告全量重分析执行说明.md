# 钟青羽数学历史报告全量重分析执行说明

## 目标

把历史数学报告中的原始图片重新走一遍当前 AI 诊断链路，让新版报告直接产出更细颗粒度的学习卡点、知识地图节点和资源推荐。

这不是旧字段补全，而是重新 OCR、重新调用 `analyzeBatch`、重新生成 `reports.bottlenecks`、`errorDetails`、`quality` 和 `subjectProfiles.currentBottlenecks`。

## 安全策略

全量重分析分两阶段执行：

1. `start`：为每份旧报告创建一份替代报告，并触发 `analyzePhotos` 重新分析图片。
2. `finalize`：只在替代报告完成后，才归档旧报告，并按替代报告重建数学学科档案。

旧报告默认不物理删除，只设置：

- `isArchived: true`
- `archivedAt`
- `archiveReason: replaced-by-math-learning-map-full-reanalysis`
- `replacedByReportId`
- `mathReanalysis.status: archived_after_reanalysis`

这样可以让前端列表不再展示旧报告，同时保留追溯能力。

## 前置条件

云函数环境变量需要设置：

```bash
MATH_REANALYSIS_TOKEN=<维护用随机长 token>
```

脚本触发 `analyzePhotos` 时会携带这个 token。`analyzePhotos` 只在 token 与环境变量匹配时允许管理员维护脚本绕过 `_openid` 限制。

## Dry Run

先预览候选报告：

```bash
node scripts/reanalyze-math-history.js --phase start --student-id <studentId> --dry-run
```

确认替代报告完成后，预览可归档报告和重建后的学科档案：

```bash
node scripts/reanalyze-math-history.js --phase finalize --student-id <studentId> --dry-run
```

## 正式执行

第一步：创建替代报告并触发重新分析。

```bash
MATH_REANALYSIS_TOKEN=<token> node scripts/reanalyze-math-history.js --phase start --student-id <studentId> --apply
```

第二步：等待替代报告全部完成后，归档旧报告并重建数学学科档案。

```bash
node scripts/reanalyze-math-history.js --phase finalize --student-id <studentId> --apply
```

## 验收检查

执行后检查：

- 旧报告已归档，不再出现在普通历史列表。
- 新报告存在 `reanalysis.sourceReportId` 和 `originalReportId`。
- 新报告的 `bottlenecks` 含有：
  - `nodeIds`
  - `candidateBottlenecks`
  - `recommendedResourceIds`
  - `resourcePlan`
  - `evidenceStrength`
  - `nextActionText`
- `subjectProfiles.currentBottlenecks` 已按新报告重建，并保留学习地图字段。
- 报告页可以展示“知识地图下一步”。

## 注意事项

- 不建议一次性对所有学生执行。先对一个学生 dry-run，再 apply。
- `start` 后不要立刻 `finalize`，除非确认替代报告已经 `completed`。
- 如果某份替代报告失败，旧报告不会被归档，可以修复后重跑。
- 重分析同一批历史图片时，系统会排除源报告的历史照片，避免被误判为重复照片。
