# 统一状态感知体系设计说明

> 创建日期：2026-07-11
> 状态：已实施第一阶段（事件总线 + 页面接入 + 上传跳转修复）

## 1. 背景

系统有 9 类操作，其中真正异步+轮询的只有 2 个（诊断分析、验证卷生成）。用户上传照片后提示"AI 正在分析中"，但之后没有任何反馈——核心断点是：

1. **断点 A**：上传后 `navigateBack` 回到的页面不一定有轮询（首页、学习记录页无轮询）
2. **断点 B**：轮询最多跑 5 分钟，长分析会超时
3. **断点 C**：离开页面后无直达结果入口，`sendNotification` 是空实现

## 2. 设计目标

不只为"分析完成通知"打补丁，而是为系统内**所有异步操作**建立统一的状态感知体系。

## 3. 核心架构

### 3.1 状态 Store + 事件总线（`utils/status-store.js`）

纯 JS 实现（不依赖 wx），提供：

```
createStatusStore() → {
  registerOperation({studentId, subject, opType, status, progress, label, reportId})
  getOperations(studentId, subject?)
  getActiveOperations(studentId)
  on(event, handler) → unsubscribe
  emit(event, payload)
}
```

- **内存模型**：Map<key, operation>，key = `studentId:subject:opType`
- **事件类型**：
  - `operation:changed` — 任何状态变更
  - `operation:registered` — 从无到活跃（操作开始）
  - `operation:completed` — 从活跃到终态（操作完成）
  - `cache:invalidated` — 缓存失效广播

### 3.2 App 级单例 + 页面混入（`utils/app-status.js`）

- `appStatus` — 全局唯一 store 实例
- `bindPageStatus(page, { studentIdGetter, subjectGetter, handlers })` — 声明式页面接入：
  - 自动在 onUnload 时退订
  - 按学生/学科过滤，只通知相关页面
  - handlers: `{ onOperationCompleted, onOperationChanged, onOperationRegistered, onCacheInvalidated }`

### 3.3 opType 枚举

| opType | 场景 | 来源 |
|--------|------|------|
| `analysis` | 拍照诊断分析 | upload.js + report.js |
| `verification_analysis` | 验证卷答题分析 | upload.js (mode=verification) + report.js |
| `verification_paper` | 验证卷自动生成 | shared-navigation.js |
| `report_pdf` | 报告 PDF 生成 | （预留，当前同步） |
| `dictation_grading` | 英语听写批改 | （预留，当前同步） |

## 4. 数据流

```
用户上传 → upload.js 注册 operation(analysis, analyzing) → emit(registered)
         → navigateTo('/pages/report/report?id=<reportId>')
                         ↓
report.js onLoad → 启动 createAnalysisPoller
             → onAnalyzing → appStatus.registerOperation(progress)
             → onCompleted → appStatus.registerOperation(completed) → emit(completed)
                         ↓
首页/学科页/学习记录页（bindPageStatus 订阅）
  → 收到 operation:completed → 强制刷新数据
```

## 5. 已接入的页面

| 页面 | 接入方式 | 效果 |
|------|---------|------|
| upload.js | 注册操作 + navigateTo 报告页 | 断点 A 修复 |
| report.js | 轮询回调同步 store + onShow 恢复轮询 | 断点 B 缓解 |
| subject-home.js | bindPageStatus → operation:completed 刷新 | 断点 C 修复 |
| index.js | bindPageStatus → operation:completed 刷新 | 首页感知分析完成 |
| upload-history.js | bindPageStatus + onShow 刷新 | 学习记录页感知 |
| shared-navigation.js | 验证卷 poller 回调同步 store | 验证卷状态全局感知 |

## 6. 后续扩展方向（本轮未做）

- **微信订阅消息推送**：`requestSubscribeMessage` + `sendSubscribeMessage` 云函数（需平台审批）
- **同步操作改异步**：报告 PDF / 学习任务包 / 默认试卷当前 60s 同步阻塞，可改为异步+注册到 store
- **首页 in-flight 状态展示**：`index-presenter.js` 读 `appStatus.getActiveOperations()` 在 actionQueue 前插入"分析中"状态卡
- **后端 sendNotification 实现**：当订阅消息就绪后，接通 `analyzePhotos` 的 stub
