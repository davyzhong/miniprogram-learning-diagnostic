# 语文英语学习闭环升级实施设计

> 状态：待产品评审
>
> 日期：2026-07-15
>
> 范围：语文“双轨诊断”和英语“词汇掌握 2.0”。本设计以当前已上线的语文错项复测、英语认词/纸面听写能力为基础，不重做数学诊断链路。

## 1. 目标与总原则

三个学科在家长视角应回答同样四个问题：

1. 孩子现在卡在哪里？
2. 今天最该做什么？
3. 做完如何证明有改善？
4. 下次何时需要再验证？

但三科不能共用同一种“卡点”模型。数学的最小单位是可迁移的细粒度能力；语文的最小单位是具体字词错项或微能力；英语的最小单位是一个单词在“会认”和“会拼”两个维度的状态。

| 学科 | 主要学习单位 | 今日行动 | 通过证据 |
| --- | --- | --- | --- |
| 数学 | 细卡点 | 资源任务或同类变式题 | 纸面验证题 |
| 语文 | 字词错项 / 阅读表达微能力 | 原项复测或策略微任务 | 原项、迁移题或任务产物 |
| 英语 | 单词的认词、拼写状态 | 认词、听写、易混词辨析 | 口头回答或听写照片 |

本轮只补齐语文与英语的闭环体验，不引入英语整卷诊断、发音评分、听力专项，也不把语文阅读能力错误地拆成庞大的知识地图。

## 2. 共同体验合同

### 2.1 工作台的固定结构

语文和英语工作台都采用同一信息优先级，保持现有 B+ 风格、高信息密度的页面语言：

```text
学科近况（1 句）
↓
今日最重要的一件事（唯一主按钮）
↓
两到三个可解释的小状态
↓
最近进展 / 历史入口
```

页面不同时展示多个同权重的大入口。次级行动保留为紧凑任务卡，避免“报告、练习、试卷、错题本”并列抢占首屏。

### 2.2 通用任务对象

前端新增一个纯展示层的 `learningAction` 适配器，不改变数学、语文或英语原有数据表。它把不同学科的待办转换为一致的页面对象：

```js
{
  subject: 'chinese' | 'english',
  kind: 'review_item' | 'skill_task' | 'recognition' | 'dictation' | 'confusion_review',
  priority: 0,
  title: '先复测“辩论”',
  detail: '形近字混淆 · 原项复测 · 约 5 分钟',
  evidenceText: '上次把“辩论”写成“辨论”',
  actionText: '开始复测',
  actionType: 'generateChinesePaper',
  statusText: '今天应完成',
  icon: '字',
  nextReviewAt: '2026-07-16'
}
```

这不是新的持久化集合。它只允许 `subject-home-presenter` 和后续的任务页面统一呈现，避免跨学科页面彼此读取内部字段。

### 2.3 排序规则

所有学科的“今日一件事”先按是否到期、是否反复出现、是否有真实证据排序；再按对家长而言的可完成性排序。

1. 到期且反复出错的原项；
2. 到期复测项；
3. 只有一项薄弱维度的英语单词；
4. 新发现但尚未开始的对象；
5. 无待办时的轻量巩固任务。

## 3. 语文：双轨学习闭环

### 3.1 产品定义

语文包含两条独立但同页可见的学习线：

| 轨道 | 解决的问题 | 最小单位 | 验证原则 |
| --- | --- | --- | --- |
| 字词成长线 | 某个字、词、拼音、诗句记不住或总写错 | `chineseReviewItem` | 原项必测，迁移题只能补充 |
| 阅读表达线 | 不知道如何找依据、概括、表达 | `chineseSkillTask` | 用一个明确策略完成小任务 |

“字词成长线”是当前语文的主线，首期在工作台优先出现。“阅读表达线”首期只做三个高频、可证据化的微任务，不做泛泛的“阅读理解薄弱”。

### 3.2 字词成长线升级

当前 `reports.chineseErrorItems`、`subjectProfiles.chineseReviewItems` 与 `papers.chineseReviewTargets` 已经建立了原项复测基础。本轮不修改其三阶段规则：原项复测、巩固复测、迁移观察；任一失败回到原项复测。

新增的产品层是“易混家族”。它让举一反三可解释、可控，而不是仅依赖模型即时联想。

```js
{
  familyId: 'char-bian',
  familyType: 'shape_similar', // homophone | shape_similar | multiple_meaning | word_usage
  anchorText: '辩',
  members: [
    { text: '辩', hint: '言字旁，和说话、争论有关' },
    { text: '辨', hint: '辛字旁，和分辨有关' },
    { text: '辫', hint: '绞丝旁，和头发有关' }
  ],
  allowedItemTypes: ['character', 'word'],
  gradeRange: [3, 6],
  source: 'curated',
  status: 'active'
}
```

首期只维护 60 至 100 个高频家族，来源为真实错项与小学教材高频混淆项。没有可靠家族时，系统宁可只出原项题，也不生成牵强的“举一反三”题。

#### 出题约束

| 阶段 | 原项题 | 易混家族题 | 题量上限 |
| --- | --- | --- | --- |
| 原项复测 | 必须 1 题 | 不出 | 每错项 1 题 |
| 巩固复测 | 必须 1 题 | 最多 1 题 | 每错项 2 题 |
| 迁移观察 | 必须 1 题 | 最多 1 题 | 每错项 2 题 |

迁移题必须标记为“举一反三”，并在家长页面解释它服务于哪个原错项。生成端优先查家族库；缺失时才沿用现有模型生成方向，且仍受现有 `reviewItemId` 绑定与原项硬校验约束。

#### 字词成长卡

工作台只展示最多 3 张紧凑卡，卡片信息固定：

```text
字  辩论        原项复测 · 今天
上次：辨论       形近字混淆
提示：言字旁的“辩”与说话、争论有关
                         [开始复测]
```

点击进入新增“语文错项详情”页。详情页按“为什么错、怎么区分、已经验证了几次、下一次何时复测”组织，不出现 `itemId`、`LP-101` 或模型内部分类。

### 3.3 阅读表达微任务线

首期只支持三种可复用任务模板：

| 模板 | 面向的问题 | 孩子提交的证据 | 推荐时长 |
| --- | --- | --- | --- |
| 回原文找依据 | 回答没有依据 | 圈画句子 + 一句理由 | 5 分钟 |
| 一句话概括 | 概括不完整 | 句式框架填空 | 5 分钟 |
| 句子写具体 | 表达空泛 | 补写或改写一句话 | 8 分钟 |

任务由诊断中已有的 `reading_skill`、`writing_skill` 或粗能力型 `bottlenecks` 触发。每张任务卡包含一个“方法提示”、一段短材料和 2 至 3 个小问题。首期采用结构化选择、填空、短文本输入三种作答形式；不做开放作文自动评分。

任务结果只产生 `passed`、`needs_followup`、`unclear` 三种证据状态：

- `passed`：连续两次完成同策略任务后，降低其工作台优先级；
- `needs_followup`：保留同一策略，隔天更换材料再练；
- `unclear`：家长可稍后重新提交，不更新状态。

### 3.4 语文数据与接口边界

| 组件 | 变更 | 说明 |
| --- | --- | --- |
| `subjectProfiles.chineseReviewItems` | 扩展只读展示字段 `familyId`、`familyHint` | 原错项仍是唯一事实来源 |
| `chineseConfusionFamilies` | 新集合 | 运营维护的易混家族，不记录学生状态 |
| `chineseSkillTasks` | 新集合 | 存储微任务模板、材料和适用能力标签 |
| `chineseSkillAttempts` | 新集合 | 保存学生作答、证据状态和复测日期 |
| `studentData.getSubjectDashboard` | 扩展语文摘要 | 返回今日主任务、最多 3 条错项、最多 1 条微任务 |
| `generatePaper` | 读取家族提示 | 仅在允许迁移时使用；保持原项题硬校验 |

语文错项详情和微任务均使用家长可读标题。所有内部字段，例如 `itemId`、能力编码、集合 ID，只能用于导航、关联和后台调试。

### 3.5 语文页面流

```text
语文工作台
  ├─ 今日字词复测 -> 验证卷预览 -> 纸面作答 -> 上传验证 -> 更新阶段
  ├─ 某个字词成长卡 -> 错项详情 -> 生成含该项的复测卷
  └─ 今日阅读表达任务 -> 微任务页 -> 提交 -> 形成策略证据
```

首屏没有待复测错项时，才把阅读表达微任务提升为主任务；两者都有时，主任务始终优先给到期的字词复测。

## 4. 英语：词汇掌握 2.0

### 4.1 产品定义

英语继续以词汇闭环为唯一核心。现有 `familiarity`（认词）与 `spelling`（拼写）双维状态机、1/3/7 天复测和听写照片 OCR 保持不变。

本轮改进不是增加一门“英语大课”，而是让每个单词的薄弱原因、今日行动和复测关系更清楚：

| 家长看到的状态 | 条件 | 推荐行动 |
| --- | --- | --- |
| 还不熟 | 认词 `untested` 或 `needs_practice` | 认词 5 个 |
| 会认不会写 | 认词稳定、拼写未稳定 | 听写 5 至 10 个 |
| 重点错词 | 任一维度反复错误 | 错词巩固 3 个 |
| 真正掌握 | 两维均 `mastered` | 不打扰，保留周期抽查 |

现有 `overallMastery` 的 `partial` 只作为内部派生值，页面必须显示为上表的明确语义，不能把 `partial` 展示给家长。

### 4.2 英语工作台与每日任务

英语工作台首屏替换为单一的“今日英语”行动卡，后接双维掌握摘要：

```text
今日英语
先完成 6 个会认不会写的单词听写 · 约 8 分钟
[开始听写]

认词   12 个待练       拼写   6 个待练       真正掌握   84 个
重点错词  there / their / Wednesday
```

任务选择规则：

1. 有拼写到期且认词已稳定的单词，优先“纸面听写”；
2. 有认词到期或明确不熟的单词，推荐“认词练习”；
3. 有重复出错词且已配置易混关系，推荐“错词巩固”；
4. 无待复测词时，提供 5 个新词的轻量认词任务。

默认任务量由当前统一的 20 词调整为可选 `5 / 10 / 20`。工作台推荐 5 或 10；完整 20 词保留在“更多练习”里，避免一次任务过长导致孩子只完成一半。

### 4.3 词族与易混词

英语的举一反三不能只按字母相似随机配对。新增受维护的 `englishWordRelations`，首期覆盖两种可靠关系：

| 类型 | 例子 | 用法 |
| --- | --- | --- |
| `spelling_confusion` | `there / their` | 拼写薄弱词的辨析卡 |
| `meaning_confusion` | `borrow / lend` | 认词薄弱词的意思对比卡 |

每个关系必须有年龄适合的中文解释、最小辨析题和使用边界；没有配置关系时不强行补题。词根、时态变化、复杂搭配和发音近似不进入第一期，以免把小学词汇练习做成语法系统。

```js
{
  relationId: 'there-their',
  relationType: 'spelling_confusion',
  wordIds: ['there', 'their'],
  explanation: 'there 表示“那里”；their 表示“他们的”。',
  prompt: '选择正确单词填空：This is ___ classroom.',
  answer: 'their',
  gradeRange: [4, 6],
  status: 'active'
}
```

“错词巩固”一组最多 3 个目标词，每个词最多 1 道辨析题。它不能替代该词原本的认词或听写复测。

### 4.4 英语数据与接口边界

| 组件 | 变更 | 说明 |
| --- | --- | --- |
| `studentEnglishWords` | 不改状态机；新增可选 `relationIds` 缓存字段 | 词条仍由双维状态作为事实来源 |
| `englishWordRelations` | 新集合 | 词族/易混词运营数据，不保存学生状态 |
| `englishPracticeSessions` | 增加 `recommendedBy` 与 `taskSize` | 便于识别今日任务完成情况 |
| `englishPracticeAttempts` | 增加可选 `relationId` | 仅在辨析卡使用 |
| `englishVocabulary` | 新增 `getTodayPlan`、`generateConfusionSession` | 保持词库、会话和状态更新在同一云函数 |
| `studentData.getSubjectDashboard` | 读取英语今日计划摘要 | 工作台不再自行猜测唯一主任务 |

`getTodayPlan(studentId)` 返回已计算好的主任务和紧凑摘要，前端不能重复实现选词优先级：

```js
{
  primaryAction: {
    kind: 'dictation',
    title: '先听写 6 个会认不会写的单词',
    wordIds: ['...'],
    taskSize: 6,
    estimatedMinutes: 8
  },
  stats: {
    recognitionDue: 12,
    spellingDue: 6,
    recurringWeak: 3,
    fullyMastered: 84
  },
  featuredWords: ['there', 'their', 'Wednesday']
}
```

### 4.5 英语页面流

```text
英语工作台
  ├─ 今日认词 -> 5/10/20 词认词会话 -> 更新 familiarity
  ├─ 今日听写 -> 语音节奏听写 -> 上传照片 -> OCR -> 更新 spelling
  ├─ 重点错词 -> 易混词辨析卡 -> 只记录辅助证据
  └─ 单词状态 -> 错词本 -> 查看为什么待复测、何时再练
```

辨析卡错误会提高该词的推荐优先级，但不应直接把拼写或认词状态置为失败；只有对应的认词回答或听写 OCR 结果才改变该维度掌握状态。

### 4.6 英语“句子应用卡”的后置试点

当下不进入开发主线。只有满足以下条件才开启小范围试点：

1. 至少 30 个词完成双维闭环；
2. 有至少 4 周的真实复测数据；
3. 家长确认“会单词但不会放进句子”是当前主要问题。

试点每次只带一个已稳定词和一个简短句子，不做时态讲解、作文批改或英语阅读理解。这样可为以后扩展积累证据，而不会污染词汇产品定位。

## 5. 交付节奏

### 第一批：让今日行动更清楚

1. 增加跨学科 `learningAction` 展示适配器；
2. 调整语文、英语工作台为“唯一主行动 + 紧凑状态”；
3. 英语支持 5/10/20 词任务量，且将主任务带入既有练习会话；
4. 只使用已有数据，不做集合迁移。

### 第二批：把举一反三做得可信

1. 建立首批语文易混家族和英语易混词运营数据；
2. 将语文迁移题优先绑定家族提示；
3. 上线英语错词巩固卡；
4. 完成内部管理/种子导入方式，暂不对家长暴露复杂编辑器。

### 第三批：补齐语文能力任务

1. 上线三类阅读表达微任务模板；
2. 接入诊断能力型卡点作为任务触发来源；
3. 保存结构化作答、证据状态和复测时间；
4. 加入学习记录中的“策略练习”条目。

### 第四批：错项与词汇详情

1. 上线语文字词成长详情页；
2. 升级英语错词本为“待练原因 + 下次复测日”；
3. 为家长提供有限的纠错能力：标记 OCR 识别不准、隐藏误判项；
4. 后续再评估手动添加语文错项和英语自定义词。

## 6. 验收与指标

### 6.1 体验验收

- 语文、英语工作台首屏均能在不滚动的情况下看懂“今天做什么”；
- 任一展示给家长的页面不出现内部编码、集合 ID、能力代码或状态枚举值；
- 语文迁移题无法代替原项复测；
- 英语辨析题无法代替认词或听写证据；
- 任务中断后可继续，重复提交不会重复累计掌握次数；
- 无待办时页面展示轻量下一步，而不是空白或无意义的“全部完成”。

### 6.2 学习效果基线

上线后按周记录，不以一次分数判断效果：

| 指标 | 计算方式 | 目标用途 |
| --- | --- | --- |
| 语文原项复现率 | 同错项再次被识别的比例 | 判断字词闭环是否有效 |
| 语文三阶段完成率 | 进入复测后达到 `mastered` 的比例 | 判断复测节奏是否合适 |
| 微任务证据完成率 | 已开始任务中得到有效证据的比例 | 判断任务是否太难或太长 |
| 英语双维掌握率 | 两维均 `mastered` 的词 / 活跃词 | 判断词汇闭环推进情况 |
| 英语会认不会写转化率 | 拼写稳定词 / 初始仅认词稳定词 | 判断听写价值 |
| 英语错词复发率 | 复测后再次出错的词比例 | 判断选词与间隔规则 |

指标只在后台和项目文档使用，不应以排名或压力数字直接呈现在孩子端。

## 7. 不在本轮范围内

- 英语整卷拍照诊断、语法专题、听力、发音评分、作文批改；
- 大而全的语文阅读知识地图、开放作文自动评分；
- 用模型生成大量未经维护的易混字词或易混单词；
- 让家长在前台编辑复杂的词族、错项或能力树；
- 更改数学现有诊断、验证卷和知识地图逻辑。

## 8. 风险与处理

| 风险 | 处理方式 |
| --- | --- |
| 易混家族质量参差 | 首期小而精、可停用，缺失时回退原项复测 |
| OCR 把字词或听写词判错 | 提供“识别不准”反馈，不直接污染掌握状态 |
| 微任务作答质量难判 | 首期仅用结构化题型，不做开放文本评分 |
| 工作台信息再次膨胀 | 固定“1 个主行动 + 最多 3 个次级状态”的上限 |
| 英语功能向大系统蔓延 | 所有新增能力先检查是否能落在词级双维闭环内 |

## 9. 评审结论待确认

本设计建议按“第一批 -> 第二批 -> 第三批 -> 第四批”顺序实施。这样可以先让孩子和家长看到明确、紧凑的行动，再逐步增加可信的举一反三和能力训练，而不是先堆叠更多入口。

评审时请重点确认两点：

1. 语文阅读表达首期是否只接受上述三种微任务模板；
2. 英语首期是否把“句子应用卡”明确放在后置试点，不进入本轮开发。
