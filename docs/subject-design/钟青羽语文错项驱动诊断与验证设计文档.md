# 钟青羽语文错项驱动诊断与验证设计文档

## 1. 设计目标

语文学科不能直接套用数学“知识点地图 + 细卡点验证卷”的模型。数学常见问题是能力链条里的某个节点不稳，例如小数点定位、通分、单位换算；语文里大量问题则是具体记忆对象没有掌握，例如某个字不会写、某个词写错、某句古诗漏字。

本设计的目标是建立一套语文专用闭环：

1. 把“具体错项”从粗学习卡点里拆出来；
2. 让记忆型错项和验证题形成强对应关系；
3. 让能力型问题继续保留为学习卡点；
4. 生成验证卷时优先复测原错字、原错词、原诗句，而不是只按粗类出同类题；
5. 通过间隔复测判断“已掌握”，而不是一次答对就清空。

## 2. 核心判断

语文错误分成两类。

第一类是记忆型错项，适合“一错一追踪”：

- 汉字：不会写、写错、形近字混淆、笔画部件错误；
- 词语：看拼音写词语错误、词语搭配错误、近义词混淆；
- 拼音：声母、韵母、声调、整体认读音节错误；
- 古诗文：漏字、错字、顺序错、作者题目混淆；
- 成语与日积月累：字形错误、含义混淆、语境误用。

第二类是能力型卡点，适合“技能归纳”：

- 阅读理解没有回到原文找依据；
- 概括段意不完整；
- 修辞手法判断不稳；
- 句式改写规则不稳；
- 作文结构、细节描写、立意表达不稳定。

结论：语文学科应以“错项清单”为第一层，以“能力卡点”为第二层。

## 3. 数据结构

### 3.1 reports.chineseErrorItems

诊断报告新增 `chineseErrorItems`。这是语文最重要的新增字段。

```js
{
  itemId: 'CHI-CHAR-辩-20260616',
  itemType: 'character',
  targetText: '辩',
  expectedAnswer: '辩',
  studentAnswer: '辨',
  sourceContext: '看拼音写词语：biàn lùn',
  mistakeType: '形近字混淆',
  sourceQuestion: '看拼音写词语',
  sourceImageIndex: 1,
  sourceFileID: 'cloud://...',
  evidenceStrength: 'high',
  verificationMethods: ['dictation', 'pinyin_to_word', 'context_fill'],
  reviewStatus: 'needs_review',
  nextReviewAt: '2026-06-18T00:00:00.000Z',
  relatedLpCode: 'LP-101',
  suggestion: '先区分“辩/辨/辫/瓣”的部件和语义，再做听写复测。'
}
```

字段说明：

| 字段 | 含义 |
| --- | --- |
| `itemId` | 错项稳定 ID，用于复测追踪 |
| `itemType` | `character` / `word` / `pinyin` / `poem_line` / `idiom` / `accumulation` / `reading_skill` / `writing_skill` |
| `targetText` | 需要掌握的具体对象 |
| `expectedAnswer` | 正确答案 |
| `studentAnswer` | 学生本次错误答案 |
| `sourceContext` | 原题语境，尽量保留 |
| `mistakeType` | 错误类型，如形近字混淆、漏字、声调错误 |
| `verificationMethods` | 后续复测形式 |
| `reviewStatus` | `needs_review` / `reviewing` / `mastered` / `recurring` |
| `relatedLpCode` | 兼容现有粗卡点 |

### 3.2 subjectProfiles.chineseReviewItems

学科档案新增 `chineseReviewItems`，保存当前待复测错项。

```js

  itemId: 'CHI-WORD-辩论',

  targetText: '辩论',
  expectedAnswer: '辩论',
  lastWrongAnswer: '辨论',
  sourceContext: '看拼音写词语：biàn lùn',
  mistakeType: '形近字混淆',
  status: 'needs_review',
  firstSeenAt: Date,
  lastSeenAt: Date,
  evidenceCount: 2,
  reviewPassCount: 0,
  reviewFailCount: 1,
  nextReviewAt: Date,
  intervalLevel: 0,
  relatedLpCode: 'LP-101',
  verificationMethods: ['dictation', 'pinyin_to_word', 'context_fill']
}
```

### 3.3 papers.chineseReviewTargets

语文验证卷新增 `chineseReviewTargets`，记录这张验证卷具体复测哪些错项。

```js
{
  itemId: 'CHI-WORD-辩论',
  itemType: 'word',
  targetText: '辩论',
  expectedAnswer: '辩论',
  sourceContext: '看拼音写词语：biàn lùn',
  verificationMethods: ['pinyin_to_word', 'dictation'],
  relatedLpCode: 'LP-101'
}
```

## 4. 诊断输出规则

语文诊断仍然输出 `bottlenecks`，用于兼容现有页面。但语文诊断必须额外输出 `chineseErrorItems`。

对于记忆型错项：

1. 必须尽量抽取 `targetText`、`expectedAnswer`、`studentAnswer`；
2. 必须保留 `sourceContext`，因为复测时要知道原始语境；
3. 可以归入 `LP-101` 或 `LP-104`，但不能只停留在粗卡点；
4. 如果是古诗、成语、日积月累，要尽量保留整句或完整词条。

对于能力型卡点：

1. 可以只进入 `bottlenecks`；
2. 若能抽取具体训练对象，也可以同时写入 `chineseErrorItems`，但 `itemType` 应使用 `reading_skill` 或 `writing_skill`；
3. 验证题允许出变式题，不要求完全复测原题。

## 5. 验证卷生成规则

语文验证卷优先由 `chineseReviewItems` 驱动。

记忆型错项验证题必须覆盖原错项：

| 错项类型 | 第一次复测 | 第二次复测 | 第三次复测 |
| --- | --- | --- | --- |
| 汉字 | 听写单字或词语 | 看拼音写词语 | 语境填空 |
| 词语 | 看拼音写词语 | 听写 | 造句或语境填空 |
| 拼音 | 给汉字注音 | 选择正确读音 | 语境读音辨析 |
| 古诗句 | 补写原句 | 上下句连线 | 默写整句或整首片段 |
| 成语 | 补全成语 | 解释含义 | 语境选择 |

能力型卡点验证题可以按技能生成：

- 阅读理解：短文 + 定位依据题；
- 句式改写：同规则多题；
- 作文表达：小片段修改或扩写。

## 6. 掌握状态规则

记忆型错项不应一次答对就移除。

建议采用 3 级间隔复测：

1. 第一次复测通过：`intervalLevel = 1`，1-2 天后再测；
2. 第二次复测通过：`intervalLevel = 2`，3-5 天后再测；
3. 第三次复测通过：标记 `mastered`；
4. 任意一次复测失败：`reviewFailCount + 1`，状态回到 `recurring`，间隔级别降回 0。

## 7. 与现有系统衔接

短期兼容策略：

1. `reports.bottlenecks` 保留，仍用于报告页、学科主页、卡点中心；
2. `reports.chineseErrorItems` 新增，用于语文错项清单；
3. `subjectProfiles.currentBottlenecks` 保留粗类；
4. `subjectProfiles.chineseReviewItems` 新增，用于语文验证卷的真实目标；
5. `generatePaper` 在 `subject === 'chinese'` 时，优先读取 `chineseReviewItems` 生成错项复测题；
6. 如果没有 `chineseReviewItems`，再退回现有 `bottleneckTargets` 模式。

## 8. 页面体验

语文报告页增加“语文具体错项”区块：

- 标题：`语文具体错项`
- 每项展示：目标、错答、错误类型、复测方式、下次复测建议；
- 示例：`辩论：写成“辨论”，形近字混淆，建议先做看拼音写词语。`

语文学科主页把主要行动按错项优先级改为：

- 有待复测错项：`生成语文错项复测卷`
- 只有能力型卡点：`生成能力验证卷`
- 暂无错项：`继续上传语文作业`

## 9. 第一阶段落地范围

第一阶段只做最小闭环：

1. 诊断 prompt 要求语文输出 `chineseErrorItems`；
2. 结果归一化保留 `chineseErrorItems`；
3. 分析合并时写入 `reports.chineseErrorItems`；
4. 学科档案维护 `subjectProfiles.chineseReviewItems`；
5. 语文验证卷生成时优先读取 `chineseReviewItems`，把原错项写入题目和 `papers.chineseReviewTargets`；
6. 增加测试覆盖“错项保存”和“验证卷围绕原错项生成”。

暂不做：

- 独立错项详情页；
- 完整间隔复测算法 UI；
- OCR 逐字纠错编辑器；
- 家长手动添加错项。

这些可以作为第二阶段继续推进。

## 10. 2026-07-15 实现核查与修正

本次核查确认：诊断阶段已经抽取并保存 `chineseErrorItems`，学科档案也会维护 `chineseReviewItems`；但自动验证卷曾沿用数学的“细卡点 ID”队列。这样虽然生成提示词会优先提到语文错项，却不能保证每个待复测字词都作为独立任务进入后台出卷，也不能可靠地把错项目标带到后续反馈。

已完成以下修正：

1. 自动出卷和维护入口在 `subject === 'chinese'` 时，改为取所有未掌握的 `chineseReviewItems.itemId`；`mastered`、`archived`、`ignored` 项不再重复出卷。
2. 生成提示词明确区分 `direct_review` 与 `similarity_transfer`：每个错项必须先出至少一道原项复测题，后者只能作为同音、同形、形近或多义的扩展，且必须继续绑定原错项 ID。
3. 生成结果增加硬校验：任何一个目标错项没有对应的原项复测题，就拒绝这次生成，不会悄悄用泛化题替代。
4. 后台分批追加题目时会合并并保存 `papers.chineseReviewTargets`，验证上传可继续按 `reviewItemId` 汇总证据和更新掌握状态。

当前尚未形成的是“相似字扩展库”的完整产品规则。系统已经允许模型在原项复测后增加同音、同形、形近和多义题，但相似范围、题量比例、难度梯度和家长可见说明仍应在下一阶段的语文验证卷整体设计中统一定义。

## 11. 分阶段验证卷实施（2026-07-15）

语文验证卷现按错项自身的复测历史分为三个阶段：

| 阶段 | 出题规则 | 通过后的安排 |
| --- | --- | --- |
| 原项复测 | 只考原错字、词或句，避免相似题分散注意力 | 1 天后进入巩固复测 |
| 巩固复测 | 保留原项题，并增加 1 道与错误类型匹配的举一反三题 | 3 天后进入迁移观察 |
| 迁移观察 | 继续保留原项题，使用同音、形近、同形或多义题观察稳定性 | 7 天后进行最后一次确认 |

任何一次失败都会回到“原项复测”。每个错项最多有 1 道举一反三题，且举一反三永远不会替代原项题。PDF、试卷预览和语文工作台均使用“原项复测 / 巩固复测 / 迁移观察”等家长可理解的文案，不显示内部错项编号。

本轮的相似题范围基于诊断得到的错误类型选择方向，仍由模型生成具体内容。后续可在真实使用数据积累后再加入受维护的相似字词库，而不应在当前阶段提前固化一份覆盖不足的词表。
