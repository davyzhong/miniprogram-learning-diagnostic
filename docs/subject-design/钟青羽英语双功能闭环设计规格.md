## 0. 速览（设计要点）

- **两个功能**：① 熟悉度（口头反应，测听力+产出+发音）② 听写（纸笔+拍照，测拼写）
- **核心抽象**：每个单词维护**两个独立维度**的状态——`familiarity`（功能1测）和 `spelling`（功能2测），各自独立运行同一套状态机
- **单次会话只走一个功能**：孩子一次要么全说、要么全写，体验一致，抽词逻辑简单
- **闭环的"联"体现在选词**：抽词时参考另一个维度的状态做加权（"熟但没测过拼写"的词优先补盲区）
- **掌握判定**：两维都 `mastered` 才算真正掌握
- **判定三态**：`correct` / `incorrect` / `unclear`（识别失败不改状态，独立处理）

## 1. 核心抽象

### 1.1 两个功能测不同的能力维度

| 功能 | 孩子做什么 | 测的能力 | 答案采集方式 |
|------|-----------|---------|-------------|
| 功能1 熟悉度 | 口头反应（中英互译式） | 听力理解 + 主动产出 + 发音 | 语音识别 |
| 功能2 听写 | 纸上完整拼写 | 拼写掌握 | 拍照 OCR |

### 1.2 两个维度独立追踪，避免状态打架

一个单词的"掌握"是多维的。若两个功能都更新同一个状态，会冲突（功能1答对推到 reviewing，功能2写错又打回 needs_practice，状态横跳）。

**解决：每个词同时维护 `familiarity` 和 `spelling` 两个独立维度，各自运行状态机。一个词"真正掌握" = 两个维度都 mastered。**

### 1.3 单次会话单功能

一次会话纯走一个功能（要么全说、要么全写）。孩子体验一致，抽词逻辑只看一个维度，简单可靠。两功能的"联动"体现在**抽词时参考另一维度状态做加权**（见 §6）。

## 2. 数据结构

### 2.1 单词文档（`studentEnglishWords` 集合）

```jsonc
{
  "_id": "...",
  "studentId": "...",
  "word": "Wednesday",            // 目标英文词
  "cnMeaning": "星期三",          // 标准中文释义
  "cnSynonyms": ["周三"],         // 容错同义词（功能1 en2cn 判定用）
  "grade": "五上",
  "unit": "Unit 2",

  "familiarity": {                // 维度A：功能1 测
    "status": "untested",         // untested | needs_practice | reviewing | mastered
    "correctCount": 0,            // reviewing 轨道上的连续正确次数
    "wrongCount": 0,
    "lastTestedAt": "",
    "nextReviewAt": "",
    "lastDirection": ""           // cn2en | en2cn（轮换用）
  },

  "spelling": {                   // 维度B：功能2 测
    "status": "untested",
    "correctCount": 0,
    "wrongCount": 0,
    "lastTestedAt": "",
    "nextReviewAt": ""
  },

  "overallMastery": "untested",   // 派生：untested | partial | mastered（见 §7）
  "createdAt": "...",
  "updatedAt": "..."
}
```

### 2.2 会话文档（`englishPracticeSessions` 集合）

```jsonc
{
  "_id": "...",
  "studentId": "...",
  "functionType": "spelling",     // familiarity | spelling（本次走哪个功能）
  "direction": "cn2en",           // 功能1：cn2en|en2cn|mixed；功能2：cn|en|mixed（提示类型）
  "wordLimit": 20,
  "wordItems": [                  // 本次抽出的词（按读题顺序）
    { "wordId": "...", "word": "boy", "order": 0 }
  ],
  "attempts": [                   // 逐题判定
    {
      "wordId": "...", "order": 0,
      "recognized": "BOY",        // 功能1：ASR文本；功能2：OCR匹配结果
      "verdict": "correct",       // correct | incorrect | unclear
      "durationMs": 4200          // 静默记录的答题时长（诊断维度）
    }
  ],
  "photoFileId": "",              // 功能2 专属：听写纸照片
  "status": "completed",
  "startedAt": "...",
  "completedAt": "..."
}
```

> `durationMs`：静默记录每题从出题到提交的时长，用于将来判断"是不会、不熟、还是粗心"。对孩子无感，MVP 就带上。

## 3. 两维状态机（两个维度各自独立运行同一套规则）

状态机沿用 v1 设计，**两个维度各跑一份**。下面用"维度"泛指 familiarity 或 spelling。

### 3.1 状态定义

| 状态 | 含义 |
|------|------|
| `untested` | 在词库中，该维度尚无有效判定记录 |
| `needs_practice` | 判定为 incorrect，需强化 |
| `reviewing` | 已答对，进入间隔复测链路 |
| `mastered` | 连续完成复测，暂时视为掌握 |

### 3.2 状态转移（`correctCount` = reviewing 轨道上的连续正确次数）

```
untested
  ├─ correct   → reviewing,  correctCount=1, nextReviewAt = 今+1天
  ├─ incorrect → needs_practice, wrongCount+1, nextReviewAt = 今+1天
  └─ unclear   → untested（不改状态，本轮重测）

needs_practice
  ├─ correct   → reviewing,  correctCount=1, nextReviewAt = 今+1天
  ├─ incorrect → needs_practice, wrongCount+1
  └─ unclear   → needs_practice（不改状态，本轮重测）

reviewing
  ├─ correct (correctCount=1) → correctCount=2, nextReviewAt = 今+3天
  ├─ correct (correctCount=2) → correctCount=3, nextReviewAt = 今+7天
  ├─ correct (correctCount=3) → mastered
  ├─ incorrect → needs_practice, correctCount=0
  └─ unclear   → reviewing（不改状态，本轮重测）

mastered
  └─ incorrect → needs_practice, correctCount=0  （遗忘回退）
```

> 关键：功能1 判定只动 `familiarity`，功能2 判定只动 `spelling`，互不干扰。这是避免状态打架的根本。

## 4. 功能1（熟悉度）规格

### 4.1 交互流

```
1. 抽词引擎选出 N 个词（见 §6）
2. 对每个词，确定提示方向（轮换 lastDirection）：
   - cn2en：TTS 播报中文释义 → 孩子说英文
   - en2cn：TTS 播报英文发音 → 孩子说中文
3. 孩子口头反应 → 录音 → ASR 转文本
4. 判定 verdict
5. 更新该词的 familiarity 维度状态（§3.2）
6. unclear 的词本轮末尾重测
```

### 4.2 判定逻辑

| 方向 | correct | incorrect | unclear |
|------|---------|-----------|---------|
| cn2en | ASR 英文 = 目标词（大小写无关，或可还原为目标拼写，如 BOY→boy） | ASR 与目标词有明确拼写差异 | ASR 为空/噪音/无法判断 |
| en2cn | ASR 中文 ∈ {cnMeaning ∪ cnSynonyms} | ASR 中文与目标释义无关 | ASR 为空/无法判断 |

- `cnSynonyms` 字段用于 en2cn 的同义容错（"星期三"/"周三"都对）。导入词库时维护，MVP 先手工补关键同义词。
- ASR 用微信同声传译插件（识别中英文都在其能力范围内，比识别字母可靠得多）。

## 5. 功能2（听写）规格

### 5.1 交互流

```
1. 抽词引擎选出 N 个词（见 §6）
2. 对每个词，TTS 播报中文释义 或 英文发音（可配置/轮换）
3. 孩子在纸上拼写 → 说"下一个"或点【下一题】按钮 → AI 读下一个
4. 全部读完后，孩子/家长拍一张听写纸照片上传
5. 云函数 OCR 识别 + 候选词约束匹配 → 逐词判定
6. 更新每个词的 spelling 维度状态（§3.2）
7. unclear（OCR失败/词序无法对应）的词本轮重测
```

### 5.2 判定逻辑（关键：候选词约束匹配）

OCR 不是开放识别手写英文，而是**在本次会话的 N 个候选词里做最近匹配**：

```pseudo
对 OCR 识别出的每个文本块（按位置从上到下、从左到右排序）：
  1. 在 [本次会话剩余未匹配的候选词] 中，找编辑距离最小的词 bestMatch
  2. 若编辑距离 == 0         → verdict = correct
  3. 若编辑距离 <= 容忍阈值   → verdict = incorrect（拼写差异，但能还原意图，如 Wensday→Wednesday）
  4. 若编辑距离 > 容忍阈值 或 无可信识别 → verdict = unclear
  5. bestMatch 从候选池移除（避免一词匹配多次）
```

- **词序对应**靠"位置排序 + 候选词消费"双重保证：按书写位置排序后依次匹配，每匹配掉一个候选词就移除，即使孩子漏写一个，后续词也能正确归位。
- **书写格式约定（MVP）**：引导孩子"一行一个词"或"从上到下顺序写"，降低 OCR 切分难度。自由排版留到后续优化。
- **拍照不复用数学诊断报告链路**。英语纸面听写在 `englishVocabulary` 内用本次候选词表做约束 OCR，再用目标词与识别文本的确定性拼写距离复核，避免把 AI verdict 直接当作最终结论。

### 5.3 节奏控制

- 屏幕放显眼的【下一题】按钮为主通道，孩子写完点一下。
- 语音指令"下一个"/"好了"为可选辅助识别（嘈杂环境或手忙时不稳，按钮兜底）。

## 6. 联动抽词规则

### 6.1 单次会话单功能

本次会话走 familiarity 或 spelling，二选一。孩子体验一致（一次全说或全写），抽词逻辑只看一个维度，简单可靠。

### 6.2 选词优先级（本次测维度 X，另一维度为 Y）

| 优先级 | 维度 X 状态 | 维度 Y 状态 | 说明 |
|:------:|------------|------------|------|
| P0 | needs_practice | needs_practice | 双重薄弱，最高优先 |
| P1 | needs_practice | * | 单维薄弱 |
| P2 | 到期复测（nextReviewAt ≤ 今） | * | 间隔复测不漏 |
| P3 | untested | reviewing 或 mastered | **"熟但没测过 X"——补盲区，联动的核心** |
| P4 | untested | untested / needs_practice | 新词 |
| P5 | reviewing 未到期 | * | 推进中 |
| P6 | mastered | * | 不选（已掌握） |

> **P3 是双功能闭环的灵魂**：功能1 测出"熟"的词，会被优先推给功能2 验拼写；反之亦然。没有 P3，两个功能就是各跑各的独立工具，闭环不闭合。

### 6.3 选词算法

```pseudo
function pickWords(目标维度X, 另一维度Y, count=20):
  candidates = 词库中 X.status != 'mastered' 的词
  按 §6.2 优先级表给每个候选打分（P0最高）
  同优先级内：wrongCount 高的优先；其次 nextReviewAt 早的；最后字母序稳定排列
  返回前 count 个
```

### 6.4 功能选择

- 单次会话纯一个功能，不混合。
- 哪个功能由孩子/家长本次选择（"今天做听写"/"今天练熟悉度"），或系统根据两维整体薄弱度推荐。

## 7. overallMastery 派生

每次任一维度状态变化后，重新计算并存储（便于查询统计）：

```pseudo
overallMastery =
  (familiarity.status == 'mastered' && spelling.status == 'mastered') ? 'mastered'
: (familiarity.status == 'untested' && spelling.status == 'untested') ? 'untested'
: 'partial'
```

工作台展示用 `overallMastery`：已掌握 / 部分掌握 / 未测。

## 8. 可配置项与待定问题

### 8.1 可配置（建议放云函数 config）

- `wordLimit`：单次会话词数（默认 20）
- 拼写容忍阈值：编辑距离（默认短词 1、长词 2-3，按词长自适应）
- 间隔节奏：1/3/7 天（可调）
- 功能2 提示类型：cn / en / mixed
- 功能1 方向策略：轮换 / 随机 / 固定

### 8.2 待定（MVP 后再决策）

- en2cn 的同义词容错深度（`cnSynonyms` 维护成本）
- 长期复盘：mastered 的词是否 N 天后随机回测防遗忘
- 拍照 OCR 对低年级潦草手写的准确率，需真机验证后定容忍阈值
- 连续多次 unclear 的词是否提示家长人工介入
- 长期：单词级数据聚合为"拼写卡点"（如双元音词普遍弱）——接上 AI Learning OS 卡点诊断理念

## 9. MVP 实施路径

闭环分三步建，避免一次性建多维的复杂度：

| 步骤 | 范围 | 产出 |
|------|------|------|
| **第一步** | 只做功能2（拼写维度）单维闭环 | 复用数学 OCR 管线，跑通"出题→听写→拍照→判定→状态→复测"，立即产出拼写数据 |
| **第二步** | 加功能1（熟悉度维度） | 状态模型升级为两维并行 |
| **第三步** | 做两维联动抽词（P3 补盲区） | 闭环真正闭合 |

先单维跑通验证假设（拼写是否为核心短板），再加维度，是稳妥路径。直接上两维联动会把 MVP 搞复杂。

## 附：与 v1 设计文档的差异

| 维度 | v1（钟青羽英语学科设计文档） | v2（本规格） |
|------|---------------------------|-------------|
| 掌握状态 | 单维 `masteryStatus` | 双维并行 `familiarity` + `spelling` |
| 功能 | 单一"听写"（语音拼读判定） | 双功能：熟悉度（口头）+ 听写（纸笔拍照） |
| 答案采集 | 语音识别字母序列 | 功能1 整词/整句 ASR；功能2 拍照 OCR |
| 拍照诊断 | 明确不做 | 功能2 复用数学 OCR 管线（听写纸为输入） |
| 闭环联动 | 无（单功能） | P3 补盲区联动抽词 |
| 判定可靠性风险 | 字母级 ASR（难点） | 整词 ASR + 图像识别（均可行） |
