# 学习档案 / 学科主页 / 验证试卷页职责去重设计

## 背景

当前小程序已经从“选择学生开始诊断”升级为单人 MVP 的“学习档案首页”。首页开始承担报告式综合摘要、样本覆盖、学习观察、学习记录和下一步建议。

随之出现一个新的信息架构问题：`首页`、`学科主页`、`验证试卷页` 多处重复展示相似内容。

典型重复包括：

- 首页展示综合摘要，学科主页又展示当前综合诊断。
- 首页展示学习观察，学科主页又展示学习卡点列表。
- 首页展示最近学习记录，学科主页又展示最近变化。
- 学科主页展示待验证卡点，验证试卷页再次用诊断口吻解释卡点。

这会带来两个问题：

- 家长和学生进入新页面后，看见的是同一组信息的不同说法，认知负担变高。
- 页面职责不清，后续迭代容易继续把摘要、卡点、记录都塞进每个页面。

## 已确认方向

采用 A 方案：

> 学科主页彻底工作台化。

核心原则：

- 首页负责解释现状。
- 学科主页负责执行动作。
- 验证试卷页负责配置出卷。
- 报告页负责承载完整诊断细节。
- 学习记录页负责承载证据链和历史。

诊断解释只应出现在两个地方：

- 首页：跨学科、阶段性、面向家长的综合解释。
- 报告页：单次报告或验证反馈的完整解释。

学科主页和验证试卷页不再重复承担诊断解释。

## 页面职责

### 1. 首页：学习档案

首页回答：

> 这个孩子现在整体学习情况怎么样？

首页保留：

- 双女孩学习插图。
- 当前综合摘要。
- 样本覆盖。
- 跨学科重点提示。
- 少量关键指标。
- 最近学习记录摘要。
- 下一步建议。
- 学科入口。

首页调整：

- “学习观察”不再展示为完整卡点列表。
- 改为“重点提示”或“当前优先事项”，最多展示 2 条。
- 只展示跨学科层面的最高优先级信息。
- 详细学科动作下沉到学科主页。
- 详细诊断解释下沉到报告页。

首页不放：

- 完整 `currentBottlenecks` 列表。
- 单学科最近变化列表。
- 每个卡点的证据、严重度、根因解释。
- 出卷配置细节。

### 2. 学科主页：学科工作台

学科主页回答：

> 这个学科现在该做什么？

学科主页保留：

- 学科名称和学生信息。
- 当前主任务，例如“生成验证试卷”或“拍照诊断”。
- 待处理队列：短名称 + 状态 + 操作入口。
- 拍照诊断入口。
- 生成验证试卷入口。
- 默认试卷入口。
- 学习记录入口。
- 查看完整报告入口。
- 分析中状态卡片。

学科主页删除：

- 顶部大图。
- “当前综合诊断”大段摘要。
- 三列诊断指标条，除非转化为任务数量。
- “最近变化”报告列表。
- 类似报告页的卡点解释。

学科主页展示方式：

- 页面首屏应该像工作台，而不是报告。
- 顶部为“数学工作台 / 下一步：生成验证试卷”。
- 主按钮优先对应当前最重要任务。
- 待处理队列只展示可执行项，不解释完整原因。

示例结构：

1. 顶部：数学工作台
2. 当前任务：下一步生成验证试卷
3. 主操作：生成验证试卷 / 拍照诊断
4. 待处理队列：计算基础、审题理解
5. 工具入口：默认试卷、学习记录、查看完整报告
6. 分析中状态：仅在有后台任务时出现

### 3. 验证试卷页：出卷配置器

验证试卷页回答：

> 这张验证卷怎么生成？

验证试卷页保留：

- 待验证对象选择。
- 已选数量。
- 每个对象的短名称。
- 相关错题数量或证据数量。
- 题量。
- 预计用时。
- A4 纸张提示。
- 预览 PDF。
- 生成 PDF。

验证试卷页调整：

- 卡点原因默认不展开。
- 如需查看来源，可点击单项展开轻量信息。
- 展开内容只显示来源报告、首次发现时间、相关错题数量。
- 不显示长篇诊断解释。

验证试卷页不放：

- 当前综合诊断摘要。
- 完整根因解释。
- 学科主页式任务卡。
- 最近记录列表。

### 4. 报告页：完整解释

报告页回答：

> 这次诊断或验证具体发现了什么？

报告页继续承担：

- 单次诊断结论。
- 学习卡点详情。
- 错题详情。
- 证据来源。
- 验证反馈。
- PDF 下载。

报告页不是本阶段重构重点，但它是诊断解释的最终承载页。

### 5. 学习记录页：证据链

学习记录页回答：

> 这些结论来自哪些真实学习材料？

学习记录页继续承担：

- 上传照片记录。
- 诊断报告历史。
- 验证试卷历史。
- 验证作答上传历史。
- 原图和 OCR 摘要。

学习记录页不是本阶段重构重点，但首页和学科主页都应把历史细节导向它。

## 数据与视图模型调整

### 首页 presenter

`index-presenter.js` 应继续生成综合档案视图，但建议调整命名和结构：

- `observations` 从完整列表降级为 `priorityHighlights`。
- 每条 highlight 只包含：
  - `subject`
  - `title`
  - `summary`
  - `actionText`
  - `targetUrl` 或足够导航的字段
- `recentRecords` 保持最多 2 条。
- `subjects` 保持为学科入口。

首页不需要展示每个卡点的完整状态。

### 学科主页 presenter

`subject-home-presenter.js` 应从“诊断视图”转为“工作台视图”。

建议输出：

```js
{
  subjectTitle: '数学工作台',
  primaryTask: {
    title: '生成验证试卷',
    summary: '2 个学习卡点等待验证',
    actionText: '生成验证试卷',
    actionType: 'verification'
  },
  taskQueue: [
    {
      id: 'LP-001',
      displayName: '计算基础',
      statusText: '待验证',
      evidenceText: '相关错题 4'
    }
  ],
  tools: [
    { key: 'diagnosis', title: '拍照诊断' },
    { key: 'defaultPaper', title: '默认试卷' },
    { key: 'history', title: '学习记录' },
    { key: 'latestReport', title: '完整报告' }
  ],
  analysisState: null
}
```

不再输出或不再使用：

- `currentSummary`
- `recentChanges`
- `persistingCount`
- `pendingCount`
- `improvedCount`

如果这些字段仍为兼容保留，也不应在新 WXML 中主展示。

### 验证试卷页

`generate-verification` 可继续使用 `pendingBottlenecks`，但展示方式调整：

- 顶部不再用说明条解释“系统针对每个卡点生成 3 道验证题”。
- 改为出卷配置摘要。
- 卡点列表默认密度更高。
- 单项可展开来源信息。
- 预览摘要改为固定侧栏或固定底部摘要。

## 交互规则

### 首页进入学科主页

点击重点提示或学科入口：

- 进入对应 `subject-home`。
- 不需要在学科主页再次解释首页摘要。

### 学科主页主按钮

根据 `primaryTask.actionType`：

- `verification` → `generate-verification`
- `diagnosis` → `upload?mode=diagnosis`
- `defaultPaper` → `default-paper`
- `history` → `upload-history`

### 待处理队列

点击某一待验证项：

- 优先进入 `generate-verification`，并预选该项。
- 如果暂不做单项预选，第一阶段可进入验证页并保留默认选择全部。

### 查看完整报告

学科主页中的“完整报告”：

- 跳转最近有效诊断报告。
- 如果没有报告，则隐藏该入口。

## 空态与异常状态

### 首页空态

保持现有：

- 还没有学习档案。
- 添加第一个孩子。

### 学科主页空态

如果该学科没有有效报告：

- 标题：`数学工作台`
- 当前任务：`上传第一份数学试卷`
- 主按钮：`拍照诊断`
- 次按钮：`默认试卷`
- 不显示“暂无诊断摘要”。

### 学科主页分析中

如果有后台分析任务：

- 顶部或任务区显示轻量状态：`正在整理本次试卷`
- 有真实批次进度时显示批次信息。
- 没有真实批次进度时不显示进度条。

### 验证试卷页空态

如果没有待验证项：

- 标题：`暂无待验证观察`
- 引导：
  - `拍照诊断`
  - `默认试卷`
- 不使用“暂无卡点”这种偏负面的表达。

## 视觉原则

本次不是品牌重做，但应遵守以下视觉方向：

- 首页可以保留柔和、报告式、带插图的表达。
- 学科主页改为更轻、更短、更像操作面板。
- 验证试卷页更像配置工具，信息密度高于首页。
- 避免在三个页面重复使用同一张大图。
- 避免每页都出现大段解释性文字。
- 保持“学习观察”“待处理队列”等柔和说法，不回退到“缺陷”“Bug”。

## 测试与验收

### 自动化测试

需要新增或调整：

- `contracts.test.js`
  - 首页仍包含 `学习档案`、`样本覆盖`。
  - 学科主页不包含 `当前综合诊断`。
  - 学科主页不包含大图资源引用。
  - 验证试卷页不包含长诊断解释入口文案。
- `subject-home-presenter.test.js`
  - 生成 `primaryTask`。
  - 生成 `taskQueue`。
  - 空态时主任务为拍照诊断。
- `page-flows.test.js`
  - 首页点击重点提示进入学科工作台。
  - 学科工作台主按钮进入验证页或上传页。
  - 待处理队列点击进入验证页。

### 人工验收

在微信开发者工具中检查：

- 首页首屏仍能理解孩子整体情况。
- 进入数学主页后，不再看到重复的综合摘要。
- 数学主页首屏能直接判断下一步做什么。
- 验证试卷页更像“出卷配置”，而不是第三个诊断摘要页。
- 家长从首页到生成验证卷的路径不比现在更长。

## 非目标

本阶段不做：

- 多学生切换完整改版。
- 底部 TabBar。
- 报告页大重构。
- 学习记录页大重构。
- AI 生成跨学科长报告。
- 语文/英语在线验证流程。

## 实施建议

建议分三步实施：

1. 先改 `subject-home` 为工作台。
2. 再压缩首页 `学习观察` 为 `重点提示`。
3. 最后改 `generate-verification` 为出卷配置器。

这样可以先消除最大重复源，再处理页面密度和出卷体验。
