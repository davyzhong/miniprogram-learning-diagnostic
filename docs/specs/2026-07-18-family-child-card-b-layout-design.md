# 家庭首页孩子卡片 B 方案设计

## 目标

孩子卡片采用“快捷入口与诊断报告并重”的信息层级。正式诊断成为身份区之后的第一块正文，快捷操作进入卡片上部；现有四项统计、优先行动、辅助行动、三科学习状态和四个快捷入口全部保留，但减少重复标题、说明文字和垂直留白。

## 信息层级

1. 身份区：头像、姓名、状态、年级/角色/成员、最近更新时间和档案入口。
2. 紧凑快捷入口：身份区下方使用一行四列完整展示；入口保留图标和完整短标题，隐藏首页价值较低的长摘要。
3. 最新学科诊断：只展示已有正式诊断的学科；每科一行，包含报告名称、日期、单行结论和“报告”动作。
4. 下一步行动：优先行动紧跟诊断，建立“看结论 → 做行动”的连续阅读路径；辅助行动保留为更轻量的双列短行。
5. 四项统计：继续四列，压缩数字、标签和色块高度；状态分段条紧随统计。
6. 三科学科入口：改为三列单行入口，只保留学科名、当前状态和箭头；详情摘要及分段条不在首页重复展示。

没有正式诊断时，不渲染诊断标题或空占位，快捷入口后直接进入下一步行动。卡片整体仍可点击进入学习档案，各内部操作使用 `catchtap`，不触发父级跳转。

## 视觉规则

- 沿用 B1 色彩变量和现有学科色，不新增图片资源。
- 卡片圆角 12rpx；局部控件圆角不超过 8rpx。
- 快捷入口在身份区下方、最新诊断之前使用一行四列按钮；完整文字优先，不允许以省略号截断标题。
- 诊断行使用学科色左边线，结论最多一行省略。
- 优先行动保持最强强调色；辅助行动、统计和学科入口依次降低视觉权重。
- 360px 与 390px 宽度下不发生横向溢出，长姓名和长状态允许合理截断或换行。

## 数据与边界

不修改首页接口和 Presenter 数据结构，继续使用 `child.quickLinks`、`diagnosisReports`、`priorityAction`、`secondaryActions`、`statusItems`、`statusSegments` 和 `subjectRows`。本次只改变家庭首页呈现层，不影响学习档案单孩子模式。

## 验收标准

- DOM 顺序满足：身份/快捷入口 → 诊断 → 优先行动/辅助行动 → 四项统计 → 三科学科入口。
- 四个快捷入口、三门学科、四项统计及现有行动数据均只渲染一次。
- 没有诊断的孩子不出现诊断空块。
- 快捷入口摘要和学科详情摘要不再占据首页高度，但数据仍由 Presenter 保留。
- 首页专项测试、B1 设计系统测试、语法检查和主包预算检查通过。
